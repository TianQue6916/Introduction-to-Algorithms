### <span style="color:#2471a3;">**[problem]**</span> <span style="color:#c0392b">Problem 9-1. Coin Crafting（金币铸造）</span>

> <span style="color:#7f8c8d;">对应官方 PDF 第 1 页</span>

> **[solution] Solution（解答）:**
>
> **1. Subproblems（子问题）**
>
> - 给每一件 craft-able（可铸造）的制品一个从 $1$ 到 $n$ 的唯一整数编号
> - 设 $p_j$ 为制品 $j$ 的 purchase price（买价），$k_j$ 为它的 melting number（熔铸数）
> - $x(i, j)$：手里有 $i$ 枚金币、只允许在编号 $1$ 到 $j$ 的制品中挑选时，所能取得的 maximum revenue（最大收入）
>
> **2. Relate（关联）**
>
> - Guess（猜测）制品 $j$ 铸还是不铸
> - 若 $i < k_j$，则制品 $j$ 铸不了
> - 若制品 $j$ 不铸，就可以在剩下的制品上递归
> - 若制品 $j$ 铸了，就收入 $p_j$、并失去 $k_j$ 枚金币
>
> > ```math
> > x(i, j) = \begin{cases}
> > x(i,\ j-1) & \text{若 } i < k_j \\
> > \max\left(p_j + x(i - k_j,\ j-1),\ x(i,\ j-1)\right) & \text{否则}
> > \end{cases}
> > ```
>
> **3. Topo. Order（拓扑序）**
>
> - subproblem（子问题）$x(i, j)$ 只依赖 $j$ 严格更小的subproblem（子问题），因此 acyclic（无环）
>
> **4. Base（基例）**
>
> - 若金币已经用完，或制品已经挑完，就再也拿不到收入
> - 对 $j \in \{0, \dots, n\}$，有 $x(0, j) = 0$
> - 对 $i \in \{0, \dots, n\}$，有 $x(i, 0) = 0$
>
> **5. Original（原问题）**
>
> - $x(n, n)$ 就是手里 $n$ 枚金币、可在全部 $n$ 件制品中挑选时所能取得的 maximum revenue（最大收入），正是所求
>
> **6. Time（时间分析）**
>
> - subproblem（子问题）数：$(n + 1)^2 = O(n^2)$，即 $i, j \in \{0, 1, \dots, n\}$ 的全部 $x(i, j)$
> - 每个subproblem（子问题）的工作量：$O(1)$
> - 运行时间 $O(n^2)$

> <span style="color:#7f8c8d;">〔原抽取串：`Let pi be the purchase price of object j, with ki its melting number`、`If i < ki, object j cannot be crafted`、`receive pi in revenue and lose ki coins`、`x(0, j) = 0 for i ∈ {0, . . . , n}`、`x(i, 0) = 0 for j ∈ {0, . . . , n}`、`nobjects`。原文里 $p_i$、$k_i$ 的下标都写成了 $i$（而 $i$ 在状态 $x(i,j)$ 里是金币数），文句却写 `object j`，即制品编号与金币数这两个下标写反了；另有两处 base case（基例）的哑变量写反；按数学意义重建为 $p_j$、$k_j$，基例重建为「$x(0,j)=0$ 对 $j$ 遍取」与「$x(i,0)=0$ 对 $i$ 遍取」，`nobjects` 重建为 `n objects`。〕</span>

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这条注要回答的是：为什么这一维只能是「剩余金币数 $\times$ 制品前缀」，以及递推里那个 $j-1$ 为什么是整道题的关键。
>
> 先看这道题逼出了什么。手边有两样互相消耗的东西：金币是唯一的可消耗资源，制品每件只能卖一次。若只看「金币还剩多少」，你无法保证同一件制品不被铸第二遍；若只看「挑到第几件」，你无法知道还剩多少金币可熔。所以状态必须同时记住这两个量，$x(i,j)$ 的两个参数就是这样被逼出来的，不是设计出来的。subproblem（子问题）的语义要读成「在预算 $i$ 之内、只从编号 $1$ 到 $j$ 的制品里选」——注意「只从到 $j$ 为止」这半句，它是让拓扑序成立的唯一理由。
>
> 再看 $j-1$ 与 $j$ 的区别，这是整道题最值钱的一行。若制品 $j$ 被铸了，递推到 $x(i - k_j, j-1)$ 而不是 $x(i-k_j, j)$：减去的下标必须退一格，因为制品 $j$ 已经用掉了。若把 $j-1$ 误写成 $j$，你描述的就是另一道题——unbounded knapsack（完全背包），同一件制品可以反复铸、反复卖。题目里「but will only purchase one of any object（但同一种制品只买一件）」这一句，在递推里只值一个减一；把减一去掉，答案会系统性偏大。这不是格式差异，是问题换了。
>
> 算一组具体数字。取 $n = 5$、买价 $(3, 4, 5)$、熔铸数 $(1, 2, 3)$。逐格填表得 $x(5,3) = 9$：最优是铸制品 $2$ 与 $3$，花掉 $2 + 3 = 5$ 枚金币、收入 $4 + 5 = 9$；其余组合同样逐一核过——$\{1,3\}$ 花 $4$ 枚只收 $8$、$\{1,2\}$ 花 $3$ 枚只收 $7$，单件最高 $5$；铸制品 $1$、$2$、$3$ 需要 $1 + 2 + 3 = 6$ 枚金币，超预算。再取 $n = 7$、买价 $(10, 4, 6)$、熔铸数 $(4, 2, 3)$，答案是 $16$。预算内的组合逐一核过（单件收入分别是 $10$、$4$、$6$，都低于 $16$）：铸制品 $1$ 与 $3$ 花 $4 + 3 = 7$ 枚、收入 $10 + 6 = 16$；铸制品 $1$ 与 $2$ 花 $4 + 2 = 6$ 枚、收入 $10 + 4 = 14$；铸制品 $2$ 与 $3$ 花 $2 + 3 = 5$ 枚、收入 $4 + 6 = 10$；三件全铸要 $4 + 2 + 3 = 9$ 枚，超出 $7$ 枚预算。所以最优确实是制品 $1$ 与制品 $3$，收入 $16$，与递推结果一致。而 $n = 3$、买价 $(5, 9)$、熔铸数 $(4, 4)$ 时答案是 $0$：两件都铸不了，一枚金币也卖不出去。这三组数由暴力枚举子集（$2^n$ 种）与 $O(n^2)$ 的递推分别算出，结果逐组相同，可复现。
>
> 跨课程连接：CLRS 的 rod cutting（切杆）是同一张表的退化版——它只有「长度」一维，因为切杆不消耗第二种资源，分支数 $O(n)$ 全部落在「第一段切多长」上。本题把那一维换成「金币数」，又把「制品」当成第二维，于是分支数被压到常数 $2$（铸 / 不铸）。这个对照给出一个判断法则：**状态维数等于互相独立的资源数，分支数等于每件物品的决策数**。再看 CLRS 的 fractional knapsack（分数背包）：它能贪心，是因为允许把物品切开，于是按密度排序的交换论证成立；本题的 $0/1$ 约束一旦去掉「可切」这个前提，密度排序立刻失效——一个高密度大件可能占满预算却不如两个中件，这正是要靠填表而不是排序的理由。
>
> 6.042J 那边能接的是计数：$n$ 件制品的子集有 $2^n$ 个，暴力就是在这 $2^n$ 个点里找满足总熔铸数 $\le i$ 的最大权。dynamic programming（动态规划）做的事是**把这个指数集合按「前缀 $\times$ 预算」重新分组**，让同一组内的所有子集共享一个值。分组数 $(n+1)^2$ 就是复杂度；这一步从 $2^n$ 掉到 $n^2$ 不是近似，是精确的等价类合并。
>
> 收束一句：这道题真正的训练点是「先问资源有几样，再问每样资源的下标在转移时是减一还是不减」。

### <span style="color:#2471a3;">**[problem]**</span> <span style="color:#c0392b">Problem 9-2. Career Fair Optimization（招聘会最优化）</span>

> <span style="color:#7f8c8d;">对应官方 PDF 第 2 页</span>

<!-- page 2/8 -->

> **[solution] Solution（解答）:**
>
> **1. Subproblems（子问题）**
>
> - $x(i, j)$：在接下来的 $i$ 分钟里、Tim 的 backpack（背包）还剩 $j$ 的重量额度时，所能领到的赠品的 maximum total coolness（最大总酷值）；此处约定 Tim 正站在招聘会现场、可以立刻去排队
>
> **2. Relate（关联）**
>
> - Tim 可以做的事只有三类：
>
>   - 不再领任何赠品
>   - 排一次队、领一件赠品
>   - 跑回家、把背包腾空
>
> > ```math
> > x(i, j) = \max \begin{cases}
> > 0 & \text{always（总是可选）} \\
> > c_{k'} + x(i - t_{k'} - 1,\ j - w_{k'}) & \text{对 } k' \in \{1, \dots, n\} \text{ 且 } w_{k'} \le j,\ t_{k'} < i \\
> > x(i - h - 1,\ b) & \text{当 } i > h
> > \end{cases}
> > ```
>
> **3. Topo. Order（拓扑序）**
>
> - subproblem（子问题）$x(i, j)$ 只依赖 $i$ 严格更小的subproblem（子问题），因此 acyclic（无环）
>
> **4. Base（基例）**
>
> - Tim 要领赠品就得花时间，所以时间为零时什么都做不成
> - 对 $j \in \{0, \dots, b\}$，有 $x(0, j) = 0$
>
> **5. Original（原问题）**
>
> - $x(k, b)$ 就是背包腾空起算、$k$ 分钟内所能领到的赠品的 maximum total coolness（最大总酷值），正是所求
>
> **6. Time（时间分析）**
>
> - subproblem（子问题）数：$\le (k + 1)(b + 1) = O(kb)$，即 $i \in \{0, \dots, k\}$、$j \in \{0, \dots, b\}$ 的全部 $x(i, j)$
> - 每个subproblem（子问题）的工作量：$O(n)$
> - 运行时间 $O(nbk)$，它对 $b$ 与 $k$ 是 pseudo-polynomial（伪多项式）的

> <span style="color:#7f8c8d;">〔原抽取串：`always`、`for k0  {1, . . . , n} where wk0  j, tk0 < i`、`when i > h`、`ck0 + x(i - tk0 - 1, j - wk0)`、`x(i - h - 1, b)`、`(k + 1)(b + 1) = O(kb)`。原文的三段 $\max$ 被抽成散落的几行，条件与取值分离；`∈`、`≤`、`<` 三个关系符全部丢失；`k'` 被抽成 `k0`。按数学意义重建为上面的分段式，`k0` 重建为 $k'$。原文 `psuedo-polynomial` 拼写有误，按其本义 pseudo-polynomial（伪多项式）译。〕</span>

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这条注要回答的是：为什么状态里必须同时有「剩余时间」和「剩余载重」，以及「回家」这个动作凭什么不增加状态维数。
>
> 先数资源。Tim 手上有两样独立在消耗的东西：时间（$k$ 分钟）与背包载重（$b$）。领一件赠品同时消耗两者（$t_{k'} + 1$ 分钟、$w_{k'}$ 重量），所以两者都不能从状态里省掉——省掉时间就不知道还能领几件，省掉载重就不知道还能装多少。于是 $x(i,j)$ 的两个参数同样是逼出来的。注意那个额外的 $+1$：「领到一件之后要花 $1$ 分钟才重新排进队里」，官方的转移把它写进了 $i - t_{k'} - 1$，这一分钟不是装饰，它是「连续领两件」与「领一件就走」的差别所在。
>
> 再看「回家」这个动作的形状。它花 $h$ 分钟跑回去、再花 $1$ 分钟重新排队，于是转移是 $x(i - h - 1,\ b)$——**第二维被无条件推回满值 $b$**。这一点是整道题的关键：回家之后，背包的历史被一次性抹掉了，所以subproblem（子问题）只需要记住「现在是满的」这一个事实，不需要记住之前装过什么。用状态机的语言说，$(i, b)$ 是一个absorbing state（吸收态）：所有「回家」的动作都汇到它。这就是为什么复杂度是 $O(nbk)$ 而不是 $O(nbk)$ 再乘上「回家次数」——回家次数不被记进状态，它的效果已经被压进了那一个满值。
>
> 算一组具体数字，仍让机器说话。取 $n = 3$、$b = 4$、$k = 10$、$h = 2$，三个摊位的酷值 $(5, 7, 3)$、重量 $(2, 3, 1)$、排队时间 $(2, 1, 1)$。按上面的递推填 $(k+1) \times (b+1) = 11 \times 5$ 张表，得 $x(10, 4) = 17$。可以顺着表回读这条最优路线：先排重量 $3$、酷值 $7$ 的摊位（花 $1 + 1 = 2$ 分钟），再排重量 $1$、酷值 $3$ 的摊位（$2$ 分钟），此时载重 $3 + 1 = 4$ 已满、用时 $4$ 分钟；回家 $h + 1 = 3$ 分钟，剩 $3$ 分钟；再排一次重量 $3$ 那家（$2$ 分钟）。酷值累计 $7 + 3 + 7 = 17$。这条路线把「回家」用了一次，总耗时 $2 + 2 + 3 + 2 = 9$ 分钟，剩下 $1$ 分钟不够再排任何一队（三个摊位的 $t_{k'}$ 都 $\ge 1$）。
>
> 跨课程连接：CLRS 的 assembly-line scheduling（装配线调度）是同一个骨架的「按阶段」版本——状态是「走到第几个工位、在哪条线上」，转移是「换线或留在本线」；本题把「阶段」换成「剩余时间」，把「哪条线」换成「背包还剩多少」，于是拓扑序从「工位编号递增」变成「剩余时间递减」。两者的共同点是：**状态必须是「未来还需要什么」的完整摘要**，凡是未来用不到的历史一律不许进状态。另一条连接是 6.042J 的状态机：把 $(i, j)$ 看成顶点、把三类动作看成有向边，这道题就是这张有向无环图上的最长路问题；「无环」由「每条边都让 $i$ 严格变小」保证，因此从 $i = 0$ 往上填表就是一次合法的 linear extension（线性扩展）。
>
> 还要看清 pseudo-polynomial（伪多项式）这四个字。$O(nbk)$ 里的 $b$ 与 $k$ 是**数值**而不是输入长度：$k$ 用二进制写只要 $\log k$ 位，但表要开 $k$ 行。所以当 $k$ 由输入的数位长度决定时，这个「多项式」会退化成指数级。这不是本题的缺陷，而是所有「按容量填表」的背包型dynamic programming（动态规划）共同的性质；改变它的唯一办法是换一套不以容量为下标的算法，而不是优化常数。
>
> 收束：看到「消耗两种资源 + 有一个重置动作」，先写下两个参数，再把重置动作写成「把某一维推回满值」——状态数不会因此增加，反而因为那个吸收点而变少。

### <span style="color:#2471a3;">**[problem]**</span> <span style="color:#c0392b">Problem 9-3. Protein Parsing（蛋白质解析）</span>

> <span style="color:#7f8c8d;">对应官方 PDF 第 2–3 页</span>

<!-- page 3/8 -->

> **[solution] Solution（解答）:**
>
> **1. Subproblems（子问题）**
>
> - 首先建一张 hash table（哈希表），把 $P$ 里的 protein marker（蛋白质标记）作为 key（键）放进去
> - 建这张 hash table（哈希表）需要（期望）$O(k|P|)$ 时间——每个标记算一次 hash（哈希）需要 $O(k)$ 时间
> - $x(i)$：DNA 链的suffix（后缀）$S[i:]$ 的所有 division（切分）中可能的最大 value（价值）
>
> **2. Relate（关联）**
>
> - 第一个 nucleotide（核苷酸）要么是一段蛋白质标记的开头，要么不是
>   - 若不是，就在剩下的部分上递归
>   - 若是，就 Guess（猜测）这段标记的长度（从 $1$ 到 $k$，或直到 $S$ 的末尾）
> - 设 $m(i, j)$ 在substring（子串）$S[i:j]$ 是一段蛋白质标记时取 $1$，否则取 $0$
> - 借助 hash table（哈希表）查表，$m(i, j)$ 可在期望 $O(k)$ 时间内算出
>
> > ```math
> > x(i) = \max\{\, m(i, j) + x(i + j) \mid j \in \{1, \dots, \min(k,\ |S| - i)\} \,\}
> > ```
>
> **3. Topo. Order（拓扑序）**
>
> - subproblem（子问题）$x(i)$ 只依赖 $i$ 严格更大的subproblem（子问题），因此 acyclic（无环）
>
> **4. Base（基例）**
>
> - 若后缀里已经没有核苷酸，任何division（切分）都拿不到价值
> - $x(|S|) = 0$
>
> **5. Original（原问题）**
>
> - $x(0)$ 就是 $S$ 的所有division（切分）中可能的最大价值，正是所求
>
> **6. Time（时间分析）**
>
> - subproblem（子问题）数：$|S| + 1 = O(|S|)$，即 $i \in \{0, \dots, |S|\}$ 的全部 $x(i)$
> - 每个subproblem（子问题）的工作量：期望 $O(k)$，用来查那 $k$ 个 $m(i, j)$
> - 运行时间 $O(k(|P| + k|S|))$，它对输入规模是 polynomial（多项式）的
> - 注意：若这 $k|S|$ 次查表都能在 $O(1)$ 时间内完成，就有可能做到 $O(k(|P| + |S|))$——具体手段是 rolling hash（滚动哈希）或 suffix tree（后缀树），而这两样**本课程（6.006）不讲授**（原文：`not covered in this course`）

> <span style="color:#7f8c8d;">〔原抽取串：`S[i :]`、`S[i : j]`、`j  {1, . . . , min(k, |S| - i)}`、`(expected) O(k|P |)`、`2 n(k + 1)`。`∈` 丢失、竖线 `|` 在部分位置丢失，按数学意义重建。另注：官方把 $m(i,j)$ 写成「子串 $S[i:j]$」，而下一段又用 $x(i+j)$ 跳到新起点，严格记号应为 $S[i:i+j]$；本译文按官方原样保留 $S[i:j]$ 的写法，只在这一处指出记号口径，不改动其内容。〕</span>

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这条注要回答的是：为什么判定「这一段是不是标记」必须外包给 hash table（哈希表），以及「猜长度」为什么只猜 $k$ 种而不是 $|S|$ 种。
>
> 先看朴素做法的代价。若每遇到一个位置 $i$、每猜一个长度 $j$，就真去 $P$ 里线性搜一遍，那么单个subproblem（子问题）要做 $k$ 次、每次 $|P|$，总计 $O(k|S|\cdot|P|)$；题目给的界是 $O(k|P| + k^2|S|)$，把 $|P|$ 从「每个子问题都要付一次」降成「只付一次」。这个降法就是预处理：把所有标记一次性放进 hash table（哈希表），此后「这条子串是不是标记」变成一个 $O(1)$（期望）的表查询，代价是 $O(k|P|)$ 的建表时间。这是**预处理换查询**最标准的一笔账，也是本题为什么要把「建表」写在 Subproblems（子问题）第 1 条而不是写在 Relate（关联）里的原因。
>
> 再看「猜长度」的取值范围。题面规定每个标记「长度至多 $k$ 个核苷酸」，因此以 $i$ 开头的候选只有 $k$ 种（还要与剩余长度 $|S| - i$ 取小）。若题目不给这个 $k$，候选就有 $O(|S|)$ 种，复杂度立刻升一个量级。所以那一条「至多 $k$」不是修辞，它就是分支数——这与 9-1 里「每件制品只能选一次」压住分支数是同一种作用：**约束写在题面里，分支数写在递推里，复杂度写在最后一节**。
>
> 算一组具体数字。取 $S = \texttt{ACGTAC}$、标记集合 $P = \{\texttt{AC}, \texttt{GT}, \texttt{ACG}, \texttt{TAC}, \texttt{C}\}$、$k = 3$。答案 $x(0) = 3$，对应切分 $\texttt{AC} \mid \texttt{GT} \mid \texttt{AC}$：三段全是标记，价值 $3$。能不能到 $4$？那需要切成四段且每段都短，而最短的标记是 $\texttt{C}$（长 $1$）与两个长 $2$ 的，$6$ 个字符最多切出 $5$ 段（每段至少 $1$ 个字符），但要四段全命中标记就得每段都对得上——枚举全部 $2^{5} = 32$ 种切法，最大价值确实是 $3$。再取 $S = \texttt{AAA}$、$P = \{\texttt{A}, \texttt{AA}\}$、$k = 2$，答案 $3$（切成 $\texttt{A}\mid\texttt{A}\mid\texttt{A}$）；取 $S = \texttt{ACGTTT}$、$P = \{\texttt{AC}, \texttt{TT}, \texttt{GTT}, \texttt{ACG}\}$、$k = 3$，答案 $2$（$\texttt{ACG}\mid\texttt{TT}\mid\texttt{T}$，最后一段不是标记；或 $\texttt{AC}\mid\texttt{GTT}\mid\texttt{T}$，同样是 $2$）。三组都由递推与暴力枚举两路算出，逐组相同。
>
> 跨课程连接：CLRS 的 rod cutting（切杆）与本题同形——都是「后缀型子问题 + 枚举第一段的长度」，区别在分支数与判定方式：切杆的分支是 $O(n)$ 种长度且收益是查表常数，本题的分支被 $k$ 卡住、且每种候选都要一次字符串判定。CLRS 的 Rabin–Karp（§32.2）正好补上题目最后那句提示：对每个可能的标记长度 $j \in \{1, \dots, k\}$ 各跑一遍 rolling hash（每遍扫 $|S|$，把一个模素数下的多项式值当作该长度窗口的代表，相邻窗口的 hash 可以 $O(1)$ 递推），于是那 $k|S|$ 次判定各自 $O(1)$，总时间降到 $O(k|P| + k|S|) = O(k(|P| + |S|))$——正是官方那条注记给出的界。这个技巧在 6.006 里不讲，原因是它属于字符串算法专题，而 6.006 的 DP 部分只要求你会用现成的 hash table（哈希表）。
>
> 6.042J 那边接的是 hash 的期望分析：题面写「expected（期望）$O(k|P|)$」而不是「$O(k|P|)$」，因为 hash table（哈希表）的查询在 simple uniform hashing（简单均匀散列）假设下才是常数期望。若把「期望」两个字删掉，这个界就成了最坏情形断言，而最坏情形下所有键撞到同一个桶，查询退化成 $O(|P|)$。**这个词不能省**，它不是客套。
>
> 收束：字符串上的 DP 只有三个动作——猜第一段多长、判定这一段是什么、跳到剩下的后缀；把「判定」外包出去，复杂度就从三个因子相乘变成两个因子相加。

### <span style="color:#2471a3;">**[problem]**</span> <span style="color:#c0392b">Problem 9-4. Lazy Egg Drop（懒惰的鸡蛋下落）</span>

> <span style="color:#7f8c8d;">对应官方 PDF 第 3–4 页</span>

<!-- page 4/8 -->

> **[solution] Solution（解答）:**
>
> **1. Subproblems（子问题）**
>
> - $x(i, j, e)$：手头有 $e$ 个 egg（鸡蛋）、还需检查第 $i$ 层到第 $j$ 层（$j \ge i$）时，确定 breaking floor（破裂楼层）所需的最小 total drop height（总下落高度）
>
> **2. Relate（关联）**
>
> - 下一个 egg（鸡蛋）必须从某个还没排除的楼层 $f$ 丢下（原文在此标 `Guess`，即猜一个）
> - 若 egg（鸡蛋）碎了，就少一个 egg（鸡蛋），且要在下面的楼层上递归
> - 否则 egg（鸡蛋）数不变，且要在上面的楼层上递归
>
> > ```math
> > x(i, j, e) = \min\{\, h_f + \max\{x(i, f-1, e-1),\ x(f+1, j, e)\} \mid f \in \{i, \dots, j\} \,\}
> > ```
>
> **3. Topo. Order（拓扑序）**
>
> - subproblem（子问题）$x(i, j, e)$ 只依赖 $j - i$ 严格更小的subproblem（子问题），因此 acyclic（无环）
>
> **4. Base（基例）**
>
> - 若 egg（鸡蛋）已经用完、却还有楼层要检查，则不可能完成
> - 对 $i, j \in \{0, \dots, n\}$ 且 $i \le j$，有 $x(i, j, 0) = \infty$
> - 若已经没有楼层要检查，就不必再丢
> - 对 $i \in \{0, \dots, n\}$、$e \in \{0, \dots, k\}$，有 $x(i, i-1, e) = 0$
>
> **5. Original（原问题）**
>
> - $x(1, n, k)$ 就是手头 $k$ 个 egg（鸡蛋）、需检查全部楼层时确定 breaking floor（破裂楼层）所需的最小 total drop height（总下落高度），正是所求
>
> **6. Time（时间分析）**
>
> - subproblem（子问题）数：$\le \binom{n}{2}(k + 1) = O(n^2k)$，即 $i, j \in \{1, \dots, n\}$ 且 $i < j$、$e \in \{0, \dots, k\}$ 的全部 $x(i, j, e)$
> - 每个subproblem（子问题）的工作量：$O(\max(1, j - i)) = O(n)$
> - 运行时间 $O(n^3k)$，它对 $k$ 是 pseudo-polynomial（伪多项式）的。不过，既然要检查全部 $n$ 层楼永远不需要丢超过 $n$ 个 egg（鸡蛋），只对 $k \le n$ 计算subproblem（子问题）就够了；于是把要检查的subproblem（子问题）限制在这个范围内，就能在 $O(n^3)$ 时间内回答本题，而这对 $n$ 是 polynomial（多项式）的

> <span style="color:#7f8c8d;">〔原抽取串：`with floors i to j  i remaining to check`、`x(i, j, 0) =  for i, j  {0, . . . , n} with i  j`、`2 n(k + 1)`、`psuedo-polynomial`。`≥`、`∞`、`≤`、`∈`、二项式系数 $\binom{n}{2}$ 的上标全部在文字层丢失；原文 `psuedo-` 拼写有误。按数学意义重建为 $j \ge i$、$x(i,j,0)=\infty$、$i \le j$、$i,j \in \{0,\dots,n\}$、$\binom{n}{2}(k+1)$，并按本义译为 pseudo-polynomial（伪多项式）。原文 `it suffices to only compute subproblems for k ≤ n` 中的 `≤` 已由版面核对确认为「小于等于」，不是「大于等于」。〕</span>

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这条注要回答的是：为什么递推里是 $\min$ 套 $\max$（而不是两个 $\min$），以及为什么「总下落高度」这个目标会让递推里少掉那个常见的 $+1$。
>
> 先把两个角色分开。取 $\min$ 的是你：要从所有可能的下落楼层 $f$ 里挑一个最省高度的。取 $\max$ 的不是对手，而是一个**固定但未知的常数**——这栋楼的 breaking floor（破裂楼层）只有一个真值，鸡蛋碎或不碎由它决定，你无法选。所以对给定的 $f$，最坏情形是那两个分支里更贵的那个：蛋碎了就得在下方 $f-1$ 层里继续、且少一个蛋；蛋没碎就得在上方继续、蛋数不变。$\max$ 就是把「不确定性」这一层写进式子，$\min$ 才是你的决策。这也解释了为什么 base case（基例）里 $e = 0$ 要取 $\infty$：没有蛋却还有楼层要查，这个分支根本不可行，必须让它被 $\max$ 每次都选中、从而永远不会成为最优。
>
> 再看为什么没有 $+1$。经典 egg drop problem（鸡蛋下落问题）最小化的是**次数**，所以每丢一次递推就加一；本题最小化的是**高度和**，每丢一次的代价是被丢的那一层的高度 $h_f$，所以递推里加的是 $h_f$。这就是「lazy（懒惰）」这个词的全部含义：楼里没电梯，把蛋拿到高层去丢是要花体力的，于是「少丢几次」不再是唯一目标，「别往高处跑」也进了目标函数。目标一换，递推里的常数 $1$ 就换成了变量 $h_f$，其余结构一字不改。
>
> 算几组具体数字。取高度 $(1, 3, 6, 10)$、$k = 2$，最小总下落高度是 $16$。最优的第一步是在 $h = 6$ 那一层（第 $3$ 层）丢。若蛋碎了，只剩 $1$ 个蛋、要在第 $1$–$2$ 层里线性试：先试 $h = 3$，不碎再试 $h = 1$，这条支路最坏要付 $6 + 3 + 1 = 10$ 米；若蛋没碎，只剩第 $4$ 层，直接丢 $h = 10$，这条支路付 $6 + 10 = 16$ 米。$\max$ 取最坏得 $16$，$\min$ 再在四个候选楼层里挑，仍然是这一条，于是 $x(1, 4, 2) = 16$。同一组高度给 $k = 3$，答案仍是 $16$：多一个蛋并不能压低最坏情形的总和，因为最坏分支照样要把高处那 $10$ 米付掉。再取高度 $(1,2,3,4,5)$、$k = 2$，答案是 $10$。这些数由 $O(n^3k)$ 的递推算出。
>
> 最有说服力的一次核对是把高度全取 $1$：此时「总下落高度」在数值上就等于「下落次数」，所以本题的 $x(1,n,k)$ 必须与经典 egg drop problem（鸡蛋下落问题）的答案逐组相等。实测 $n = 1..8$、$k = 1, 2, 3$ 共 $24$ 组，两组算法给出的数完全相同（例如 $n = 8$、$k = 2$ 都是 $4$；$n = 7$、$k = 2$ 都是 $4$；$n = 6$、$k = 2$ 都是 $3$）。这不是巧合，而是「$h_f \equiv 1$ 时 $\sum h_f = $ 次数」这一句话的直接后果；它同时验证了上面的递推没有漏掉或错加那个常数。
>
> 跨课程连接：CLRS 的 optimal binary search tree（最优二叉搜索树，§15.5）是同构的区间型 dynamic programming（动态规划）——都是「猜一个分割点 $f$，两侧递归，再把两侧的结果合起来」；差别只在合并方式：OBST（最优二叉搜索树）把两侧的期望代价相加（因为查询会落到任意一侧），本题对两侧取 $\max$（因为只有一侧是真会发生的最坏情形）。这一处差别值得单独记住：**同样的区间骨架，加号换来的是「期望」，$\max$ 换来的是「最坏」**。另一条连接是 6.042J 的递归结构：把区间 $[i, j]$ 看成节点，$j - i$ 是这个节点的「尺度」，所有转移都指向尺度更小的节点，于是按尺度从小到大填表就是一次合法的拓扑序——这正是官方把 acyclic（无环）写成「依赖 $j - i$ 严格更小」的原因。
>
> 最后看那句 $k \le n$。$n$ 层楼最多只需要 $n$ 个蛋（每层一个、从下往上逐个试），所以当 $k > n$ 时，把 $k$ 截到 $n$ 不会改变答案；于是表里 $e$ 这一维只需开到 $\min(k, n)$，复杂度从 $O(n^3k)$ 降到 $O(n^3)$，对 $n$ 就是多项式了。这一步是「参数超出问题规模时可以截断」的标准手法；9-5 里做的是同一个检查的另一半——那里的 $k$ 由题面钉死为 $5$，于是 $2^k$ 只是个常数因子，复杂度才对 $n$ 是 polynomial（多项式）的。

### <span style="color:#2471a3;">**[problem]**</span> <span style="color:#c0392b">Problem 9-5. Building a Wall（砌一堵墙）</span>

> <span style="color:#7f8c8d;">对应官方 PDF 第 4–7 页</span>

<!-- page 5/8 -->

**(a)** 给定 $n \times k$ 的 border plan（边界规划）$B$，给出一个 $O(2^{2k}kn)$ 时间的 algorithm（算法），返回一个 complete（完备）且 non-overlapping（不重叠）的 placement（摆放），并使所用的 cube stone（方石）数尽可能少。

> **[solution] Solution（解答）:**
>
> **1. Subproblems（子问题）**
>
> - 做法是反复地：把最左那一列里**最高的那个还没被盖住的立方格**用某块石头盖掉
> - 放一块石头最多只会影响最左边两列，所以我们的subproblem（子问题）只需记住最左两列当前的覆盖状态
> - 把 boundary（边界）上一列「填了一半」的状态 $c$ 表示成一个长度 $k$ 的 Boolean array（布尔数组）：若这一列第 $j$ 行还需要被盖住，则 $c[j]$ 为 True；否则为 False
> - 令 $C_0(i)$ 对应输入 border plan（边界规划）$B$ 中第 $i$ 列的初始填充状态：$B[j][i] = $ `'.'` 时 $C_0(i)[j]$ 为 True，$B[j][i] = $ `'#'` 时为 False
> - 令 $C_0(n) = C_0(n+1) = c_F$，其中 $c_F$ 对应一列全为 False 的列
> - $x(i, c_1, c_2)$：把「部分覆盖的列 $c_1$ 与 $c_2$」以及「原来的第 $i+2$ 列到第 $n-1$ 列」全部盖住所需的 minimum number of cube stones（最少方石数）
>
<!-- page 6/8 -->

> **2. Relate（关联）**
>
> - 若最左那一列的所有行都已被盖住，就可以往前走，去盖下一列里还没被盖住的立方格
> - 否则，就放一块石头盖住最左那一列里最高的那个还没被盖住的立方格，用的石头是下面三种之一：
>   - 一块 cube stone（方石）；
>   - 一块朝 down（向下）竖放的long stone（长石），前提是下面那一格也还没被盖住；
>   - 一块朝 right（向右）横放的long stone（长石），前提是右边那一格也还没被盖住。
> - 令 $f(c, k)$ 表示把列 $c$ 中的元素 $c[k]$ 改成 False 之后得到的那个部分填充的列
> - 令 $t(c)$ 表示列 $c$ 中第一个（最靠上的）True 的下标
> - 若 $c_1$ 全为 False，则
>
> > ```math
> > x(i, c_1, c_2) = x(i + 1,\ c_2,\ C_0(i + 2))
> > ```
>
> - 否则 $t(c_1)$ 有定义，于是
>
> > ```math
> > x(i, c_1, c_2) = \min \begin{cases}
> > 1 + x(i,\ f(c_1, t(c_1)),\ c_2) & \text{always（总是可选）} \\
> > x(i,\ f(f(c_1, t(c_1)),\ t(c_1)+1),\ c_2) & \text{若 } c_1[t(c_1)+1] \text{ 为 True} \\
> > x(i,\ f(c_1, t(c_1)),\ f(c_2, t(c_1))) & \text{若 } c_2[t(c_1)] \text{ 为 True}
> > \end{cases}
> > ```
>
> **3. Topo. Order（拓扑序）**
>
> - subproblem（子问题）$x(i, c_1, c_2)$ 要么让 $i$ 严格增大，要么在 $i$ 不变的前提下让列 $c_1$ 里 True 的个数严格减少，因此 acyclic（无环）
>
> **4. Base（基例）**
>
> - 当已经没有东西需要覆盖时，不需要任何 cube stone（方石）
> - $x(n, c_F, c_F) = 0$
>
> **5. Original（原问题）**
>
> - $x(0, C_0(0), C_0(1))$ 就是填满整张 border plan（边界规划）所需的最少方石数，正是所求
> - 存下 parent pointers（父指针），以便把最优的那次 placement（摆放）重构出来
>
> **6. Time（时间分析）**
>
> - $c_1$ 与 $c_2$ 各自有 $2^k$ 种可能的列
> - subproblem（子问题）数：$n \cdot 2^k \cdot 2^k = O(n\,2^{2k})$
> - 每个subproblem（子问题）的工作量：$O(k)$，用来查 memo（记忆表），或用来算出一个新的列
> - 运行时间 $O(2^{2k}kn)$，它对 $k$ 是 exponential（指数级）的，但对 $n$ 是 polynomial（多项式）的

> <span style="color:#7f8c8d;">〔原抽取串：`n2k2k = O(n22k) subproblems`、`2k possible columns`、`always`、`if c1[t(c1) + 1] is True`、`if c2[t(c1)] is True`。上标在文字层被压平（$2^k$ 抽成 `2k`、$2^{2k}$ 抽成 `22k`），三段 $\min$ 的条件与取值被分行拆散。按数学意义重建为 $2^k$ 种列、$n\,2^{2k}$ 个子问题、以及上面那个带三行条件的分段式。〕</span>

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这条注要回答的是：为什么状态里只要两列、为什么那一列的状态是一个长度 $k$ 的布尔串、以及 $O(2^{2k}kn)$ 这个式子里的三个因子各是谁。
>
> 先说「为什么只要两列」。石头只有三种形状：$1 \times 1$ 的方石占一格，竖放长石占同一列相邻的两行，横放长石占同一行相邻的两列。三种形状的**列跨度**最大是 $2$——任何一块石头都不可能同时碰到第 $i$ 列与第 $i+2$ 列。于是当你从最左列往右推进时，第 $i$ 列之后的第二列还没有被任何石头碰过，它的状态完全由输入 $B$ 决定（记作 $C_0(i+2)$），不需要记在状态里。**这一条「跨度上界」就是状态宽度的来源**：跨度是 $2$，状态里就要存 $2$ 列的掩码；若题目允许 $1 \times 3$ 的长石，状态就得存 $3$ 列，复杂度里的指数从 $2k$ 变成 $3k$。
>
> 再说「为什么是一个长度 $k$ 的布尔串」。一列有 $k$ 行，每一行只有两种可能：还需要盖（该位记作 `True`）或不需要（该位记作 `False`）。$k$ 个独立的二元变量恰好有 $2^k$ 种取值，所以「一列的填充状态」这个词其实等价于「$k$ 位的bitmask（位掩码）」。这就是为什么复杂度里出现 $2^k$ 而不是 $k$ 的某个多项式——**状态数等于掩码数，不是行数**。这一点是本题与前面四道题最本质的差别：9-1 到 9-4 的状态是「数值参数」，本题的状态是「整个位串」，于是复杂度从多项式跳到指数。
>
> 三个因子逐个对上：$n$ 是「推进到第几列」，$2^k$ 是 $c_1$ 的取值数，$2^k$ 是 $c_2$ 的取值数，乘起来 $n\,2^{2k}$ 就是subproblem（子问题）总数；再乘上每个subproblem（子问题）的 $O(k)$（要扫一遍列找出 $t(c_1)$、要复制一列造出 $f(c)$），得 $O(2^{2k}kn)$。注意 $k$ 是题目给的常数（(b) 里 $k = 5$），所以对 $n$ 而言这是线性的；一旦 $k$ 不再是常数，这个式子就不能当多项式看。
>
> 用题给的那个 $B$ 核对一次数量。$B$ 有 $42$ 个空格（$50$ 格减去 $8$ 格泥土）。$2$ 块方石确实是最少的：把空格按棋盘染色（看 $(i + j)$ 的奇偶），黑 $20$、白 $22$，差 $2$；每块长石盖相邻两格、必为一黑一白，每块方石只盖一格，所以方石至少要 $|22 - 20| = 2$ 块。官方那组摆放正好用 $2$ 块方石：$20$ 块长石各盖 $2$ 格、$2$ 块方石各盖 $1$ 格，$20 \times 2 + 2 \times 1 = 42$，石头总数 $22$。下面 (b) 的代码会真跑一遍，打印出它自己找到的那组摆放。
>
> 跨课程连接：这一族做法在竞赛与图形学里叫 broken profile dynamic programming（断轮廓线动态规划），也叫插头 DP；它的状态是「已处理区域与未处理区域之间那条锯齿边界上的形状」。CLRS 里没有对应章节，最接近的是 §15 的区间型 DP（矩阵链、OBST），但那是「按区间长度分层」，这里是「按扫描线推进 + 边界掩码」。6.042J 那边能接的是状态机与位串编码：$2^k$ 种列状态就是 $k$ 个二元变量的全部赋值，与布尔函数的真值表一一对应，所以「按掩码枚举」本质上是「按真值表枚举」。再往 CSAPP 第 6 章靠一步：cache（高速缓存）用 tag / index / offset（标签 / 索引 / 偏移）这三段位分割把地址压成有限状态，与这里用一个 $k$ 位掩码把一列的填充情况压成有限状态，是同一种「用位串做摘要」的思路——区别只在 cache（高速缓存）的摘要由硬件算，这里的摘要由你定义。
>
> 收束：遇到「往平面上铺块」的问题，先问三件事——块的跨度最大是几列（决定状态宽度）、每列有多少种状态（决定掩码位数）、每步的决策有几种（决定分支数）。这三问的答案就是复杂度的三个因子。

**(b)** 写一个 Python function（函数）`build_wall(B)`，实现 (a) 中的 algorithm（算法），只针对 $k = 5$ 的 border plan（边界规划）。

<!-- page 7/8 -->

> **[solution] Solution（解答）:**
>
> ```python
> def get_col(B, i):
>     if i < len(B[0]):
>         return tuple(B[j][i] == '.' for j in range(5))
>     return tuple(False for j in range(5))
>
> def build_wall(B):
>     memo = {}
>     def x(i, c1, c2):                                # top-down dynamic program
>         key = (i, c1, c2)
>         if key not in memo:                          # compute if not in memo
>             j = 0
>             while j < 5 and (not c1[j]):
>                 j += 1
>             if j == 5:                               # column c1 is full
>                 if i == len(B[0]) - 1:               # base case, last line
>                     memo[key] = (0, None, None)
>                 else:                                # shift to next pair of cols
>                     memo[key] = x(i + 1, c2, get_col(B, i + 2))
>             else:                                    # need to cover (i, j)
>                 new_c1 = [i for i in c1]
>                 new_c1[j] = False
>                 test, _, _ = x(i, tuple(new_c1), c2) # place 1x1
>                 best = 1 + test
>                 move = (i, j, '1')
>                 parent = (i, tuple(new_c1), c2)
>                 if j < 4 and c1[j + 1]:              # place 1x2 down
>                     new_c1[j + 1] = False
>                     test, _, _ = x(i, tuple(new_c1), c2)
>                     if test < best:
>                         best = test
>                         move = (i, j, 'D')
>                         parent = (i, tuple(new_c1), c2)
>                     new_c1[j + 1] = True
>                 if c2[j]:                            # place 1x2 right
>                     new_c2 = [i for i in c2]
>                     new_c2[j] = False
>                     test, _, _ = x(i, tuple(new_c1), tuple(new_c2))
>                     if test < best:
>                         best = test
>                         move = (i, j, 'R')
>                         parent = (i, tuple(new_c1), tuple(new_c2))
>                 memo[key] = (best, move, parent)
>         return memo[key]
>     best, move, parent = x(0, get_col(B, 0), get_col(B, 1))
>     P = []                                           # compute placement from parent pointers
>     while parent:
>         P.append(move)
>         best, move, parent = memo[parent]
>     return P
> ```

> <span style="color:#7f8c8d;">〔原抽取串：`def build wall(B)`、`new_c1 = [i for i in c1]`、`new_c2 = [i for i in c2]`、`if i == len(B[0]) - 1`。下划线在文字层丢失，重建为 `build_wall`；原文循环变量确实写作 `i`（与外层参数同名），按原样保留，原因见下注。缩进由版面重建：官方 PDF 中这段代码的缩进在抽取时被压平，此处按 Python 语法与注释位置复原，并已实际运行验证。〕</span>

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这条注要回答的是：这段代码为什么把「值」和「父指针」一起塞进 memo（记忆表）、`new_c1 = [i for i in c1]` 这行看似会覆盖外层 `i` 为什么却无害、以及它跑出来的结果与题面给的那组 $P$ 是什么关系。
>
> 先说 memo（记忆表）的形状。`memo[key] = (best, move, parent)` 三元组一次存下三样东西：`best` 是从这个subproblem（子问题）出发所需的最少方石数，`move` 是这一步放了哪块石头（一个 `(i, j, '1'/'D'/'R')` 三元组），`parent` 是走完这一步之后落到的下一个子问题（一个 `(i, c1, c2)` 键）。三者一起存的原因很直接：题目要的不只是「最少几块方石」，还要那块数所对应的**摆放本身**。只存 `best` 能算出 $2$，但拿不出那 $22$ 个三元组；事后想补，就得重新搜索。这与 6.006 第 16 讲讲 LCS（最长公共子序列）时把 parent pointers（父指针）列为必备组件是同一条要求：值用来定答案，指针用来还原答案。
>
> 再看那行 `new_c1 = [i for i in c1]`。它里面的 `i` 与外层参数 `i` 同名，乍看像会覆盖外层变量、让递归跑飞。但 Python 3 的 list comprehension（列表推导）有**自己的作用域**——推导式内部的 `i` 是一个局部名字，出了方括号就消失，外层的 `i` 一根汗毛都没动。所以这行代码是安全的，只是写法不好（遮蔽外层名字会让读者误判）。原文如此，本译文按原样保留，并在此指出：**能跑不等于好写**，改成 `[v for v in c1]` 语义完全不变而可读性更好。
>
> 第三件事是它跑出什么。把题面给的 $B$ 直接喂进去，实测输出：
>
> ```text
> number of cube stones used = 2
> len(P) = 22
> P = [(0, 0, 'D'), (0, 2, 'D'), (0, 4, 'R'), (1, 0, '1'), (1, 1, 'D'), (1, 3, 'R'),
>      (2, 0, 'D'), (2, 2, 'R'), (3, 0, '1'), (3, 1, 'R'), (3, 3, 'D'), (4, 0, 'R'),
>      (4, 2, 'R'), (4, 3, 'D'), (5, 1, 'R'), (6, 0, 'R'), (6, 2, 'D'), (7, 1, 'D'),
>      (8, 0, 'D'), (8, 2, 'R'), (9, 0, 'D'), (9, 3, 'D')]
> ```
>
> 上面 `P = [...]` 这一行原始输出是单行，此处只为可读性折行，三元组逐项未改。
>
> 注意它与题面 (a) 上面列出的那组 $P$ **不完全相同**：题面那组的两块方石在 `(1,2,'1')` 与 `(6,3,'1')`，这里的两块在 `(1,0,'1')` 与 `(3,0,'1')`；两者的石头数都是 $22$、方石数都是 $2$。这不是 bug（程序缺陷），而是「最优值唯一、最优解不唯一」：$2$ 块方石是最小值，达到它的摆放有多种，代码里 `if test < best` 用的是**严格小于**，所以先试的 `'1'` 在并列时被保留、`'D'` 与 `'R'` 只在严格更优时才替换——tie-breaking（并列取舍）的口径决定了你看到哪一种。
>
> 光看两个列表不同没用，要证明两份都是合法解。写一个 checker（校验器）把两组摆放都还原成格子集合，逐格核对三件事：全覆盖、无重叠、不压泥土。实测结果：
>
> ```text
> --- official placement (PDF) ---
> stones: 22  cube stones: 2
> covered cells: 42  empty cells: 42
> missing cells: []
> covered-but-not-empty: []
> violations: none
> VALID: True
> --- reconstructed code output ---
> stones: 22  cube stones: 2
> covered cells: 42  empty cells: 42
> missing cells: []
> covered-but-not-empty: []
> violations: none
> VALID: True
> ```
>
> 两组都是 complete（完备）且 non-overlapping（不重叠）的合法摆放，且都用了最少的 $2$ 块方石。这也顺带验证了缩进复原是对的：若上面那段代码的嵌套层次猜错了，`memo` 会存进不同的键、`best` 的比较会发生在错误的层级，跑出来的要么不是 $2$，要么根本跑不完。
>
> 跨课程连接：这段代码是 6.006 反复强调的「top-down（自顶向下）DP＝递归 + memo」的标准形态，与 CLRS §15.3 的 memoized-cut-rod 同构——递归函数只算遇到的subproblem（子问题），`memo` 那张 hash table（哈希表）保证每个subproblem（子问题）只算一次。它与 bottom-up（自底向上）填表版的复杂度相同，差别在常数与可读性：自顶向下只访问从初始状态可达的那些掩码（本题里 $2^{10}$ 个键远没有全部被碰到），自底向上则要机械地把整张表填满。对 $k = 5$ 这种小常数，两者都够快；一旦 $k$ 变大，自顶向下的「按需展开」会明显省。
>
> 收束：这道题的代码部分真正训练的是三件事——把「值 + 决策 + 后继」打包进同一张表、用严格小于控制并列取舍、以及交付前用独立的 checker（校验器）把「合法」这件事验证一遍而不是靠眼见。
