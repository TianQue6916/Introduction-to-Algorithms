### Problem 2. [8 points] Frequentest（最高频元素）（2 小题）

下面两个 Python 函数都能正确求解如下问题：给定一个含 n 个正整数的数组 X，其中 X 中的最大整数为 k，返回 X 中出现次数最多的那个整数。
（The following two Python functions correctly solve the problem: given an array X of n positive integers, where the maximum integer in X is k, return the integer that appears the most times in X.）

假设（Assume）：
- Python 的 list（列表）用 dynamic array（动态数组）实现；
- Python 的 dict（字典）用 hash table（哈希表）实现，该哈希表从 universal hash family（全域哈希函数族）中随机选取哈希函数；
- `max(X)` 在最坏情况下以 $O(|X|)$ 时间返回数组 X 中的最大整数。

对每个函数，用 n 和 k 表示其 worst-case（最坏情况）与 expected（期望）运行时间。

#### (a) [4 points]

```python
def frequentest_a(X):
    k = max(X)
    H = {}
    for x in X:
        H[x] = 0
    best = X[0]
    for x in X:
        H[x] += 1
        if H[x] > H[best]:
            best = x
    return best
```

**i. Worst-case（最坏情况）：**

**ii. Expected（期望）：**

#### (b) [4 points]

```python
def frequentest_b(X):
    k = max(X)
    A = []
    for i in range(k + 1):
        A.append(0)
    best = X[0]
    for x in X:
        A[x] += 1
        if A[x] > A[best]:
            best = x
    return best
```

**i. Worst-case（最坏情况）：**

**ii. Expected（期望）：**

### 解答（Solution）

**核心思路（idea）：** 本题考察 hash table（哈希表）与 direct-access array（直接寻址数组）两种计数方式的运行时间差异——前者时间只与 n 有关，后者时间还与 k 有关。

#### (a) `frequentest_a`

**算法本质：** 用 dict（即哈希表）H 来统计每个整数的出现次数。第一步 `k = max(X)` 花费 $O(n)$；第二步 `for x in X: H[x] = 0` 初始化，每个元素做一次哈希插入，耗时 $O(n)$（期望）；第三步再遍历一遍 X 做累加并维护 `best`，同样 $O(n)$。

**正确性（循环不变式）：** 在第二个 `for` 循环的每次迭代结束时，不变式为：对已经遍历过的所有元素，`H[x]` 恰为 x 到目前为止出现的次数，且 `best` 是已遍历元素中出现次数最多的那个（出现并列时取先出现者）。初始化（未遍历任何元素）时 `best = X[0]` 且 `H[X[0]]` 尚未累加——但首轮遍历到 `X[0]` 时 `H[X[0]]` 变为 1，`H[X[0]] > H[best]` 不成立（相等），故 `best` 保持为 `X[0]`，不变式成立。归纳步：处理元素 x 时，`H[x] += 1` 使计数正确；若 `H[x] > H[best]` 则更新 `best`，故 `best` 仍指向当前最大值。终止时已遍历全部 n 个元素，`best` 即为全局出现次数最多的整数，返回正确。

**复杂度分析：**
- **Worst-case（最坏情况）：** 哈希表单次操作在最坏情况下可能退化为 $O(n)$（例如哈希函数把全部键映射到同一槽位，发生大量碰撞），于是两次遍历共 $2n$ 次操作，每次最坏 $O(n)$，合计 $O(n^2)$。
- **Expected（期望）：** 由于哈希函数从 universal hash family（全域哈希函数族）中随机选取，单次哈希表操作（插入/查询/更新）的期望时间为 $O(1)$。因此总期望时间为

```math
O(n) + O(n) + O(n) = O(n)
```

**答案：** 最坏 $O(n^2)$；期望 $O(n)$。

#### (b) `frequentest_b`

**算法本质：** 用长度为 $k+1$ 的 direct-access array（直接寻址数组）A 来计数，其中下标就是元素值本身。`A.append(0)` 循环执行 $k+1$ 次，这是本题与 (a) 的关键差异——运行时间将依赖 k。

**正确性（循环不变式）：** 在第二个 `for` 循环每次迭代结束时，对数组下标 $0 \le i \le k$，`A[i]` 恰为值 i 在已遍历元素中出现的次数，`best` 为已遍历元素中出现次数最多的值。因为元素值都是正整数且不超过 k，直接寻址数组 A 能唯一、无碰撞地存储每个值的计数（这正是 direct-access array 相对哈希表的优势——无需处理碰撞）。归纳过程与 (a) 相同，终止时返回正确的最高频整数。

**复杂度分析：**
- 初始化数组 A 的循环花费 $\Theta(k)$ 时间（执行 $k+1$ 次 `append`，动态数组均摊每次 $O(1)$，故总 $O(k)$）。注意：动态数组 `append` 的均摊成本为 $O(1)$，这是 amortized analysis（均摊分析）的经典结论——即使某次扩容需复制全部元素，摊到所有操作上仍是 $O(1)$。
- `max(X)` 花费 $O(n)$。
- 计数遍历花费 $O(n)$。

由于这里不涉及随机哈希，最坏与期望相同：

```math
T(n,k) = O(k) + O(n) + O(n) = O(n + k)
```

**答案：** 最坏 $O(n+k)$；期望 $O(n+k)$。

> **小结：** (a) 与 (b) 的本质差别在于「用空间换确定性」——(a) 哈希表时间与 k 无关，期望快但最坏可能退化为 $O(n^2)$；(b) 直接寻址数组最坏、期望都稳定为 $O(n+k)$，但当 k 很大时初始化代价高昂。两者各有利弊。

## 第 4 页 · Problem 3

### Problem 3. [10 points] Haphazard Heap（乱序堆）（3 小题）

数组 `[A, B, C, D, E, F, G, H, I, J]` 表示一个含 10 个元素的 binary min-heap（二叉最小堆），其中每个元素的 key（键）都是互不相同的整数。请说明数组中哪个（些）元素可能拥有以下键：
（Array [A,B,C,D,E,F,G,H,I,J] represents a binary min-heap containing 10 items, where the key of each item is a distinct integer. State which item(s) in the array could have the key with:）

- (a) 最小整数（the smallest integer）
- (b) 第三小的整数（the third smallest integer）
- (c) 最大整数（the largest integer）

### 解答（Solution）

**核心概念（definition）：** 一个 binary min-heap（二叉最小堆）是一棵 complete binary tree（完全二叉树），且满足 heap property（堆性质）：每个结点的键 $\le$ 其所有子结点的键。用数组表示时，下标为 i 的结点（数组从 1 开始计数，即 A 为 1 号、B 为 2 号、…、J 为 10 号）的左孩子为 $2i$，右孩子为 $2i+1$，父结点为 $\lfloor i/2 \rfloor$。

题目数组 `[A,B,C,D,E,F,G,H,I,J]` 对应下标 1–10，其隐式完全二叉树结构为：

```math
\text{层 1: } A \\
\text{层 2: } B, C \\
\text{层 3: } D, E, F, G \\
\text{层 4: } H, I, J
```

其中父—子关系：A 的孩子是 B、C；B 的孩子是 D、E；C 的孩子是 F、G；D 的孩子是 H、I；E 的孩子是 J；F、G、H、I、J 为叶（其中 F、G 无孩子，H、I、J 也无孩子）。

#### (a) 最小整数（the smallest integer）

**判据（为什么这样判断）：** 最小堆的 heap property 要求「父结点键 ≤ 子结点键」，因此整棵树的最小键必然位于根结点（数组下标 1），即 A。因为任何其他结点都有一个祖先链最终指向根，沿链每上一层键不增，故根的键 $\le$ 所有结点的键。

**答案：** 只有 **A** 可能拥有最小整数。

#### (b) 第三小整数（the third smallest integer）

**判据：** 第三小的键必须是在「除最小键外，距离根最近、且未被更小键占据的若干候选结点」之中。由于键互不相同：

- 最小的键在 A（根）。
- 第二小的键只能出现在 A 的两个孩子 B 或 C 之一（因为除根外，任何结点若要成为第二小，它上面只能有一个比它小的祖先，即根；而只有 B、C 的父亲恰好就是根 A，其余结点的祖先链更长、中间至少还有一个键更小的结点，故第二小必在 B、C 中）。
- 第三小的键：在排除前两小后，可能的候选结点必须满足「其上只有至多两个键更小」。具体地，候选集合为 $\{B, C, D, E\}$——即根 A 的孩子与孙子层中、父结点可能尚未被前两小占据的那些结点。

更严格地论证（用层数上界）：第 r 小的键所在结点的 depth（深度，即到根的边数）至多为 $r-1$。原因：从根到该结点的路径上共有 depth 个祖先，每个祖先的键都更小（heap property），故比它小的键至少有 depth 个，于是 $r-1 \ge \text{depth}$。第三小（$r=3$）要求 depth $\le 2$，即该结点只能是深度 0、1、2 的结点——即 A、B、C、D、E。再排除已被前两小占据的 A 和（B 或 C 之一），剩下候选为 $\{B, C, D, E\}$ 中未被占用的三个。

**答案：** 第三小整数可能位于 **B、C、D、E 中的任意一个**（更精确地说，是集合 $\{B,C,D,E\}$ 去掉第二小所处位置后的剩余三者之一）。

#### (c) 最大整数（the largest integer）

**判据：** 最大键只需满足「大于它自己的所有祖先」，而对它的孩子没有约束（它是叶子就没有孩子；若有孩子，堆性质只要求它 ≤ 孩子，但这与「它是全局最大」矛盾——故最大键所在结点不能有孩子）。因此最大键必须是一个 leaf（叶子结点）。本题的叶子为 F、G、H、I、J。

**答案：** 最大整数可能位于 **F、G、H、I、J 中的任意一个**（即所有叶子结点）。

> **小结：** 本题的核心是「heap property + 完全二叉树的结构」联合决定的定位上界：最小值锁定在根；第 r 小的结点深度 ≤ r−1；最大值必在叶子层。

## 第 5 页 · Problem 4

### Problem 4. [10 points] Transforming Trees（变换树）（2 小题）

下面这棵树包含 8 个元素，每个存储的元素是一个整数，且整数本身就是它的 key。
（The tree below contains 8 items, where each stored item is an integer which is its own key.）

```
            93
           /  \
         85    23
        /  \   /  \
      17   63 38  11
                /
              13
```

（原图为：根 93；93 的左孩子 85、右孩子 23；85 的左孩子 17、右孩子 63；23 的左孩子 38、右孩子 11；38 的左孩子 13。）

#### (a) [6 points] 假设上面画的这棵树是某个 binary max-heap H 的 implicit tree（隐式树）。请写出 H 的数组表示——先写执行操作 H.delete_max() 之前，再写执行之后。
（Suppose the tree drawn above is the implicit tree of a binary max-heap H. State the array representation of H, first before and then after performing the operation H.delete_max().）

#### (b) [4 points] 改为假设：上面这棵原始树是一个 Sequence AVL Tree（序列 AVL 树）S（注意 Sequence 数据结构是 zero-indexed，即从 0 开始索引）。S 的叶子按 traversal order（遍历顺序）存储的元素为 (17, 63, 11, 13)。对 S 执行操作 S.delete_at(3)，包括任何所需的旋转，然后在操作完成后，按遍历顺序列出 S 叶子中存储的元素。（你不需要画出这棵树。）
（Suppose instead that the original tree drawn above is a Sequence AVL Tree S (note Sequence data structures are zero-indexed). The items in the leaves of S in traversal order are (17, 63, 11, 13). Perform operation S.delete_at(3) on S including any rotations, and then list the items stored in the leaves of S in traversal order, after the operation has completed. (You do not need to draw the tree.)）

### 解答（Solution）

#### (a) 二叉最大堆的数组表示与 delete_max

**核心概念（definition）：** binary max-heap（二叉最大堆）的数组表示按「逐层、自左向右」的顺序填充数组，下标从 1 开始。给定上面的隐式树：

- 第 1 层：93
- 第 2 层：85, 23
- 第 3 层：17, 63, 38, 11
- 第 4 层：13（位于 38 的左孩子）

**操作前的数组表示：** 逐层自左向右排列：

```math
[93,\ 85,\ 23,\ 17,\ 63,\ 38,\ 11,\ 13]
```

对应下标：1→93, 2→85, 3→23, 4→17, 5→63, 6→38, 7→11, 8→13。

**执行 H.delete_max()：** 最大堆的 delete-max 操作（删除根并维持堆性质）步骤为：

1. 取出并删除根（最大值 93）。
2. 将数组最后一个元素（下标 8 的 13）搬到根的位置（下标 1），即把 13 放到根，同时堆的大小减 1（剩下 7 个元素）。
3. 从根开始执行 max-heapify（向下沉 / 下滤）：13 与其两个孩子 85、23 比较，最大的是 85（85 > 23 > 13），故 13 与 85 交换。
4. 13 现在在 85 的原位置（下标 2），其孩子为 17、63，最大的是 63（63 > 17 > 13），故 13 与 63 交换。
5. 13 现在在 63 的原位置（下标 5），该位置没有孩子（原树中 63 无孩子），下滤结束。

**操作后的树：**

```
            85
           /  \
         63    23
        /  \   /  \
      17   13 38  11
```

**操作后的数组表示（逐层自左向右）：**

```math
[85,\ 63,\ 23,\ 17,\ 13,\ 38,\ 11]
```

**正确性说明（为什么这样做是对的）：** delete_max 的正确性依据 max-heapify 的不变式——在每次下沉前，以当前结点为根的子树，除了当前结点本身可能违反堆性质外，其余都满足堆性质；每次把当前结点与最大的孩子交换后，违反堆性质的结点下移一层，最终到达叶子或不再违反，整棵树恢复为合法的最大堆。这里每一步都按「与较大的孩子交换」执行，故结果正确。

#### (b) 序列 AVL 树的 delete_at(3)

**核心概念（definition）：** Sequence AVL Tree（序列 AVL 树）是一种 augmented（增广）二叉搜索树，每个结点额外存储其 subtree size（子树大小），从而支持按 traversal order（中序遍历顺序）进行下标访问、插入、删除，所有操作保持 AVL 平衡（任一结点左右子树高度差 ≤ 1）。

题意关键：叶子按遍历顺序为 (17, 63, 11, 13)，且是 zero-indexed（从 0 开始）。执行 `S.delete_at(3)` 即删除遍历顺序中下标为 3 的元素。

**下标定位（为什么 delete_at(3) 删的是 13）：** 遍历顺序（中序）下，叶子依次为：

```math
\text{下标 } 0:\ 17,\quad 1:\ 63,\quad 2:\ 11,\quad 3:\ 13
```

因此下标 3 对应叶子 **13**。`delete_at(3)` 删除的就是元素 13。

**删除后的叶子序列：** 删除 13 后，剩下的叶子按原遍历顺序为 (17, 63, 11)。删除操作可能触发 rebalancing（旋转），但 AVL 旋转只改变树的结构（即哪些内部结点作为「高度平衡子树」），**不会改变元素的中序遍历顺序**——这是 AVL 旋转的一个基本不变式（旋转保持 inorder 顺序不变）。

**答案：** 操作完成后，S 的叶子按遍历顺序存储的元素为：

```math
(17,\ 63,\ 11)
```

> **论证要点：** 旋转不改变遍历顺序（这是 binary search tree 旋转操作的核心性质——单旋或双旋只是局部的指针调整，中序序列保持不变量）。因此无论发生多少次旋转，删除下标 3（元素 13）后的叶子序列恒为 (17, 63, 11)。

## 第 6 页 · Problem 5

### Problem 5. [20 points] Sorting Sock（排序袜）（4 小题）

在 Wog Hearts 魔法与巫术学校，n 名新生由一个古老魔法神器「排序袜（Sorting Sock）」分入四个学院。排序袜首先按四个学院各自的特质对这 n 名学生进行排序，然后依据排序结果作出判定。对下面每一小题，请说明并论证哪种排序方法最高效。
（At Wog Hearts School of Wizcraft and Witcherdry, n incoming students are sorted into four houses by an ancient magical artifact called the Sorting Sock. The Sorting Sock first sorts the n students by each of the four houses' attributes and then uses the results to make its determinations. For each of the following parts, state and justify what type of sort would be most efficient.）

> 注：所谓「高效（efficient）」指——正确且更快的算法将比更慢的获得更多分数。

#### (a) [5 points] 对 Hufflepuff（赫奇帕奇，原文写作 "Puffle Huff"）学院：学生须按 friend number（朋友数）排序，即「他们与其余 n−1 名新生中多少人是朋友」，且该朋友数可在 O(1) 时间内确定。
（For House Puffle Huff, students must be sorted by friend number, i.e., how many of the other n − 1 incoming students they are friends with, which can be determined in O(1) time.）

#### (b) [5 points] 对 Ravenclaw（拉文克劳，原文写作 "Craven Law"）学院：学生须按他们书籍的重量排序。书籍重量无法精确测量，但排序袜有一台秤，可以在 O(1) 时间内判断一组书的总重量是大于、小于还是等于另一组书。
（For House Craven Law, students must be sorted by the weight of their books. Book weights cannot be measured precisely, but the Sorting Sock has a scale that can determine in O(1) time whether one set of books has total weight greater than, less than, or equal to another set of books.）

### 解答（Solution）

> 说明：原文第 6 页在 (b) 之后截止（本 EX3 的任务范围即第 1–6 页）。本题 (c)、(d) 两小题出现在第 7 页，超出本次译注范围。以下对已给出的 (a)、(b) 两小题作完整解答。

#### (a) 按朋友数排序（friend number 可在 O(1) 内取得）

**核心概念（definition）：** friend number 是 0 到 n−1 之间的一个非负整数，且是每个学生的一个可 O(1) 取得的 key（键）。由于 key 的取值范围是有界的（$0 \le \text{key} < n$），且所有 key 都是非负整数，这正适合 **counting sort（计数排序）** 或 **radix sort（基数排序）**。

**最高效选择：counting sort（计数排序）。**

**理由（为什么 counting sort 最优）：** 计数排序的思想是——由于 key 的取值范围 $[0, n-1]$ 只有 n 个可能值，可以用一个大小为 n 的计数数组直接统计每个朋友数出现的人数，再按 key 从小到大输出，从而在不做任何两两比较的情况下完成排序。其运行时间为

```math
T(n) = O(n + n) = O(n)
```

**正确性（为什么 counting sort 正确）：** 计数排序的循环不变式为：在统计阶段结束后，计数数组 `C[j]` 恰等于 key 为 j 的学生人数；在输出阶段，我们按 j 从 0 到 n−1 依次把 `C[j]` 个 key 为 j 的学生加入结果，故结果中的学生按朋友数非降序排列，且每个学生恰好出现一次（稳定/不稳定均保证正确排序）。因此排序正确。

**为何比比较排序更快：** 任何基于两两比较的排序（如 merge sort、quick sort）在最坏/平均情形下都需要 $\Omega(n \log n)$ 次比较；而计数排序利用 key 的有界整数性质，绕过了比较下界，达到 $O(n)$。故对本小题计数排序最高效。

**答案：** 使用 counting sort（计数排序），运行时间 $O(n)$。

#### (b) 按书籍重量排序（只能三态比较：大于 / 小于 / 等于）

**核心概念（definition）：** 这里排序只能依赖 comparison（比较）——秤给出的信息等价于一次「三态比较」，且比较操作本身是 O(1)。由于我们**只能通过比较获得相对顺序信息**，无法像 (a) 那样利用整数 key 的取值结构做计数，因此本题的最优界就是 comparison-based sort（基于比较的排序）的理论下界 $\Omega(n \log n)$。

**最高效选择：merge sort（归并排序）。**

**理由（为什么 merge sort 最优）：** 归并排序是典型的 comparison-based sort，其最坏情况运行时间为 $\Theta(n \log n)$，且**达到比较排序的最坏情况最优下界**。相比之下，quick sort 的最坏情况是 $O(n^2)$（尽管期望 $O(n\log n)$），而 heap sort 虽同为 $\Theta(n\log n)$ 但常数较大。因此在对最坏情况敏感的「最高效」要求下，归并排序是最稳妥的选择。

**复杂度分析（递推式并求解）：** 归并排序将规模 n 的问题分成两个规模 $n/2$ 的子问题，合并两个有序序列需 $\Theta(n)$ 次比较。其递推式为：

```math
T(n) = 2T\left(\frac{n}{2}\right) + \Theta(n), \qquad T(1) = \Theta(1)
```

用 Master Theorem（主定理）求解：此递推式符合主定理的第二种情形，$a=2,\ b=2,\ f(n)=\Theta(n)$，且 $f(n)=\Theta(n^{\log_2 2})=\Theta(n)$，故

```math
T(n) = \Theta(n \log n)
```

**为何不能再快（下界论证）：** 基于比较的排序，其 decision tree（决策树）至少有 $n!$ 个叶子，树高至少为 $\log_2(n!) = \Theta(n \log n)$（由 Stirling 近似 $\log_2(n!) = n\log_2 n - O(n)$ 得到）。因为一次比较最多将可能排列数减半，要区分 $n!$ 种排列至少需要 $\log_2(n!)$ 次比较。故 $\Omega(n \log n)$ 是无法突破的下界。

**答案：** 使用 merge sort（归并排序），运行时间 $\Theta(n \log n)$，达到比较排序最优下界。

> **小结 (a) 与 (b) 的对比：** (a) 因为 key 是取值有界的整数，可用计数排序突破比较下界达到 $O(n)$；(b) 因为只能做相对比较、无整数结构可资利用，最优只能是 $\Theta(n \log n)$ 的归并排序。这正是「能否利用 key 的结构信息」决定排序上界差异的经典例证。

### Problem 5. [20 points] Sorting Sock（排序袜）—— (c)、(d) 小题

> 承接第 6 页 (a)、(b) 两小题。以下为同题剩余两小题。

#### (c) [5 points] 对 Gryffindor（格兰芬多，原文写作 "House Driven Gore"）学院：学生须按 bravery（勇气值）排序，但勇气值无法被直接测量或量化；不过，对任意一组学生，排序袜可以在 O(1) 时间内找出其中勇气值最高（bravest）的那名学生——例如，通过让学生们面对一个可怕的场面。
（For House Driven Gore, students must be sorted by bravery, which can't be directly measured or quantified, but for any set of students, the Sorting Sock can determine the bravest among them in O(1) time, e.g., by presenting the students with a scary situation.）

#### (d) [5 points] 对 Slytherin（斯莱特林，原文写作 "House Leather Skin"）学院：学生须按他们的 magical lineage（魔法血统）排序，其定义为：在这名学生往前推 $3\lceil \log n\rceil + 4$ 代以内的祖先中，有多少位是魔法师。回想一下：人类（无论是否魔法师）在前一代总是恰好有两位双亲，这一点与 binary tree（二叉树）的结点不同——二叉树结点至多只有一个父结点。假设排序袜可以在 O(1) 时间内计算出任意一名学生的魔法血统值。
（For House Leather Skin, students must be sorted by their magical lineage: how many of a student's ancestors within the previous 3dlog ne + 4 generations were magical. Recall that humans, magical or not, always have two parents in the previous generation, unlike binary tree nodes which have at most one. Assume the Sorting Sock can compute the magical lineage of a student in O(1) time.）

### 解答（Solution）

#### (c) 按勇气值排序（只能「找最大值」，无法两两比较）

**核心思路（idea）：** 排序袜提供的是一个「任意子集求最大」的 oracle（预言机），它在 O(1) 时间内返回一组学生中的最勇敢者，但**不能**直接比较任意两名学生的勇气大小。要排序，我们必须反复利用「找最大」这一操作。

**最高效选择：selection sort（选择排序）。**

**理由（为什么 selection sort 最优）：** 选择排序的每一步恰好就是「在剩余未排序的元素中找出最大者，把它放到已排序部分的末尾」。而这正是排序袜唯一能做的操作——在 O(1) 内找出子集中的最大者。因此选择排序天然适配本小题的能力模型：第 i 步在 $n-i+1$ 个剩余学生中找出最勇敢者（O(1)），放置到正确位置，共执行 $n-1$ 步。

**复杂度分析（写出递推式并求解）：** 第 1 步在 n 个学生中找最大，第 2 步在 $n-1$ 个中找最大，……，第 $n-1$ 步在 2 个中找最大。每一步的「找最大」都是 O(1)，总时间为：

```math
T(n) = \sum_{i=2}^{n} O(1) = (n-1)\cdot O(1) = O(n)
```

**正确性（循环不变式）：** 在第 k 次「找最大」操作完成后，不变式为：数组末尾的 $k$ 个位置已按勇气值从低到高（或从高到低，取决于放置方向）有序填好，且这 $k$ 个元素恰好是全体元素中勇气值最小的 $k$ 个。初始化（$k=0$）时末尾 0 个位置，平凡成立。归纳步：第 $k+1$ 次操作在剩余 $n-k$ 个学生中选出勇气最大者（即剩余集合中尚未放置的最勇敢者），把它放到「已排序部分」之前，故末尾 $k+1$ 个位置仍有序且是全体最小的 $k+1$ 个。终止（$k=n-1$）时全体有序。

> **关键洞察：** 因为「找最大」被假设为 O(1)，选择排序打破了基于比较排序的 $\Omega(n \log n)$ 下界——该下界的前提是每次只能做一次三态比较，而本小题的 oracle 一次就能定位整个子集的最大值，信息量远大于一次比较。故能达到 $O(n)$。

**答案：** 使用 selection sort（选择排序），运行时间 $O(n)$。

#### (d) 按魔法血统排序（key 可直接 O(1) 算出，但取值域巨大）

**核心思路（idea）：** 魔法血统值是每个学生的一个整数 key，可在 O(1) 内算出。表面看这像 (a)——key 是整数——但关键区别在于 key 的取值范围：往前 $3\lceil\log n\rceil+4$ 代，每代祖先数翻倍，故第 $g$ 代有 $2^g$ 位祖先。血统值（魔法祖先的个数）最大可以是全部祖先数：

```math
\sum_{g=1}^{3\lceil\log n\rceil+4} 2^{g} = 2^{3\lceil\log n\rceil+5} - 2 = O\big(2^{3\log n}\big) = O(n^3)
```

**为什么不能用 counting sort（计数排序）：** (a) 中 key 取值域为 $[0,n-1]$，只有 $n$ 个可能值，计数数组大小 O(n) 即可。但本小题血统值的取值域达到 $O(n^3)$——第 $3\lceil\log n\rceil$ 代祖先数约为 $2^{3\log n}=n^3$ 量级。若用计数排序，计数数组需要 $O(n^3)$ 大小，远超 $O(n)$ 的「最高效」要求，故计数排序不可行。

**最高效选择：comparison-based sort（基于比较的排序），具体用 merge sort（归并排序）或 heap sort（堆排序）。**

**理由：** 既然 key 是整数且能 O(1) 算出，任意两名学生之间可以 O(1) 比较其血统值大小（各算一次再比较）。因此这是一个标准的 comparison-based 排序，最优界为 $\Theta(n \log n)$。取能达到最坏情况最优的 merge sort（或 heap sort）。

**复杂度分析（递推式并求解）：** 归并排序递推式：

```math
T(n) = 2T\left(\frac{n}{2}\right) + \Theta(n), \qquad T(1)=\Theta(1)
```

由 Master Theorem（主定理）第二种情形（$a=2,\ b=2,\ f(n)=\Theta(n)=\Theta(n^{\log_2 2})$）：

```math
T(n) = \Theta(n \log n)
```

**正确性（为什么基于比较的排序正确）：** merge sort 的正确性由「归并两个已有序序列得到有序序列」这一归纳结构保证：递归地先各自有序（归纳假设），再线性合并。其循环不变式为——在 merge 的每一步，输出数组已填入的是两子序列中当前剩余元素的最小者，故输出始终非降序，且最终包含全部元素。合并正确 ⟹ 递归正确。

> **对比 (a) 与 (d)：** (a) 与 (d) 的 key 都是 O(1) 可算的整数，但 (a) 取值域 $[0,n-1]$ 有界、可计数排序达 $O(n)$；(d) 取值域 $O(n^3)$ 太大，计数数组不可承受，只能退回基于比较排序的 $\Theta(n\log n)$。**「key 的取值域大小」决定了能否用计数排序。**

**答案：** 使用 merge sort（归并排序，或 heap sort），运行时间 $\Theta(n \log n)$。

## 第 8 页 · Problem 6

### Problem 6. [15 points] Triple Sum（三数之和）

给定三个数组 A、B、C，每个都包含 n 个整数。给出一个 $O(n^2)$ 时间的算法，判断是否存在某个 $a \in A$、某个 $b \in B$、某个 $c \in C$ 使得三者之和为零，即 $a + b + c = 0$。请说明你的运行时间是 worst-case（最坏情况）、expected（期望）还是 amortized（均摊）。
（Given three arrays A, B, C, each containing n integers, give an O(n2)-time algorithm to find whether some a ∈ A, some b ∈ B, and some c ∈ C have zero sum, i.e., a + b + c = 0. State whether your running time is worst-case, expected, and/or amortized.）

### 解答（Solution）

**核心思路（idea）：** 直接三重循环枚举所有 $(a,b,c)$ 是 $O(n^3)$，太慢。关键观察：等式 $a+b+c=0$ 等价于 $a+b = -c$。于是我们可以**固定 c（枚举 C 中的每个元素），把问题化为「在 A、B 中找一对元素，其和等于 $-c$」**，而后者可用排序 + 双指针在 $O(n)$ 内完成（或者用哈希表在期望 $O(n)$ 内完成）。

**算法（pseudocode）：**

```text
TRIPLE-SUM(A, B, C):
    1. 将数组 B 按非降序排序          // 花费 O(n log n)
    2. 对 A 也排序                    // 花费 O(n log n)
    3. for 每个 c ∈ C:               // 共 n 轮，每轮 O(n)
    4.     target = -c
    5.     i = 0, j = n - 1          // 双指针：i 指向 A 首，j 指向 B 尾
    6.     while i < n 且 j ≥ 0:
    7.         s = A[i] + B[j]
    8.         if s == target: return true
    9.         else if s < target: i = i + 1   // 和偏小，增大 A 的下标
    10.        else:               j = j - 1   // 和偏大，减小 B 的下标
    11. return false
```

> 注：也可用哈希表替代双指针——对每个 c，把 B 的元素全部放入哈希表，再对每个 $a\in A$ 查 $-(a+c)$ 是否在哈希表中，期望 $O(n)$ 每轮，总期望 $O(n^2)$。此处给出的是确定性的排序 + 双指针版本，保证 worst-case $O(n^2)$。

**为什么双指针正确（循环不变式）：** 在固定 c 的内层 while 循环中，不变式为：若存在 $a'\in A,\ b'\in B$ 使 $a'+b'=\text{target}$，则这对 $(a',b')$ 对应的下标必满足 $i \le a'$ 的 index 且 $b'$ 的 index $\le j$（即尚未被双指针「越过去」丢弃的区域内）。初始化时 $i=0,\ j=n-1$，覆盖整个搜索空间，成立。归纳步：若当前 $s<\text{target}$，则对任何 $b'\le B[j]$，$A[i]+b' \le A[i]+B[j] = s < \text{target}$，故 $A[i]$ 不可能与任何尚未考虑的 B 元素配对成和，可以安全地 $i=i+1$ 而不丢失解；对称地，$s>\text{target}$ 时 $j=j-1$ 也安全。终止时要么命中 target 返回 true，要么 $i,j$ 交叉、搜索空间耗尽，说明无解返回 false。不变式保证每一步都不丢失任何可行解，故算法正确。

**复杂度分析（写出递推式并求解）：**

- 排序 A、B 各一次：$O(n \log n)$。
- 外层循环 n 轮（枚举 c），每轮内层双指针扫描 A、B 至多 $O(n)$ 步（i 只增不降、j 只降不增，合计移动 $O(n)$ 次）。故主体为：

```math
T(n) = O(n \log n) + O(n \log n) + n \cdot O(n) = O(n^2)
```

（若展开可写为 $T(n)=2\,O(n\log n)+\sum_{c\in C}O(n)=O(n^2)$。）

**运行时间性质：** 本算法不依赖随机性，故为 **worst-case（最坏情况）$O(n^2)$**（同时也是 expected 与 amortized 的 $O(n^2)$）。若改用哈希表版本，则主体为 expected（期望）$O(n^2)$，最坏情况可能退化。

**答案：** 存在一个 worst-case $O(n^2)$ 的算法（排序 + 双指针），正确判断三数之和是否为零。

## 第 9 页 · Problem 7

### Problem 7. [15 points] Where am i?（我在哪？）

给定一棵含 n 个结点的 Sequence AVL Tree（序列 AVL 树）T，以及一个指向 T 中结点 v 的指针。请描述一个 $O(\log n)$ 时间的算法，返回结点 v 在 T 的 traversal order（遍历顺序）中的（从零开始索引的）下标 i。
（Given a Sequence AVL Tree T containing n nodes, and a pointer to a node v from T, describe an O(log n)-time algorithm to return the (zero-indexed) index i of node v in the traversal order of T.）

> 回想：Sequence AVL Tree T 中每个结点 u 存储：元素 u.item、父结点 u.parent、左孩子 u.left、右孩子 u.right、子树高度 u.height、子树大小 u.size。
（Recall that every node u in a Sequence AVL Tree T stores an item u.item, parent u.parent, left child u.left, right child u.right, subtree height u.height, and subtree size u.size.）

### 解答（Solution）

**核心概念（definition）：** Sequence AVL Tree（序列 AVL 树）是一棵 **AVL 树**（一种 self-balancing binary search tree，自平衡二叉搜索树，满足任意结点左右子树高度差 ≤ 1）的 **augmented（增广）** 版本：每个结点额外存储 subtree size（子树大小，即该子树内的结点总数），从而支持按 traversal order（中序遍历顺序，即排序后从小到大的顺序）在 $O(\log n)$ 内完成「按下标访问 / 求某结点的下标 / 插入 / 删除」等序列操作。

**核心思路（idea）：** 结点 v 在遍历顺序中的下标 i，等于「在遍历顺序中排在 v 之前」的结点个数。这些结点恰好由三部分构成：

1. v 的**左子树**中的所有结点（它们在中序里都排在 v 之前）；
2. 从 v 向上走到根的过程中，每次「从某个祖先的**右孩子**一侧向上」时，该祖先及其**左子树**里的所有结点也都排在 v 之前。

**算法（pseudocode）：**

```text
INDEX-OF(T, v):
    1. i = v.left.size                 // 第一部分：v 左子树全部排在 v 之前
    2. x = v
    3. while x.parent ≠ NIL:           // 沿父指针向上走到根
    4.     if x == x.parent.right:     // x 是父结点的右孩子
    5.         i = i + 1 + x.parent.left.size
    6.                                 //   加：父结点本身(1) + 父结点左子树(left.size)
    7.     x = x.parent
    8. return i
```

（说明：第 5 步里「+1」是父结点本身——因为父结点的左子树结点、以及父结点自身，在中序里都排在 v 之前。）

**为什么这样做正确（循环不变式）：** 设当前变量 x 为 v 沿父指针上移后所处的位置，不变式为：变量 i 恰好等于「在以 x 为根的子树中、且在遍历顺序里排在 v 之前」的结点个数。

- **初始化（进入 while 前，x = v）：** $i = v.\text{left}.\text{size}$，恰为「v 的左子树中排在 v 之前的结点数」，而 v 右子树中的结点都排在 v 之后、不计入，不变式成立。
- **归纳步（一次上移）：** 假设在 x 处不变式成立（i 已累计了 x 子树内排在 v 之前的结点数）。若 x 是父结点 p 的左孩子，则 p 及其右子树都排在 v 之后，上移到 p 时不需累加，i 仍是「p 子树内排在 v 之前的结点数」，不变式保持；若 x 是 p 的右孩子，则 p 的左子树全部结点、以及 p 本身，都排在 v 之前（因为这些元素在中序里都位于 p 的左孩子一侧），需累加 $p.\text{left}.\text{size}+1$，上移后 i 即为「p 子树内排在 v 之前的结点数」，不变式保持。
- **终止（x 到达根）：** 此时 i 是「整棵树 T 内排在 v 之前的结点数」，而「排在 v 之前的结点数」正是 v 的 zero-indexed 下标。返回 i 正确。

**复杂度分析：** 每一步沿父指针上移一层，至多经过树高 h 步。由于 T 是 AVL 树，其高度满足 $h = O(\log n)$（AVL 树平衡性质保证 $h \le 1.44\log_2(n+1)$ 量级）。每步只做常数次 size 读取与加法，故：

```math
T(n) = O(h) = O(\log n)
```

**运行时间性质：** 确定性算法，worst-case（最坏情况）$O(\log n)$。

**答案：** 用「左子树大小 + 沿父指针累加『从右孩子一侧上来的祖先及其左子树』」的方法，在 $O(\log n)$ 时间内返回 v 的零基下标 i。

## 第 10 页 · Problem 8

### Problem 8. [20 points] Methane Menace（甲烷威胁）

FearBird 是一个超级反派，他一直在 mahtoG 市的甲烷燃气管道网络上打小孔。该网络由 n 根管道组成，每根管道用一个互不相同的正整数作为标签。一个孔 i 用一对正整数 $(p_i, d_i)$ 表示，其中 $p_i$ 表示该孔所在管道的标签，$d_i$ 是一个正整数，表示该孔距离管道 $p_i$ 前端的距离。假设同一根管道 $p_i$ 上的任意两个孔，到其前端的距离都互不相同。当发现一个新孔 $(p_i, d_i)$ 时，城市会收到一份报告，记录下来以便跟踪。城市会按如下优先级方案定期修补孔：

- 如果每根管道上至多只有一个孔，则修补任意一个孔（如果存在的话）；
- 否则，在出现在同一根管道上的孔对（即 $p_i = p_j$）中，找出任意一对距离差 $|d_i - d_j|$ 最小的孔，并修补其中一个。

请描述一个数据库，支持以下操作，其中 k 是操作发生时网络中「已记录但尚未修补」的孔的数量。请说明你的运行时间是 worst-case（最坏情况）、expected（期望）还是 amortized（均摊）。

- **initialize(H)**：用 n 个孔 $H = \{(p_0, d_0), \dots, (p_{n-1}, d_{n-1})\}$ 初始化数据库，每根管道上恰好一个孔，在 $O(n)$ 时间内完成。
- **report(p_i, d_i)**：记录管道 $p_i$ 上距离 $d_i$ 处存在一个孔，在 $O(\log k)$ 时间内完成。
- **patch()**：按上述优先级方案修补任意一个孔，在 $O(\log k)$ 时间内完成。

（原文英文：FearBird is a supervillian who has been making small holes in the methane gas pipe network of mahtoG City. The network consists of n pipes, each labeled with a distinct positive integer. A hole i is designated by a pair of positive integers (pi, di), where pi denotes the label of the pipe containing the hole, and di is a positive integer representing the distance of the hole from the front of pipe pi. Assume any two holes in the same pipe pi will be at different distances from the front of pi. When a new hole (pi, di) is spotted, the city receives a report of the hole to keep track of. The city will periodically patch holes using the following priority scheme: [bullet list as above]. Describe a database supporting the following operations, where k is the number of recorded but unpatched holes in the network at the time of the operation. State whether your running times are worst-case, expected, and/or amortized. initialize(H) / report(pi,di) / patch() [signatures as above].）

### 解答（Solution）

**核心思路（idea）：** 关键观察是优先级方案的第二条：它要求找出「同一根管道上、距离最接近的一对孔」。因此我们需要的核心数据结构是——对**每一根管道**，维护其孔按距离 $d$ 排序的有序集合，并动态维护**相邻孔之间的距离差**，以便快速找到全局最小的相邻距离差。这正是用 **augmented（增广）的平衡二叉搜索树**（每根管道一个）+ 一个**全局最小堆**（维护跨管道的最小相邻距离差）的组合。

**核心概念（definition）：**
- **AVL tree / balanced BST（平衡二叉搜索树）**：一种自平衡二叉搜索树，支持 insert / delete / find 等操作在 $O(\log m)$（m 为结点数）内完成，可增广存储子树信息。
- **min-heap（最小堆）**：一种支持「取最小键 O(1)、插入 / 删除 $O(\log m)$」的优先级队列，常配合「lazy deletion（懒删除）」维护跨结构的最小值。

**数据结构设计：**

1. **每个管道 $p$ 一棵平衡 BST（如 AVL 树）** $T_p$，按距离 $d$ 排序，存储该管道上当前所有未修补孔的距离。每棵 $T_p$ 增广维护「该管道内相邻孔距离差的最小值」$\delta_p$（即中序遍历相邻两结点距离差的最小者；若该管道孔数 < 2，则 $\delta_p = +\infty$，表示不存在可比的相邻对）。

2. **一个全局 min-heap** $Q$，堆中的元素是「每一根有 ≥ 2 个孔的管道的 $\delta_p$」，键为 $\delta_p$ 的值。堆顶即全局最小的相邻距离差。

**各操作的实现与复杂度：**

**initialize(H)：** 每根管道恰好一个孔，故为每根管道建立一棵只含一个结点的 BST（$O(1)$ 每根），共 n 根，总 $O(n)$。此时所有管道孔数 < 2，堆 Q 为空。

**report(p_i, d_i)：** 在管道 $p_i$ 的 BST $T_{p_i}$ 中插入距离 $d_i$（$O(\log k)$）。插入后需要更新该管道的 $\delta_{p_i}$：只需比较新插入结点与其**中序前驱、中序后继**的距离差（因为插入只会影响这两处相邻对），取与旧的 $\delta_{p_i}$ 的最小者。若该管道孔数从 1 变成 2，则把新的 $\delta_{p_i}$ 插入全局堆 Q；若从 ≥2 继续增长，则更新 Q 中对应项（用 lazy deletion 或「旧值懒删除 + 新值插入」）。总时间 $O(\log k)$。

**patch()：**
- 若堆 Q 为空 → 说明所有管道孔数 ≤ 1，走优先级第一条：任取一个仍有孔的管道，修补其任意一个孔（懒删除该孔），$O(\log k)$。
- 若堆 Q 非空 → 取堆顶（全局最小相邻距离差 $\delta$）对应的管道 p，该管道上有一对距离差为 $\delta$ 的相邻孔 $(d_a, d_b)$，修补其中一个（如 $d_a$）。修补后从 $T_p$ 中删除 $d_a$（$O(\log k)$），并重新计算 $T_p$ 的 $\delta_p$（删除后该孔的前驱、后继可能成为新的相邻对，需比较它们；若管道孔数降到 < 2 则 $\delta_p = +\infty$），同步更新堆 Q（懒删除旧键、插入新键）。总时间 $O(\log k)$。

**为什么正确（正确性论证）：**

- **invariant（结构不变量）：** 每根管道的 $T_p$ 始终按距离有序，且 $\delta_p$ 始终等于该管道内相邻孔距离差的最小值；全局堆 Q 的堆顶始终等于所有（孔数 ≥ 2 的）管道中 $\delta_p$ 的最小者，即「同一管道上距离最接近的一对孔」的距离差。
- **report 正确性（为什么只检查前驱后继）：** 在有序集合中插入新元素 x，只有 x 与其直接前驱、直接后继会形成新的相邻对，其余相邻对不变，故 $\delta_p$ 的更新只需检查这两处，不会漏掉任何可能的新最小距离差。
- **patch 正确性（为什么这样选符合优先级）：** 优先级方案要求——若存在「同一管道 ≥ 2 个孔」，就在这些管道中选相邻距离差最小的一对来修补。这正是「堆 Q 非空时取堆顶」的情形；当所有管道孔数 ≤ 1 时（堆 Q 为空），任意孔都可修，走第一条。故每一步都严格遵循题目优先级，正确。

**运行时间性质：** 所有操作都基于 AVL 树 / 堆的确定性 $O(\log k)$ 操作，不依赖随机性，故均为 **worst-case（最坏情况）$O(\log k)$**（initialize 为 $O(n)$）。同时自然也是 expected 与 amortized 的 $O(\log k)$。

**答案：** 「每管道一棵按距离排序的增广平衡 BST（维护本管道最小相邻差）+ 一个全局最小堆（维护跨管道最小相邻差）」，实现 initialize $O(n)$、report 与 patch 各 worst-case $O(\log k)$。

## 第 11 页 · Problem 9

### Problem 9. [20 points] Vapor Invite（蒸汽邀约）

Vapor 是一个有 n 名用户的在线游戏平台。每名用户有一个唯一的正整数 ID $d_i$，以及一个可更新的状态，状态为 active（活跃）或 inactive（非活跃）。每天，Vapor 会在线上发布一个 active range（活跃区间）：一对正整数 $(a, b)$，满足「ID 落在该区间内的每一位用户（即 $a \le d_i \le b$）都必须是活跃的」。Vapor 希望发布一个包含尽可能多活跃用户的活跃区间，并邀请他们参加一场特殊锦标赛。请描述一个数据库，支持以下 worst-case（最坏情况）操作：

- **build(D)**：用用户 ID 集合 $D = \{d_0, \dots, d_{n-1}\}$ 初始化数据库，初始将所有用户状态设为 active，在 $O(n \log n)$ 时间内完成。
- **toggle status(d_i)**：切换 ID 为 $d_i$ 的用户的活跃状态（active ↔ inactive），在 $O(\log n)$ 时间内完成。
- **big active range()**：返回一个包含尽可能多活跃用户的活跃区间 $(a, b)$，在 $O(1)$ 时间内完成。

（原文英文：Vapor is an online gaming platform with n users. Each user has a unique positive integer ID di and an updatable status, which can be either active or inactive. Every day, Vapor will post online an active range: a pair of positive integers (a, b) with the property that every user having an ID di contained in the range (i.e., with a ≤ di ≤ b) must be active. Vapor wants to post an active range containing as many active users as possible, and invite them to play in a special tournament. Describe a database supporting the following worst-case operations: build(D) / toggle status(di) / big active range() [signatures as above].）

### 解答（Solution）

**核心思路（idea）：** 活跃区间 $(a,b)$ 要求其内部**所有**用户都活跃，等价于「$(a,b)$ 内不能包含任何 inactive 用户」。因此，最大的活跃区间必然是**两个相邻 inactive 用户之间（或 inactive 用户与无穷端点之间）的那一段连续活跃用户**。于是问题转化为：动态维护「inactive 用户的集合」，并求「相邻 inactive 用户之间活跃用户数最多的那段」。

**核心概念（definition）：**
- **augmented balanced BST（增广平衡二叉搜索树）**：在每个结点额外存储子树聚合信息（如子树大小、子树内「最大连续活跃段」），支持在 $O(\log n)$ 内插入 / 删除并 $O(1)$ 读取全局聚合值。
- **max subarray（最大子段和）类增广**：在有序序列上维护「以某段为界的最大连续活跃用户数」，是线段树 / 平衡树上的经典增广技巧。

**数据结构设计：**

将所有用户按 ID 排序（ID 唯一），构成一个有序序列。用一个**增广平衡 BST（如 AVL 树）** $T$ 存储这一序列，每个结点对应一名用户并记录其状态（active / inactive）。每个结点额外增广维护如下字段（针对以该结点为根的子树，即 ID 的一个连续区间）：

- `size`：子树内用户总数；
- `prefix`：子树对应区间内「从最左端开始的最大连续活跃用户数」（prefix 最大活跃段）；
- `suffix`：子树对应区间内「到最右端为止的最大连续活跃用户数」（suffix 最大活跃段）；
- `best`：子树对应区间内「最大连续活跃用户数」（即该区间内最大的活跃段）；
- `allActive`：子树内用户是否全部活跃（布尔值）。

这四个增广量可在每个结点用「左孩子 + 自身 + 右孩子」的信息在 $O(1)$ 内合并（这就是 max subarray 问题的平衡树版本）。

**各操作的实现与复杂度：**

**build(D)：** 对 D 排序（$O(n \log n)$），建立一棵平衡 BST（可按中序线性建树 $O(n)$），并自底向上计算各结点的增广字段。总 $O(n \log n)$（排序主导）。

**toggle status(d_i)：** 在 T 中定位 ID 为 $d_i$ 的结点（$O(\log n)$），翻转其状态，然后沿「该结点到根」的路径自底向上重新计算每个祖先的增广字段（每条路径长 $O(\log n)$，每步合并 $O(1)$）。总 $O(\log n)$。

**big active range()：** 直接返回根结点的 `best` 字段对应的区间，即 $O(1)$。具体地，根结点维护的 `best` 就是全局最大活跃段；我们只需在根结点上同时记录「该 best 段对应的左右端点 ID」，即可 $O(1)$ 返回 $(a,b)$。

**为什么正确（正确性论证）：**

- **结构不变量：** 每个结点 u 的四个增广字段，恰等于以 u 为根的子树（ID 连续区间）内对应的真实值。归纳证明：叶子显然；内结点 u 的区间 = 左孩子区间 + {u} + 右孩子区间，而最大活跃段要么完全在左孩子（左.`best`）、要么完全在右孩子（右.`best`）、要么跨越 u（左.`suffix` + [u 若活跃] + 右.`prefix`），三者取最大即得 u.`best`。prefix / suffix 同理递推。故每个字段都正确。
- **活跃区间 ⇔ 无 inactive 用户：** 由定义，区间 $(a,b)$ 是合法活跃区间当且仅当其内所有用户都活跃，即不跨越任何 inactive 用户；因此最大活跃区间就是「被 inactive 用户切分出的各连续活跃段」中最大的一段，恰好等于根结点的 `best`。返回它即最优。
- **toggle 正确性：** 翻转单个状态只影响该结点及其祖先的增广字段，沿路径重算即可恢复不变量，其余结点不受影响。

**运行时间性质：** 全部为确定性算法，故为 worst-case（最坏情况）：build $O(n\log n)$、toggle $O(\log n)$、big active range $O(1)$。

**答案：** 用「按 ID 排序的增广平衡 BST，结点增广 prefix/suffix/best/allActive 四个字段（max subarray 技巧）」，实现 build $O(n\log n)$、toggle $O(\log n)$、big active range $O(1)$，全部 worst-case。
