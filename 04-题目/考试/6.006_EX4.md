### Algorithm: Sorting（算法：排序）

Reduce your problem to a problem you already know how to solve using known algorithms. You should know how each of these sorting algorithms are implemented, as well as be able to choose the right algorithm for a given task.
**把问题归约到某个你已会用已知算法求解的问题上。**你应当既知道下面每一种排序算法是如何实现的，又能针对给定任务选出正确的算法。

| Algorithm（算法） | Time $O(\cdot)$（时间） | In-place?（原地？） | Stable?（稳定？） | Comments（备注） |
|---|---|---|---|---|
| Insertion Sort（插入排序） | $n^2$ | Y | Y | $O(nk)$ for $k$-proximate（对 $k$ 邻近输入的复杂度为 $O(nk)$） |
| Selection Sort（选择排序） | $n^2$ | Y | N | $O(n)$ swaps（$O(n)$ 次交换） |
| Merge Sort（归并排序） | $n\log n$ | N | Y | stable, optimal comparison（稳定、比较排序最优） |
| AVL Sort（AVL 排序） | $n\log n$ | N | Y | good if also need dynamic（若还需动态操作则更佳） |
| Heap Sort（堆排序） | $n\log n$ | Y | N | low space, optimal comparison（低空间、比较排序最优） |
| Counting Sort（计数排序） | $n+u$ | N | Y | $O(n)$ when $u=O(n)$（当 $u=O(n)$ 时为 $O(n)$） |
| Radix Sort（基数排序） | $n+n\log_u n$ | N | Y | $O(n)$ when $u=O(n^c)$（当 $u=O(n^c)$ 时为 $O(n)$） |

**译注（关键概念定义）：**

- **Comparison sort**（比较排序）：仅通过比较元素之间的大小关系（`<`/`>`）来确定次序的排序算法，其最坏情况下界为 $\Omega(n\log n)$。
- **Stable sort**（稳定排序）：若两个元素的关键字相等，排序后它们保持输入中的相对先后顺序，则该排序是稳定的。
- **In-place sort**（原地排序）：除输入本身占用的空间外，仅使用常数（或对数）级额外空间的排序。
- **$u$** 是**universe size（值域大小）**，即键可能取值的总数；**$n$** 是待排序元素个数。
- **$k$-proximate**（$k$ 邻近）：输入中每个元素距其最终正确位置的偏移不超过 $k$，插入排序此时仅需 $O(nk)$。
- **Radix Sort** 的时间项 $n+n\log_u n$：当每个数字以基 $u$ 表示、共 $d=\log_u n$ 位时，总代价为 $n + n\log_u n$；当 $u=O(n^c)$（$c$ 为常数）时，$\log_u n = \frac{\log n}{\log u} = O(1)$，故整体为 $O(n)$。

### Data Structures（数据结构）

Reduce your problem to using a data structure storing a set of items, supporting certain search and dynamic operations efficiently. You should know how each of these data structures implement the operations they support, as well as be able to choose the right data structure for a given task.
**把问题归约到「使用一个存储元素集合（set of items）的数据结构」上**，该结构须高效支持某些查找与动态操作。你应当既知道每种数据结构如何实现其所支持的操作，又能针对给定任务选出正确的数据结构。

### Sequence data structures（序列数据结构）

Sequence data structures support **extrinsic** operations that maintain, query, and modify an **externally imposed order** on items.
**序列数据结构**支持的是**extrinsic（外赋）操作**——即维护、查询、修改**由外部强加的次序（externally imposed order）**的操作。

**表头说明：** Container 列为数据结构名；Static（静态操作）列含 `build(X)`、`get at(i)`、`set at(i,x)`；Dynamic（动态操作）列含 `insert first(x)`、`delete first()`、`insert last(x)`、`delete last()`、`insert at(i,x)`、`delete at(i)`。

| Data Structure（数据结构） | build(X) | get at(i) | set at(i,x) | insert first(x) | delete first() | insert last(x) | delete last() | insert at(i,x) | delete at(i) |
|---|---|---|---|---|---|---|---|---|---|
| Array（数组） | $n$ | $1$ | $1$ | $n$ | $n$ | $n$ | $n$ | $n$ | $n$ |
| Linked List（链表） | $n$ | $n$ | $n$ | $1$ | $1$ | $n$ | $n$ | $n$ | $n$ |
| Dynamic Array（动态数组） | $n$ | $1$ | $1$ | $n$ | $n$ | $1(a)$ | $1(a)$ | $n$ | $n$ |
| Sequence AVL（序列 AVL 树） | $n$ | $\log n$ | $\log n$ | $\log n$ | $\log n$ | $\log n$ | $\log n$ | $\log n$ | $\log n$ |

**译注：** 表中 `(a)` 表示 **amortized（均摊）**复杂度；无标记者均为**worst-case（最坏情况）**。例如 Dynamic Array 的 `insert last`/`delete last` 因扩容摊还而均摊为 $O(1)$，但单次最坏可达 $O(n)$。

**Sequence AVL（序列 AVL 树）定义：** 一种**平衡二叉搜索树（AVL tree，AVL 树）**，除按关键字外还维护 subtree size（子树大小），从而支持按**rank / index（位置）**在 $O(\log n)$ 内访问、插入、删除序列元素。

### Set data structures（集合数据结构）

Set data structures support **intrinsic** operations that maintain, query, and modify a set of items **based on what the items are**, i.e., based on the unique key associated with each item.
**集合数据结构**支持的是**intrinsic（内在）操作**——即依据「元素本身是什么」（也就是每个元素唯一关联的键 key）来维护、查询、修改集合的操作。

| Data Structure（数据结构） | build(X) | find(k) | insert(x) | delete(k) | find min() | find max() | find prev(k) | find next(k) |
|---|---|---|---|---|---|---|---|---|
| Array（数组） | $n$ | $n$ | $n$ | $n$ | $n$ | $n$ | $n$ | $n$ |
| Sorted Array（有序数组） | $n\log n$ | $\log n$ | $n$ | $n$ | $1$ | $1$ | $\log n$ | $\log n$ |
| Direct Access（直接寻址） | $u$ | $1$ | $1$ | $1$ | $u$ | $u$ | $u$ | $u$ |
| Hash Table（哈希表） | $n(e)$ | $1(e)$ | $1(a)(e)$ | $1(e)$ | $n$ | $n$ | $n$ | $n$ |
| Set AVL（集合 AVL 树） | $n\log n$ | $\log n$ | $\log n$ | $\log n$ | $\log n$ | $\log n$ | $\log n$ | $\log n$ |

**译注（复杂度记号约定）：**

- `(a)` = **amortized**（均摊）：一组操作的总代价摊到每个操作上后每个操作的界。
- `(e)` = **expected**（期望）：在随机化（如哈希函数随机）或概率假设下，代价的**期望值**界。
- 无记号 = **worst-case**（最坏情况）。

**关键概念定义：**

- **Hash table**（哈希表）：通过哈希函数把键映射到桶、支持**期望 $O(1)$** 的 `find/insert/delete` 的数据结构（假设哈希函数把键均匀散列）。
- **Direct Access**（直接寻址表）：用一个大数组以键值本身为下标直接索引，值域 $u$ 不大时每次操作 $O(1)$，但 `build` 与 `find min/max` 需扫描整个值域，故为 $O(u)$。
- **Set AVL**（集合 AVL 树）：**平衡二叉搜索树（binary search tree，BST）**的一种，每个节点维护子树高度平衡（左右子树高度差 ≤ 1），使 `find/insert/delete/find prev/next/min/max` 均为 $O(\log n)$。

### Priority Queues（优先队列）

Priority Queues support a limited number of Set operations.
**priority queue（优先队列）**仅支持一部分集合操作。

| Data Structure（数据结构） | build(X) | insert(x) | delete max() | find max() |
|---|---|---|---|---|
| Dynamic Array（动态数组） | $n$ | $1(a)$ | $n$ | $n$ |
| Sorted Dyn. Array（有序动态数组） | $n\log n$ | $n$ | $1(a)$ | $1$ |
| Set AVL（集合 AVL 树） | $n\log n$ | $\log n$ | $\log n$ | $\log n$ |
| Binary Heap（二叉堆） | $n$ | $\log n(a)$ | $\log n(a)$ | $1$ |

**关键概念定义：**

- **Priority queue**（优先队列）：支持「插入元素」「取出并删除最大（或最小）关键字元素」的抽象数据类型（ADT）。
- **Binary heap**（二叉堆）：一种**完全二叉树**结构，满足**heap property（堆性质）**（父节点关键字 ≥ 子节点，即最大堆），支持 `insert`、`delete max` 在 $O(\log n)$ 内完成、`find max` 在 $O(1)$ 内完成。

**译注：** 表中 `delete max()` 对应「取出并删除最大关键字元素」；Dynamic Array 实现下 `insert` 摊还 $O(1)$ 是因为直接追加到数组尾部（add to back），但 `delete max` 需线性扫描找最大值故为 $O(n)$。Binary Heap 的 `insert`/`delete max` 单次最坏为 $O(\log n)$，标 `(a)` 表示同时也可按均摊意义理解为 $O(\log n)$。

### Problem 1. Restaurant Lineup（餐厅排队，S19 Q1）

Popular restaurant *Criminal Seafood* does not take reservations, but maintains a wait list where customers who have been on the wait list longer are seated earlier. Sometimes customers decide to eat somewhere else, so the restaurant must remove them from the wait list. Assume each customer has a different name, and no two customers are added to the wait list at the exact same time.
**热门餐厅「Criminal Seafood（犯罪海鲜）」不接受预订，但维护一份候位名单（wait list）：在名单上待得越久的顾客越早入座。有时顾客决定去别处用餐，餐厅须把他们从候位名单中移除。假设每位顾客姓名各不相同，且任意两位顾客都不会在同一时刻被加入候位名单。**

Design a database to help Criminal Seafood maintain its wait list supporting the following operations, each in $O(1)$ time. State whether each operation running time is worst-case, amortized, and/or expected.
**设计一个数据库，帮助该餐厅维护候位名单，支持下列操作，且每个操作均为 $O(1)$ 时间。请说明每个操作的运行时间是「worst-case（最坏情况）」「amortized（均摊）」还是「expected（期望）」。**

- `build()` —— initialize an empty database
  初始化一个空数据库。
- `add name(x)` —— add name x to the back of the wait list
  把姓名 x 加到候位名单**末尾（back）**。
- `remove name(x)` —— remove name x from the wait list
  把姓名 x 从候位名单中**移除**。
- `seat()` —— remove and return the name of the customer from the front of the wait list
  移除并返回候位名单**队首（front）**顾客的姓名。

**解（完整答案链）：**

**Idea（本质）：** 候位名单是一个「先进先出」的**queue（队列）**——队首是最早加入者、优先入座；队尾是最近加入者。核心难点在于 `remove name(x)` 要从**中间任意位置**删除，而普通队列/数组不支持 $O(1)$ 的中间删除。解法是**doubly linked list（双向链表）+ hash table（哈希表）**结合：链表维护「加入顺序」这一外赋次序，哈希表实现「由姓名 → 链表节点指针」的 $O(1)$ 定位，从而把中间的删除也降到 $O(1)$。

**数据结构与 invariants（不变量）：**

1. **双向链表 $L$**：按加入时间先后顺序存储所有在候位名单中的顾客姓名；`L.head` 指向队首（最早加入），`L.tail` 指向队尾（最近加入）。**不变量**：$L$ 中元素的顺序恰好等于「加入时间从早到晚」的顺序。
2. **哈希表 $H$**：`H.find(x)` 返回姓名 x 在链表 $L$ 中对应节点指针。**不变量**：$x$ 在候位名单中当且仅当 $H$ 中存在键 x；且该键的值指向 $L$ 中那个确切的节点。

**伪代码（pseudocode）：**

```math
\begin{aligned}
&\textbf{build}():\\
&\qquad L \leftarrow \text{empty doubly linked list}\\
&\qquad H \leftarrow \text{empty hash table}\\[6pt]
&\textbf{add name}(x):\\
&\qquad v \leftarrow \text{new node storing } x\\
&\qquad L.\text{insert last}(v)\\
&\qquad H.\text{insert}(\text{key}=x,\ \text{value}=v)\\[6pt]
&\textbf{remove name}(x):\\
&\qquad v \leftarrow H.\text{find}(x)\\
&\qquad L.\text{delete}(v)\\
&\qquad H.\text{delete}(x)\\[6pt]
&\textbf{seat}():\\
&\qquad v \leftarrow L.\text{head}\\
&\qquad L.\text{delete first}()\\
&\qquad H.\text{delete}(v.\text{key})\\
&\qquad \textbf{return}\ v.\text{key}
\end{aligned}
```

**复杂度分析：**

- `build()`：初始化空链表与空哈希表，$O(1)$。
- `add name(x)`：链表 `insert last` 与哈希 `insert` 各为常数时间，故 $O(1)$ **amortized（均摊）与 expected（期望）**（哈希插入的期望界；链表尾插为最坏 $O(1)$）。
- `remove name(x)`：哈希 `find` 期望 $O(1)$ 定位节点，链表 `delete` 在双向链表中为最坏 $O(1)$（有前后指针即可重连），故整体 $O(1)$ **expected（期望）**。
- `seat()`：取 `L.head` 并 `delete first` 为最坏 $O(1)$，哈希删除为期望 $O(1)$，故整体 $O(1)$ **worst-case（最坏）**（链表操作）叠加**expected（期望）**（哈希删除）。

**正确性论证（循环不变式 / 归纳）：**

- **不变式 $I$**：在任意一次操作完成后，(1) $L$ 中所有节点按加入时间从早到晚排列，队首为最早加入者；(2) 对每个在名单中的姓名 $x$，$H[x]$ 精确指向它在 $L$ 中的节点。
  - **初始**：`build()` 后链表与哈希表皆空，$I$ 平凡成立。
  - **保持**：`add` 把新节点接到队尾（保持时间序），并在 $H$ 登记指针；`remove` 先经 $H$ 定位节点，再用双向链表的前后指针 $O(1)$ 摘除该节点并删除 $H$ 项，均保持 $I$；`seat` 摘除队首并删除 $H$ 对应项，同样保持 $I$。
  - **终止**：因为 $I$ 在每一步都保持，故 `seat()` 返回的始终是最早加入且仍在名单中的顾客，满足「待得越久越早入座」的要求。

### Problem 2. Rainy Research（降雨研究，S19 Q1）

Mether Wan is a scientist who studies global rainfall. Mether often receives data measurements from a large set of deployed sensors. Each collected data measurement is a triple of integers $(r, \ell, t)$, where $r$ is a positive amount of rainfall measured at latitude $\ell$ at time $t$. The peak rainfall at latitude $\ell$ since time $t$ is the maximum rainfall of any measurement at latitude $\ell$ measured at a time greater than or equal to $t$ (or zero if no such measurement exists). Describe a database that can store Mether's sensor data and support the following operations, each in worst-case $O(\log n)$ time where $n$ is the number of measurements in the database at the time of the operation.
**Mether Wan 是一位研究全球降雨的科学家，经常从一个大规模部署的传感器集合接收测量数据。每条测量数据是一个整数三元组 $(r, \ell, t)$，其中 $r$ 是在纬度（latitude）$\ell$、时刻（time）$t$ 测得的**正**降雨量。**「纬度 $\ell$ 自时刻 $t$ 起的峰值降雨量（peak rainfall）」**定义为：在纬度 $\ell$ 上、测量时刻大于等于 $t$ 的所有测量中降雨量的最大值（若不存在这样的测量则为 0）。**请描述一个数据库**，能存储 Mether 的传感器数据并支持下列操作，每个操作在最坏情况下均为 $O(\log n)$ 时间，其中 $n$ 是操作发生时数据库中的测量条数。**

- `build()` —— initialize an empty database
  初始化一个空数据库。
- `record data(r, ℓ, t)` —— add a rainfall measurement r at latitude ℓ at time t
  添加一条「在纬度 $\ell$、时刻 $t$ 的降雨量 $r$」的测量。
- `peak rainfall(ℓ, t)` —— return the peak rainfall at latitude ℓ since time t
  返回纬度 $\ell$ 自时刻 $t$ 起的峰值降雨量。

**解（完整答案链）：**

**Idea（本质）：** 查询是在**固定纬度 $\ell$** 上、对**时刻维度做后缀最大值**（suffix maximum over time）——即「时刻 ≥ t 的所有测量中的最大 $r$」。这正是一个**按纬度分桶、桶内按时间维护的集合 + 前缀/后缀最大值**问题。解法是**哈希表（按纬度分桶）+ 每桶一棵按时间排序的平衡二叉搜索树（AVL 树）**，其中每个节点额外**augment（扩充）**一个「子树内降雨量的最大值」字段，使 `peak rainfall` 可通过对时刻的后缀区间在 $O(\log n)$ 内求最大值。

**数据结构与不变量：**

1. **哈希表 $H$**：键为纬度 $\ell$，值为指向该纬度对应平衡 BST 根节点的指针。**不变量**：$H$ 中恰有一个键对应每个「已出现测量」的纬度。
2. **每桶一棵 AVL 树 $T_\ell$**：以时间 $t$ 为键、按时间升序组织该纬度 $\ell$ 的所有测量；每个节点存储三元组 $(r, \ell, t)$，并**扩充**一个字段 `max`，表示「以该节点为根的子树内所有测量中 $r$ 的最大值」。**不变量**：`node.max = max(node.r, node.left.max, node.right.max)`。

**伪代码（pseudocode）：**

```math
\begin{aligned}
&\textbf{build}():\\
&\qquad H \leftarrow \text{empty hash table}\\[6pt]
&\textbf{record data}(r, \ell, t):\\
&\qquad T \leftarrow H.\text{find}(\ell)\ \ (\text{若不存在则新建空 AVL 树并登记到 } H)\\
&\qquad v \leftarrow \text{新节点，存 } (r,\ell,t)\\
&\qquad T.\text{insert}(v,\ \text{key}=t)\\
&\qquad \text{沿插入路径自底向上重算各节点 } .max\\[6pt]
&\textbf{peak rainfall}(\ell, t):\\
&\qquad T \leftarrow H.\text{find}(\ell)\ \ (\text{若不存在则返回 } 0)\\
&\qquad \text{求 } T \text{ 中所有键 } \ge t \text{ 的节点集合的 } r \text{ 最大值}\\
&\qquad \textbf{return}\ \text{该最大值（若无节点则返回 } 0）
\end{aligned}
```

其中「求键 $\ge t$ 的节点集合的最大 $r$」用一次**基于 `max` 字段的区间（后缀）查询**完成：从根出发，若当前子树的最小键仍 $< t$ 则需下探细分，否则直接用子树的 `max`；整个过程只访问 $O(\log n)$ 个节点。

**复杂度分析：**

- `build()`：初始化空哈希表，$O(1)$。
- `record data(r, ℓ, t)`：哈希 `find` 期望 $O(1)$；AVL 树 `insert` 最坏 $O(\log n)$（AVL 保持平衡，树高为 $O(\log n)$）；插入后自底向上重算 `max` 也只沿插入路径 $O(\log n)$ 个节点。故最坏 $O(\log n)$。
- `peak rainfall(ℓ, t)`：定位桶 $O(1)$（期望），后缀区间查询访问 $O(\log n)$ 个节点（每个节点 $O(1)$ 合并 `max`）。故最坏 $O(\log n)$。

> **为什么是 $O(\log n)$ 而非 $O(1)$：** 关键在 `peak rainfall` 必须对「时刻 ≥ t」的**后缀**求最大值，而时间是动态插入的任意整数，无法用数组下标直接寻址；用平衡 BST 以时间排序后，树高 $O(\log n)$，一次后缀最大值查询只需沿树访问 $O(\log n)$ 个节点，每个节点 $O(1)$，故总代价 $O(\log n)$，满足题目要求。

**正确性论证（循环不变式 / 归纳）：**

- **不变式 $J$**：任意时刻，对每个纬度 $\ell$，$T_\ell$ 是一棵按时间 $t$ 有序的 AVL 树，且每个节点 `.max` 精确等于其子树内所有测量的最大 $r$。
  - **初始**：`build()` 后 $H$ 为空，$J$ 平凡成立。
  - **保持（`record data`）**：AVL 插入后通过旋转恢复平衡，树仍按时间有序；沿插入路径自底向上按 `node.max = max(node.r, node.left.max, node.right.max)` 重算，恰是**子树最大值**的正确归纳式——由「左右子树 `.max` 已正确」推出「父节点 `.max` 正确」，故 $J$ 保持。
  - **保持（`peak rainfall`）**：后缀查询把「键 ≥ t」的集合 $S$ 表示为 $O(\log n)$ 个互不相交子树的并，对每个子树直接用其根 `.max` 得到该子树内最大 $r$，再取这些值的最大值，即 $S$ 内的最大 $r$。由 $J$ 中 `.max` 的正确性，返回值恰为「纬度 $\ell$、时刻 ≥ t 的最大降雨量」，无测量时返回 0，满足定义。
  - **终止**：$J$ 在每次操作后均保持，故每次查询结果正确。
