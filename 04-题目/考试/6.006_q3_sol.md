## 第 3 页：动态规划通用评分要求 + Problem 2

### 通用要求（针对 Problem 3、4、5）

Please solve problems (3), (4), and (5) using dynamic programming. Be sure to define a set of subproblems, relate the subproblems recursively, argue the relation is acyclic, provide base cases, construct a solution from the subproblems, and analyze running time. Correct but inefficient dynamic programs will be awarded significant partial credit.
→ 请用 dynamic programming（动态规划）求解 Problem (3)、(4)、(5)。务必：**定义**一组 subproblems（子问题）；把子问题之间的**递归关系**写出来；论证该关系是 **acyclic（无环）** 的；给出 **base cases（基本情况）**；由子问题的解**构造**原问题的解；并分析 **running time（运行时间）**。正确但低效的动态规划会获得**可观的部分分数**。

> **译注（这就是本题的答题模板）**：这六条把 DP 题的评分点写死了——① subproblems（子问题）② relate（递推）③ topo（无环性）④ base ⑤ original（由子问题构造原解）⑥ time。下面 Problem 3 的官方解答**逐条对应**这六步，连小标题都一字不差（1. Subproblems / 2. Relate / 3. Topo / 4. Base / 5. Original / 6. Time）。凡是要拿满分的 DP 题，都按这个骨架写。
>
> 三个必给的术语定义：
> - **dynamic programming（动态规划）**：把原问题拆成一族**互相重叠**的子问题，按子问题依赖图的拓扑序自底向上（或记忆化自顶向下）求解，使每个子问题**只算一次**的方法。可判定特征：存在一个「子问题 ↔ 状态下标」的映射，且状态间的依赖关系无环。
> - **subproblem（子问题）**：原问题的一个参数化副本，参数取自一个规模受控的下标集合；本卷里子问题就是「后缀 $T[i:]$ 上的最优值」$x(i)$。
> - **DAG（directed acyclic graph，有向无环图）**：有向且不含任何有向环的图。可判定特征：存在 vertex（顶点）的一个线性排列（即 topological order），使每条边都从序小的顶点指向序大的顶点。**一个递推能当 DP 用，判据就是「子问题依赖图是 DAG（有向无环图）」**——本题里 $x(i)$ 只依赖下标更大的 $x(i')$，天然满足。

### Problem 2. [3 points] Pseudo-Circling

#### 题目

**Problem 2. [3 points] Pseudo-Circling（伪多项式圈选）**

Indicate whether the given running times of each of problems (3), (4), and (5) are polynomial or pseudopolynomial by circling the appropriate word below. One can answer this question without actually solving problems (3), (4), and (5). (1 point each)
→ 请圈出下面合适的词，指明 problem (3)、(4)、(5) 各自给出的运行时间是 polynomial（多项式的）还是 pseudopolynomial（伪多项式的）。**不做** problem (3)、(4)、(5) 也能回答本题。（每小题 1 分）

**(a) Problem 3: Number Scrabble**
Polynomial　　Pseudopolynomial

**(b) Problem 4: Limited-Unlimited**
Polynomial　　Pseudopolynomial

**(c) Problem 5: Office Hour Optimization**
Polynomial　　Pseudopolynomial

#### 解答

**Solution (a)**：**Polynomial**（圈 Polynomial）

> **理由（一句）**：Problem 3 的算法是**期望** $O(n+m)$——时间只取决于数组长度 $n$ 与词典条目数 $m$ 这两个**规模**，而与数组里整数 $t_i$、单词价值 $v(p_i)$ 的**数值大小**完全无关（单词长度上界 10 是常数）。

**Solution (b)**：**Pseudopolynomial**（圈 Pseudopolynomial）

> **理由（一句）**：Problem 4（Limited-Unlimited）的运行时间表达式中，输入里某个整数是**以数值本身**（而不是以它的二进制位长 $\log V$）进入循环次数的——形如 $O(n\cdot V)$（本题就是 $O(n\cdot m)$，$m$ 是目标和）的「容量 / 目标值维度」展开，故对**输入规模**（bit 数）而言不是多项式，而是 pseudopolynomial（伪多项式）。

**Solution (c)**：**Polynomial**（圈 Polynomial）

> **理由（一句）**：Problem 5（Office Hour Optimization，答疑时间最优化）的状态是 $x(i,j,k)$——三个下标分别是分到房间 $a$、$b$、$c$ 的**人数**，第 $i+j+k$ 个学生也由这三个数隐含确定；循环次数只由学生人数 $n$ 决定，benefit（收益）$a_i,b_i,c_i$ 的**数值大小**从不进入任何下标范围，因此是 polynomial（多项式）。

> **译注（为什么"不做题也能答"）**：判据只有一条——
> 设输入的编码长度为 $L$ bit。若算法时间是 $O(L^k)$（$k$ 为常数），叫 **polynomial（多项式时间）**；若时间是 $O(\mathrm{poly}(N,\,V))$，其中 $N$ 是元素个数、而 $V$ 是输入中某个整数的**数值**（而 $V$ 的二进制编码只有 $\log_2 V$ 位），叫 **pseudopolynomial（伪多项式时间）**。
> 口诀：**把输入里所有整数换写成二进制位长，时间仍是多项式 → polynomial；时间随数值线性膨胀 → pseudopolynomial。**
> 这也正是 Problem 3 与 Problem 4 的分水岭：Number Scrabble 里单词长度被硬性限死在 $\le 10$，**数值不进循环**；而 "Limited-Unlimited" 这个题名本身就提示了 bounded/unbounded 的**容量维度**，容量是数值，一进循环就是伪多项式。
> 落到本文三份递推上看（Problem 3、4、5 的递推都在第 4–6 页完整译出）：Problem 3 的状态只有后缀起点 $x(i)$、Problem 5 的状态是三个**人数** $x(i,j,k)$，下标范围全由 $n$（或 $n^3$）决定，与 $t_i$、$a_i$ 的数值无关；只有 Problem 4 的状态 $x_A(i,k)$、$x_B(i,k)$ 带一个 $k \in \{0, \ldots, m\}$，而 $m$ 是**目标和**（数值本身），所以三者之中只有它是 pseudopolynomial（伪多项式）。

## 第 4 页：Problem 3. Number Scrabble [17 points]

### 题目

**Problem 3. [17 points] Number Scrabble（数字拼字）**

Number Scrabble is a one-player game played on an array $T = [t_0, \ldots, t_{n-1}]$ of $n$ positive integers.
→ Number Scrabble 是一个**单人**游戏，在一个由 $n$ 个正整数构成的数组 $T = [t_0, \ldots, t_{n-1}]$ 上进行。

There is a list $P = \{(p_0, v(p_0)), \ldots, (p_{m-1}, v(p_{m-1}))\}$ of $m$ unique playable words, where playable word $p_i$ is a non-empty array of at most 10 positive integers and $v(p_i)$ is the positive integer value of $p_i$.
→ 另有一个列表 $P = \{(p_0, v(p_0)), \ldots, (p_{m-1}, v(p_{m-1}))\}$，含 $m$ 个**互不相同**的 playable word（可玩单词）；其中 playable word（可玩单词）$p_i$ 是一个**非空**、长度**至多 10** 的正整数数组，$v(p_i)$ 是 $p_i$ 的（正）整数价值。

The objective of the game is to find a gameplay $S$ — a list of non-overlapping subarrays (i.e., substrings) of $T$, each a playable word — where $S$ has maximum total value, $\sum_{s \in S} v(s)$.
→ 游戏目标是找出一个 gameplay（一局玩法）$S$ —— 它是 $T$ 的一串**互不重叠**的 subarrays（子数组，即 substrings 子串），每一个都必须是 playable word（可玩单词）—— 使得 $S$ 的**总价值** $\sum_{s \in S} v(s)$ 最大。

For example, if
$T = [1, 5, 2, 4, 1]$ and $P = \{([2], 3),\ ([1], 1),\ ([5, 2], 8),\ ([1, 2], 12),\ ([1, 5], 2)\}$,
then $S_1 = ([1, 5],\, [2],\, [1])$, $S_2 = ([1],\, [5, 2],\, [1])$, and $S_3 = ([1],\, [2],\, [1])$ are all valid gameplays, with total values 6, 10, and 5 respectively. Note playable word $[1, 2]$ cannot exist in any gameplay of $T$, since $[1, 2]$ is not a contiguous subarray of $T$.
→ 例如，若 $T = [1, 5, 2, 4, 1]$，$P = \{([2], 3),\ ([1], 1),\ ([5, 2], 8),\ ([1, 2], 12),\ ([1, 5], 2)\}$，则 $S_1 = ([1, 5],\, [2],\, [1])$、$S_2 = ([1],\, [5, 2],\, [1])$、$S_3 = ([1],\, [2],\, [1])$ 都是合法的 gameplay（一局玩法），总价值分别为 6、10、5。注意：playable word（可玩单词）$[1, 2]$ **不可能**出现在 $T$ 的任何 gameplay（一局玩法）里，因为 $[1, 2]$ 不是 $T$ 的 contiguous subarray（连续子数组）。

Given $T$ and $P$, describe an $O(n+m)$-time algorithm to return a gameplay of maximum total value.
→ 给定 $T$ 与 $P$，请描述一个 $O(n+m)$ 时间的算法，返回一个总价值最大的 gameplay（一局玩法）。

> **译注（题面的三处易错点，直接决定算法形态）**
> 1. **"non-overlapping" 但允许留空**：gameplay（一局玩法）只要求各 playable word（可玩单词）互不重叠，**不要求铺满** $T$——例中 $S_3 = ([1],[2],[1])$ 就跳过了 $t_3 = 4$。所以「每个位置选或不选」是合法选项，跳过是免费动作，这也是递推里 $x(i+1)$ 那一项的来源。
> 2. **长度上界 10 是常数**：这是 $O(n+m)$ 成立的根本原因。若单词长度无界，枚举所有长度就退化成 $O(n^2)$ 次查询；正因 $\le 10$，每个位置的候选只有 $10$ 个，是**常数个**。
> 3. **$[1,2]\in P$ 却用不上**：单词必须匹配 $T$ 的**连续**片段。这提示「判断一个片段是不是单词」这件事必须**按内容查表**（而不是按 $P$ 里位置），因为 $P$ 是集合、与 $T$ 的坐标无关。

### 解答（官方 Solution 全文译注）

#### 0. idea（一句话本质）

**把「在 $T$ 上切出若干互不重叠、且都在词典 $P$ 中的子串、使总价值最大」看成后缀上的最优化切分**：位置 $i$ 只有两种命运——要么 $t_i$ 不属于任何 playable word（可玩单词），即被跳过（问题缩到 $T[i+1:]$），要么 $t_i$ 是某个长度 $j \le 10$ 的 playable word（可玩单词）的**开头**（吃掉 $T[i:i+j]$，问题缩到 $T[i+j:]$）。两种命运的后果只由**一个下标 $i$** 决定，且右侧剩余部分是**同型子问题**——这就是 optimal substructure（最优子结构），于是 $x(i)$ 一个下标就能刻画全部状态。

#### 1. 预处理：把「这段子数组是不是一个 playable word（可玩单词）」压成期望 $O(1)$ 查询

> **原文**：To solve this problem, it would be useful to be able to check whether a particular array of at most 10 positive integers is a playable word. Construct an empty hash table $D$ and insert each $p_i$ for $i \in \{0, \ldots, m-1\}$ into $D$, mapping to its value $v(p_i)$. Each hash table insertion takes expected constant time (as each $p_i$ has constant size), so constructing $D$ takes expected $O(m)$ time.
> → 为了解题，最好能**判定**「某个长度至多 10 的正整数数组是不是一个 playable word（可玩单词）」。建一个空的 hash table（哈希表）$D$，把每个 $p_i$（$i \in \{0, \ldots, m-1\}$）插入 $D$，并映射到它的价值 $v(p_i)$。每次插入是**期望常数时间**（因为每个 $p_i$ 的规模是常数），所以建 $D$ 花期望 $O(m)$ 时间。

**为什么必须建表**：DP 每一步都要问「$T[i:i+j]$ 在不在 $P$ 里、价值多少」。若线性扫描 $P$（$m$ 条），每个位置 $10$ 次查询、每次 $O(m)$，总时间变成 $O(n m)$，直接违背 $O(n+m)$ 的要求。hash table（哈希表）把这个查询降到期望 $O(1)$，$m$ 就只以**建表**的代价出现一次，这就是「$+m$」而不是「$\times m$」的原因。

> **术语定义**：**hash table（哈希表）**：一种用 hash function（哈希函数）把 key 映射到 bucket（桶）下标的字典结构；支持 insert / search / delete，**期望** $O(1)$、**最坏** $O(n)$（所有 key 撞到同一桶时）。本题的 key 是「长度 $\le 10$ 的整数数组」，其 size（规模）是常数，故「把 key 哈希一遍」本身也是 $O(1)$——这一点是后面复杂度里 $O(m)$ 而非 $O(10m)$ 的来源。

#### 2. Subproblems（定义子问题）

> **原文**：$x(i)$: the maximum total value of any gameplay on suffix $T[i:]$ for $i \in \{0, \ldots, n\}$
> → $x(i)$：后缀 $T[i:]$ 上**任意** gameplay（一局玩法）的最大总价值，$i \in \{0, \ldots, n\}$。

**为什么用 suffix（后缀）而不是前缀、也不是区间**：playable word（可玩单词）是**连续**片段且**互不重叠**，解题是从左往右"下刀"。一旦确定了「覆盖 $t_i$ 的那一段是 $T[i:i+j]$」，$i$ 左边的一切已经与右边**无关**（不重叠保证左边不会再伸过来），右侧 $T[i+j:]$ 就是一个**完全同型**的问题。所以状态只需「剩余后缀的起点 $i$」一个参数；若允许重叠，状态就得扩成二维区间，那才是真正的失分点。

子问题个数：$i$ 取 $0,1,\ldots,n$ 共 $n+1$ 个（$i=n$ 是空后缀，必须留着当边界）。

#### 3. Relate（写递推关系）

> **原文**：Left-most playable word either starts with $t_i$ or it does not — if playable word starts with $t_i$, word may have any length in $\{1, \ldots, 10\}$ (Guess!)
> → **最左边**的那个 playable word（可玩单词），要么以 $t_i$ 开头，要么不以 $t_i$ 开头。若以 $t_i$ 开头，它的长度可以是 $\{1, \ldots, 10\}$ 中**任意**一个（此即 Guess，猜一步）。

> **原文**：$j \in \{0, \ldots, 10\}$ and $i+j \le n$ and $T[i:i+j] \in D$
> → 条件：$j \in \{0, \ldots, 10\}$，且 $i+j \le n$，且 $T[i:i+j] \in D$（即该片段确实在词典中）。

> **原文**：
> $x(i) = \max\left(\{x(i+1)\} \cup \{D[T[i:i+j]] + x(i+j)\}\right)$，满足 $T[i:i+j] \in D$、$i+j \le n$、$j \in \{0,\ldots,10\}$。
> → 把「跳过」与「以 $t_i$ 开头取长度 $j$ 的 playable word（可玩单词）」两类候选并成一个集合，取最大值。

**重建后的完整递推式**（这是本页最关键的重建）：

```math
x(i) \;=\; \max\Bigl(\ \{\, x(i+1) \,\}\ \cup\ \{\, D[\,T[i:i+j]\,] + x(i+j)\ \mid\ 1 \le j \le 10,\ \ i+j \le n,\ \ T[i:i+j] \in D \,\}\ \Bigr)
```

四个条件各自的作用，缺一不可：

- $j \ge 1$：playable word（可玩单词）**非空**（题目明文规定 non-empty），$j=0$ 是空数组，不是合法 playable word（可玩单词）；
- $j \le 10$：playable word（可玩单词）长度的常数上界，也是本算法 $O(n+m)$ 的命门；
- $i+j \le n$：不许越界，$T[i:i+j]$ 必须**完整**落在数组内；
- $T[i:i+j] \in D$：内容必须是词典里的词（注意是**按内容**判定，与 $P$ 的存储顺序无关）。

> **译注（PDF 碎片重建说明，对照硬性契约）**：原文这一行在文字层被打散成三块——左侧 `x(i) = max {x(i + 1)} ∪ ...`、中间一个孤立的 `j ∈ {0, . . . , 10}`、下方 `T [i : i + j] ∈ D`；再加上一个被拆成大括号私有码位的「分情况大括号」。按数学意义，这些碎片**只能**拼成上面那一条带 side condition（旁置条件）的 max 递推式，没有第二种可能：因为 `max{...} ∪ {...}` 的第二个集合必须由 `D[T[i:i+j]] + x(i+j)` 生成，而它的合法性正由上列三个条件（$j$ 范围、$i+j\le n$、在 $D$ 中）共同约束。
>
> **关于上界集写成 $\{0, \ldots, 10\}$**：原式写的是 $j \in \{0, \ldots, 10\}$，而把 $j=0$ 代进去得到 $T[i:i]$，这是**空数组**，而题目明确要求 playable word（可玩单词）非空，故 $j=0$ 这一项在条件 $T[i:i+j]\in D$ 下**恒不成立**（$D$ 里没有任何空 key），被条件自动筛掉。因此取 $j \in \{1,\ldots,10\}$ 与原式**严格等价**，写 $\{1,\ldots,10\}$ 只是把无效项显式删掉。
>
> **端点自检（契约要求的边界验证）**：取 $i=n$，则任何 $j \ge 1$ 都使 $i+j > n$，第二集合为空，递推退化为 $x(n) = \max\{x(n+1)\}$——这就不对了。**所以 $i=n$ 必须由 base case（基本情况）单独钉死为 $x(n)=0$，不能走递推**。这一处正是"代入端点验证两段衔接"发现的：递推式的定义域是 $i \in \{0,\ldots,n-1\}$，$i=n$ 交给 base。

#### 4. Topo（论证无环，即递推可以按序求值）

> **原文**：$x(i)$ only depends on subproblems with strictly larger $i$, so acyclic
> → $x(i)$ 只依赖于下标**严格更大**的子问题，因此无环。

**为什么这就够了**：把每个 $x(i)$ 看作顶点，把「$x(i)$ 依赖 $x(i')$」画成有向边 $x(i') \to x(i)$（依赖者指向被依赖者，$i' > i$），则每条边都从**大**下标指向**小**下标。于是「按 $i$ 从 $n$ 递减到 $0$ 的顺序计算」正好是该依赖图的一个 topological order（拓扑序）——排在前面（下标大）的顶点先算，计算 $x(i)$ 时它需要的所有 $x(i')$ 都已算完。因为存在这样的线性序，图中**不可能有有向环**（沿环走下标会严格递增又回到自身，矛盾）。

#### 5. Base（基本情况）

> **原文**：$x(n) = 0$ (empty gameplay admits no value)
> → $x(n) = 0$：空的 gameplay（一局玩法）不含任何价值。

**为什么是 0**：$T[n:]$ 是空数组，空数组上唯一合法的 gameplay（一局玩法）是空列表——空和的值为 0；又因为每个 playable word（可玩单词）长度 $\ge 1$，任何 playable word（可玩单词）都放不进空数组，所以最大值确实就是 0，不是 $-\infty$。（若把「跳过」也视作损失，才需要 $-\infty$；本题跳过免费，故为 0。）

#### 6. Original（由子问题的解构造原问题的解）

> **原文**：Solve subproblems via recursive top down or iterative bottom up; $x(0)$ is the maximum value of any gameplay on $T$; Store parent pointers to reconstruct an optimal gameplay.
> → 用**递归自顶向下**（top down）或**迭代自底向上**（bottom up）求解子问题；$x(0)$ 就是 $T$ 上任意 gameplay（一局玩法）的最大价值；另存 **parent pointers（父指针）** 以**重建**一个最优 gameplay（一局玩法）。

**为什么答案是 $x(0)$**：$T = T[0:]$，正是整个数组，故 $x(0)$ 即所求最大总价值。**为什么必须存 parent**：DP 只算出「最大值是多少」，没记住「怎么达到」；要在 $O(n)$ 内吐出方案，就得在每个位置记下**当时选的是哪个后继下标**（取词则记 $i+j$，跳过则记 $i+1$），再从 $0$ 顺着指针走一趟。

#### 7. Time（复杂度）

> **原文**：# subproblems: $n+1 = O(n)$；Work per subproblem: expected $O(1)$；Together with hash table construction, yields expected $O(n+m)$ time。
> → 子问题数 $n+1 = O(n)$；每个子问题的工作量期望 $O(1)$；加上建 hash table（哈希表），总时间**期望** $O(n+m)$。

**"每子问题 $O(1)$" 的账要算清**：每个 $x(i)$ 有 $1$ 个跳过候选 + 至多 $10$ 个取词候选；每个取词候选 = 一次 hash 查询（期望 $O(1)$）+ 一次加法 + 一次比较与赋值（均 $O(1)$）。常数 $11$ 不进渐近，故为 $\Theta(1)$。

### 完整答案链（补充：伪代码 + 正确性 + 递推式求解 + 样例验证）

#### 8. Pseudocode（伪代码，LaTeX 版）

```math
\begin{array}{ll}
\textbf{proc} & \text{NumberScrabble}(T[0..n-1],\ P)\\
1 & D \leftarrow \text{NewHashTable}() \\
2 & \textbf{for each}\ (p,\ v(p)) \in P: \quad D.\text{Insert}(p,\ v(p)) \\
3 & x[n] \leftarrow 0; \quad par[n] \leftarrow \text{nil} \\
4 & \textbf{for}\ i = n-1\ \textbf{downto}\ 0: \\
5 & \quad x[i] \leftarrow x[i+1]; \quad par[i] \leftarrow i+1 \quad\quad \text{// (A) 跳过 } t_i \\
6 & \quad \textbf{for}\ j = 1\ \textbf{to}\ \min(10,\ n-i): \quad\quad \text{// (B) 猜长度} \\
7 & \quad\quad \textbf{if}\ T[i:i+j] \in D\ \textbf{and}\ D[T[i:i+j]] + x[i+j] > x[i]: \\
8 & \quad\quad\quad x[i] \leftarrow D[T[i:i+j]] + x[i+j]; \quad par[i] \leftarrow i+j \\
9 & \textbf{return}\ \text{Reconstruct}(T,\ par,\ n)
\end{array}
```

```math
\begin{array}{ll}
\textbf{proc} & \text{Reconstruct}(T,\ par,\ n)\\
1 & S \leftarrow \langle \rangle; \quad i \leftarrow 0 \quad\quad \text{// } S \text{ 存 gameplay}\\
2 & \textbf{while}\ i < n: \\
3 & \quad \textbf{if}\ par[i] = i+1: \quad i \leftarrow i+1 \quad\quad \text{// 该位置被跳过，不产出 word} \\
4 & \quad \textbf{else}: \quad S.\text{Append}(T[i:par[i]]); \quad i \leftarrow par[i] \\
5 & \textbf{return}\ S
\end{array}
```

**接口与边界**：第 6 行的 $\min(10,\ n-i)$ 是「$j \le 10$」与「$i+j \le n$」两个条件的合并写法，避免越界；第 5 行**先**把 $x[i]$ 初始化为跳过候选，等价于把 $\{x(i+1)\}$ 放进 max 集合里先占位——这样第 7 行的严格大于就自动实现了「取 max」。$P$ 中的 key 用数组直接做 key（长度 $\le 10$ 的整数数组），哈希时按元素逐个混入，代价 $O(10)=O(1)$。

#### 9. 正确性（必须用归纳假设，不能写"显然"）

**命题**：对每个 $i \in \{0, 1, \ldots, n\}$，$x(i)$ 等于 $T[i:]$ 上所有合法 gameplay（一局玩法）的**最大总价值**。

**归纳变量**：对 $i$ 做**递减**归纳（从 $i=n$ 往下到 $i=0$）。等价地，令 $k = n-i$ 为后缀长度，则是对 $k$ 做递增归纳。用递减形式是为了让归纳假设「对一切 $i' > i$ 成立」恰好覆盖递推用到的全部子问题。

**Base（$i=n$）**：$T[n:]$ 为空数组。空数组上唯一合法 gameplay（一局玩法）是空列表，$\sum_{s\in S} v(s) = 0$（空和）；而任何 playable word（可玩单词）长度 $\ge 1$，均无法放入空数组，故可选集合只有 $\{\varnothing\}$，最大值 $=0=x(n)$。✓

**Inductive step**：设对一切 $i' > i$ 命题成立，证 $i$ 成立。任取 $T[i:]$ 上一个合法 gameplay（一局玩法）$S$，按「$t_i$ 是否被覆盖」分两种互斥情形：

- **情形 A：$t_i$ 不被任何 $s \in S$ 覆盖。** 则每个 $s \in S$ 都完全落在 $T[i+1:]$ 之内（因为 $s$ 是 $T[i:]$ 的连续子数组、又不含位置 $i$，只能整体位于 $i$ 右侧），且仍互不重叠、仍在 $D$ 中，所以 $S$ 也是 $T[i+1:]$ 上的合法 gameplay（一局玩法），由归纳假设 $v(S) \le x(i+1)$。
- **情形 B：$t_i$ 被某个 $s \in S$ 覆盖。** 因 $S$ 中 playable word（可玩单词）互不重叠、每个都是连续段，覆盖位置 $i$ 的 playable word（可玩单词）**唯一**；又因所有 playable word（可玩单词）都在 $T[i:]$ 内、不含 $i$ 左侧的位置，它必须**以 $i$ 为左端点**，即 $s = T[i:i+j]$。由题目约束：$1 \le |s| = j \le 10$；由 $s \subseteq T[i:]$ 得 $i+j \le n$；由 $s$ 是 playable word（可玩单词）得 $T[i:i+j] \in D$ 且 $v(s) = D[T[i:i+j]]$。去掉 $s$ 后的 $S' = S \setminus \{s\}$ 是 $T[i+j:]$ 上的合法 gameplay（不重叠性继承），由归纳假设 $v(S') \le x(i+j)$。于是 $v(S) = D[T[i:i+j]] + v(S') \le D[T[i:i+j]] + x(i+j)$，且该候选满足全部三个 side condition，故被 max 的第二集合枚举到。

两情形穷尽，故对任意 $S$ 都有 $v(S) \le x(i)$ —— $x(i)$ 是**上界**。

**反向（可达性）**：max 中每个候选都是可实现的。
- 若取的是 $x(i+1)$：把 $T[i+1:]$ 的最优 gameplay（一局玩法）原样放进 $T[i:]$，playable word（可玩单词）互不重叠、都在 $D$ 中，仍合法，价值 $x(i+1)$；
- 若取的是某个合法 $j$：$s = T[i:i+j]$ 与 $T[i+j:]$ 的最优 gameplay（一局玩法）拼起来，$s$ 的右端点 $\le i+j$ 且后者全部起点 $\ge i+j$，故不重叠，合法，价值 $D[T[i:i+j]] + x(i+j)$。

所以 $x(i)$ 又是**可达值**。上下界相合，$x(i) = \max_S v(S)$。归纳完成。∎

**重建算法的正确性（循环不变式）**：`Reconstruct` 的 while 循环，不变式为——「每次迭代开始时，$S$ 中已收集的 playable word（可玩单词）恰好构成 $T[0:i]$ 的一个合法 gameplay（一局玩法），且其总价值 $= x(0) - x(i)$」。
- *Initialization*：$i=0$，$S=\langle\rangle$，$T[0:0]$ 为空，价值 $0 = x(0)-x(0)$。✓
- *Maintenance*：若 $par[i] = i+1$，由第 5 行 $x(i) = x(i+1)$，追加的是空动作，新价值 $= (x(0)-x(i)) + 0 = x(0) - x(i+1)$；若 $par[i] = i+j$（$j\ge1$），由第 8 行 $x(i) = D[T[i:i+j]] + x(i+j)$，追加 $T[i:par[i]]$ 后新价值 $= (x(0)-x(i)) + D[T[i:i+j]] = x(0) - x(i+j)$。两种情形都保持不变式，且新增段左端为 $i$、与已收集部分（全在 $[0,i)$ 内）不重叠。✓
- *Termination*：每次迭代 $i$ 严格增大（$par[i] > i$），故必终止于 $i=n$；此时不变式给出 $S$ 是 $T[0:n]$ 的合法 gameplay（一局玩法）、总价值 $= x(0) - x(n) = x(0)$，即最优。✓

#### 10. 复杂度：递推式写出来并解出来

**(i) 记忆化/自底向上的总工作量。** 子问题按依赖关系形成一条「下标递减」的链式 DAG（有向无环图），每个子问题的**直接工作量**是常数 $c$（$1$ 次跳过 + $\le 10$ 次 hash 查询），因此总和是一个求和而不是分治递推：

```math
W(n) \;=\; \sum_{i=0}^{n-1} \Theta(1) \;=\; \Theta(n)
```

按主定理的语言说：这里没有「把问题分成若干子规模再合并」的结构，故递推是 $W(n) = W(n-1) + \Theta(1)$，解得 $W(n) = \Theta(n)$（等差数列求和：$\sum_{k=1}^{n} c = cn$）。

**(ii) 建表工作量。**

```math
W_{\mathrm{build}}(m) \;=\; \sum_{k=0}^{m-1} O(|p_k|) \;=\; \sum_{k=0}^{m-1} O(10) \;=\; O(m)
```

关键在 $|p_k| \le 10$ 是常数：单次插入的代价是 $O(|p_k|) = O(1)$（哈希一个 key 要扫过它的全部元素，但元素个数被 10 封顶），乘上 $m$ 次插入才是 $O(m)$。若 key 长度不受限、上界记作 $L$，单次插入就是 $O(L)$、建表 $O(mL)$——那才会多出一个长度因子。

**(iii) 合计（期望）。**

```math
T(n, m) \;=\; W(n) + W_{\mathrm{build}}(m) \;=\; \Theta(n) + O(m) \;=\; O(n+m)
```

期望来自 hash table（哈希表）的期望 $O(1)$ 查询；最坏情况（全部 key 碰撞）会退化到 $O(nm)$，故严格说法是 **expected $O(n+m)$**。空间：hash table（哈希表）存 $m$ 个 key 各 $O(10)$、$x$ 与 $par$ 各 $O(n)$，合计 $O(n+m)$。

**(iv) 反例：忘记记忆化会怎样（这就是"Correct but inefficient 拿 partial credit"的典型）。** 纯递归展开（每个状态不缓存、重复求解）的递推为

```math
R(i) \;=\; R(i+1) + \sum_{j=1}^{10} R(i+j) + O(1) \;=\; 2R(i+1) + R(i+2) + \cdots + R(i+10) + O(1)
```

设 $R(i) = \Theta(\lambda^{\,n-i})$，代入并同除 $\lambda^{\,n-i}$ 得特征方程

```math
1 \;=\; 2\lambda^{-1} + \lambda^{-2} + \cdots + \lambda^{-10}
\quad\Longleftrightarrow\quad
\lambda^{10} \;=\; 2\lambda^{9} + \lambda^{8} + \cdots + \lambda + 1
```

左端在 $\lambda=1$ 时为 $1$、右端为 $2+9=11$，故 $\lambda = 1$ 时右 > 左；$\lambda \to \infty$ 时左端 $\lambda^{10}$ 主导、左 > 右，由连续性知存在根 $\lambda^{*} > 1$。于是 $R(0) = \Theta((\lambda^{*})^{n})$，**指数级**。记忆化把「每个子问题重算多次」压成「只算一次」，正是把 $R$ 变成 $W$ 的那一步——这也是 DP 存在的全部理由。

#### 11. 样例走一遍（用题目给的 $T$、$P$ 自检递推）

$T = [1,5,2,4,1]$，$n=5$；$D$：$[2]\mapsto 3$，$[1]\mapsto 1$，$[5,2]\mapsto 8$，$[1,2]\mapsto 12$，$[1,5]\mapsto 2$。

| $i$ | $t_i$ | 候选（跳过 ／ 取词） | $x(i)$ | $par(i)$ |
|---|---|---|---|---|
| 5 | —（空后缀） | base | 0 | nil |
| 4 | 1 | 跳过 $x(5)=0$；$[1]\to 1+x(5)=1$ | **1** | 5 |
| 3 | 4 | 跳过 $x(4)=1$；无以 4 开头的 playable word（可玩单词）| **1** | 4 |
| 2 | 2 | 跳过 $x(3)=1$；$[2]\to 3+x(3)=4$ | **4** | 3 |
| 1 | 5 | 跳过 $x(2)=4$；$[5,2]\to 8+x(3)=9$ | **9** | 3 |
| 0 | 1 | 跳过 $x(1)=9$；$[1]\to 1+x(1)=10$；$[1,5]\to 2+x(2)=6$；$[1,5,2]\notin D$ | **10** | 1 |

- $i=3$ 一行值得注意：$t_3=4$，词典里没有以 4 开头的词（$[1,2]$ 里的 1、2 位置不对），所以只有跳过——这说明「内容匹配」是硬条件，不能只看数值在不在 $T$ 里。
- 重建：$0 \xrightarrow{\text{取 }[1]} 1 \xrightarrow{\text{取 }[5,2]} 3 \xrightarrow{\text{跳过}} 4 \xrightarrow{\text{取 }[1]} 5$，得 gameplay（一局玩法）$([1],\,[5,2],\,[1])$，总价值 $1+8+1 = 10$，与题面给出的 $S_2$ 及其价值 10 **完全吻合**。
- 端点自检：$x(0)=10$ 不超过「$D$ 中所有词价值之和」$1+3+8+12+2=26$，也不低于「$T$ 中真正出现过的词的最大价值」$\max\{1,3,8,2\}=8$（价值 12 的 $[1,2]$ 在 $T$ 里不存在，用不上）——$8 \le 10 \le 26$ 落在合理区间内，说明递推没有丢掉候选、也没有凭空造出候选。

#### 12. 常见错误（对应原文 "See scratch S2 for common mistakes"）

1. **忘记「跳过」分支**：只写取词项，导致遇到无法匹配的位置（如 $t_3=4$）时递推断裂。跳过项 $x(i+1)$ 是合法性的保障。
2. **把 $j$ 的上界写成 $n-i$ 而不封顶 10**：逻辑上不错，但会枚举到长度 $>10$ 的片段，既违背"at most 10"的题设，也把 $O(1)$ 变成 $O(n)$，总时间退化成 $O(n^2)$。
3. **用 $T$ 中的位置或用 $P$ 的下标做状态**：状态必须是「后缀起点 $i$」，不是「$P$ 里第几个词」——因为词与 $T$ 的坐标无关，混用会导致状态爆炸且无法保证无环。
4. **把 playable word（可玩单词）的 $v$ 当成"长度"或"能不能用"**：$v$ 只进目标函数，不进可行性判定；可行性只看「是否等于 $T$ 的某个连续片段且长度 $\le 10$」。
5. **算复杂度时把建表写成 $O(10m)$ 还声称 $O(m)$ 而不解释**：必须点明 $|p_k| \le 10$ 是常数，这一步才是 $O(m)$ 的依据。

## 第 5 页

**Problem 4. [19 points] Limited-Unlimited（受限—不受限序列）**

给定两个整数集合 $A$ 与 $B$，$A$ 与 $B$ 的一个 **limited-unlimited sequence（受限—不受限序列）** 是指任意一个整数序列 $S$，满足：每个整数 $s \in S$ 都出现在 $A$ 或 $B$ 中；并且若 $s$ 出现在 $A$ 中，则 $s$ 在 $S$ 中至多出现一次。给定一个目标和 $m$ 以及两个**不相交**的集合 $A$、$B$，每个集合都恰好包含 $n$ 个**互不相同的正整数**，请描述一个 $O(nm)$ 时间的算法，判断 $m$ 是否为 $A$ 与 $B$ 的某个 limited-unlimited sequence（受限—不受限序列）$S$ 的元素之和，即

```math
m = \sum_{s \in S} s
```

**Solution（解答）：**

**1. Subproblems（子问题）**

- 先给 $A = (a_0, \dots, a_{n-1})$ 和 $B = (b_0, \dots, b_{n-1})$ 各自固定一个任意顺序。
- $x_A(i, k)$：布尔值，表示 $k$ 是否为 $A$ 的后缀 $A[i:]$（**不允许重复取**）的某个子集之和。
- $x_B(i, k)$：布尔值，表示 $k$ 是否为 $B$ 的后缀 $B[i:]$（**允许重复取**）的某个子集之和。
- 其中 $i \in \{0, \dots, n\}$，$k \in \{0, \dots, m\}$。

**2. Relate（递推关系）**

- 对于 $A$：要么使用 $a_i$ 一次，要么不使用（之后不能再用了）：

```math
x_A(i, k) = \big( a_i \le k \ \wedge\ x_A(i+1,\ k-a_i) \big) \ \vee\ x_A(i+1,\ k)
```

- 对于 $B$：要么使用 $b_j$ 一次，要么不使用（但之后**还能再用**）：

```math
x_B(i, k) = \big( b_j \le k \ \wedge\ x_B(i,\ k-b_j) \big) \ \vee\ x_B(i+1,\ k)
```

> **译注（$b_j$ 的下标口径）**：源 PDF 第 2 步 Relate 里，subproblem（子问题）的下标是 $i$（$x_B(i,k)$、$x_B(i+1,k)$），但同一段被「猜」的那个元素写成了 $b_j$（原文两行：`Either use bj once or not (but may use again)`、`xB(i, k) = OR xB(i, k - bj) if bj <= k`）。两处必须是同一个下标，$j$ 就是 $i$：只有 $j=i$ 时 $x_B(i,\ k-b_j)$ 的第二个参数才严格小于 $k$，依赖才落在 $k-i$ 严格更小的子问题上——这正是第 3 步 acyclic（有向无环的）论证所依赖的那条不等式。若把 $j$ 当成独立下标，$x_B(i,\ k-b_j)$ 引用的就是一个没有定义过的量。所以 $b_j$ 是原文的记号瑕疵，不是另一种状态设计；本文照抄原式以保真，只在此点明 $j=i$。

**3. Topo（拓扑序 / 无环性）**

- 子问题 $x_A(i, k)$ 与 $x_B(i, k)$ 都只依赖于 $k - i$ 严格更小的 subproblem（子问题），因此是 acyclic（有向无环的）：沿依赖边看 $k - i$ 严格递减，走不出一个环，所以按 $k-i$ 递增的顺序逐层求值即可。

**4. Base（基本情况）**

- $x_s(i, 0) = \text{True}$，其中 $s \in \{A, B\}$，$i \in \{0, \dots, n\}$（总能凑出和为 $0$）。
- $x_s(n, k) = \text{False}$，其中 $s \in \{A, B\}$，$k \in \{1, \dots, m\}$（凑不出正数和）。

**5. Original（原问题）**

- 用递归的 top-down（自顶向下）写法、或迭代的 bottom-up（自底向上）写法求解这些 subproblem（子问题）。
- 原问题等价于：是否存在 $A$ 的一个子集与 $B$ 的一个可重复取用的子集，两者之和等于 $m$。
- 即

```math
\bigvee_{k=0}^{m} \Big( x_A(0, k) \ \wedge\ x_B(0, m-k) \Big)
```

**6. Time（时间复杂度）**

- 子问题个数：$(n+1)(m+1) = O(nm)$。
- 每个子问题的工作量：$O(1)$。
- 原问题额外耗时 $O(m)$。
- 总运行时间：$O(nm)$。

- （常见错误见草稿纸 S2。）

## 第 6 页

**Problem 5. [19 points] Office Hour Optimization（答疑时间最优化）**

班级 0.660《Algorithms for Introductions（入门算法）》举办线上 office hours（答疑），在三个对应的 breakout room（分组讨论室）里帮助学生解决三道题 —— $a$、$b$、$c$。TA（助教）想开发一个『Sort Bot』，在 office hours（答疑）开始时把每个学生分配到**某一个**房间。假设有 $3n$ 个学生，每个学生 $i$ 被分配到题目 $a$、$b$、$c$ 的房间时，分别有已知的非负整数 benefit（收益）$a_i$、$b_i$、$c_i$。

请描述一个 $O(n^3)$ 时间的算法，判断是否能把学生**均等**地分配到三个 breakout room（即每个房间 $n$ 个学生），同时为**每个学生**都提供**严格为正**的帮助；若可行，则返回所有此类分配中学生的**最大总收益**。注意：分配不能把学生分到其收益为零的房间。

**Solution（解答）：**

**1. Subproblems（子问题）**

- 令学生为 $i \in \{1, \dots, 3n\}$。
- $x(i, j, k)$：把学生 $\{1, \dots, i+j+k\}$ 分配到 breakout room（分组讨论室），其中 $i$ 个学生去房间 $a$、$j$ 个去房间 $b$、$k$ 个去房间 $c$ 时，所能获得的最大收益，且每个学生都被分到收益严格为正的房间（若不存在这种分配则等于 $-\infty$）。
- 其中 $i, j, k \in \{0, \dots, n\}$。

**2. Relate（递推关系）**

- 必须把学生 $i+j+k$ 分到某个房间（这是 DP 中的猜测 Guess）：

```math
x(i, j, k) = \max\Big\{\, -\infty\ \Big\}\ \cup\ \begin{cases}
a_{i+j+k} + x(i-1, j, k), & i > 0 \text{ 且 } a_{i+j+k} > 0,\\
b_{i+j+k} + x(i, j-1, k), & j > 0 \text{ 且 } b_{i+j+k} > 0,\\
c_{i+j+k} + x(i, j, k-1), & k > 0 \text{ 且 } c_{i+j+k} > 0
\end{cases}
```

**3. Topo（拓扑序 / 无环性）**

- 子问题 $x(i, j, k)$ 只依赖于 $i+j+k$ 严格更小的 subproblem（子问题），因此是 acyclic（有向无环的）：沿依赖边看 $i+j+k$ 严格递减，从 $(0,0,0)$ 出发按 $i+j+k$ 递增填表即可。

**4. Base（基本情况）**

- $x(0, 0, 0) = 0$（给零个学生分配，收益为零）。

**5. Original（原问题）**

- 用递归的 top-down（自顶向下）写法、或迭代的 bottom-up（自底向上）写法求解这些 subproblem（子问题）。
- $x(n, n, n)$ 就是把所有学生均等分到三个房间的最大收益。

**6. Time（时间复杂度）**

- 子问题个数：$(n+1)^3 = O(n^3)$。
- 每个子问题的工作量：$O(1)$。
- 总运行时间：$O(n^3)$。
> **译注（为什么状态只有三维）**：$x(i,j,k)$ 只用「三个房间各分到几个人」这三个数就够，因为已分配的学生总数 $i+j+k$ 被这三个数隐含确定了——这正是 $O(n^3)$ 而不是 $O(n^4)$ 的来源，也是第 7 页 Common Mistakes（常见错误）里「定义了 $O(n^4)$ 个 subproblem（子问题）」那一条针对的坑。$-\infty$ 在递推里承担「不可行」的语义：某条分法一旦让某个学生落进零 benefit（收益）的房间，这条路径的值就被吸收到 $-\infty$，取 $\max$ 时自然被淘汰，因此不需要另开一个可行性数组。

- （常见错误见草稿纸 S2。）
