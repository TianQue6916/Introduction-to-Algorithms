### <span style="color:#2471a3;">**[problem]**</span> <span style="color:#c0392b">Problem 8-1. Sunny Studies（阳光学习计划）</span>

Tim the Beaver（海狸蒂姆）需要为考试复习，但天气越来越暖和，Tim 想花更多时间待在户外。天气越暖 Tim 越喜欢户外活动：具体来说，如果户外温度是高于零度的 $t$ 个整数单位，那么 Tim 在外面待一天后 happiness（幸福感）会增加 $t$（当 $t$ 为负时幸福感会下降）。在期末考试前的 $n$ 天里，每一天 Tim 要么学习，要么出去玩（同一天从不两者兼做）。为了保持学业不掉队，Tim 决心连续在户外玩的天数**不超过两天**。给定未来 $n$ 天的 weather forecast（天气预报）温度估计，描述一个 $O(n)$ 时间的 dynamic programming algorithm（动态规划算法），确定 Tim 应该在哪几天学习，才能使幸福感增加最多。

> **[solution] Solution（解答）:**
>
> **1. Subproblems（子问题）**
>
> - 设 $t(i)$ 为第 $i$ 天的温度
> - $x(i)$：第 $i$ 天到第 $n$ 天期间可能达到的最大幸福感增加量
>
> **2. Relate（关联）**
>
> - Guess（猜测）第 $i$ 天是学习还是出去玩会带来更多幸福感
> - 如果学习，幸福感不变，但第二天可以学习或玩，即 $x(i+1)$
> - 如果玩，幸福感改变 $t(i)$，并且要么
>   - 第 $i+1$ 天学习：$t(i) + x(i+2)$；或
>   - 第 $i+1$ 天也玩、第 $i+2$ 天学习：$t(i) + t(i+1) + x(i+3)$
> - 对 $i \in \{1, \dots, n-1\}$：
>
>   ```math
>   x(i) = \max\{x(i+1),\ t(i) + x(i+2),\ t(i) + t(i+1) + x(i+3)\}
>   ```
>
> **3. Topo. Order（拓扑序）**
>
> - 子问题 $x(i)$ 只依赖下标严格更大的子问题，因此 acyclic（无环）
>
> **4. Base（基例）**
>
> - $x(n) = \max\{0, t(n)\}$：如果只剩一天，要么玩要么学习
> - $x(n+1) = x(n+2) = 0$：如果没有更多天，无法再增加幸福感
>
> **5. Original（原问题）**
>
> - $x(1)$ 是从第 1 天到第 $n$ 天的最大幸福感增加量
> - 存储 parent pointers（父指针）以重构应该学习的天数
>
> **6. Time（时间分析）**
>
> - 子问题数：$x(i)$，$i \in \{1, \dots, n+2\}$，共 $n+2 = O(n)$ 个
> - 每个子问题的工作量：$O(1)$（branching factor，分支因子为常数）
> - 运行时间 $O(n)$

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这条注要回答的是：像“连续在户外不超过两天”这种全局约束，怎么塞进动态规划的子问题结构里，而且不必额外加状态维度。
>
> 机制的第一步是把约束当成一台机器来读。“连续不超过两天”是一条正则语言，识别它的自动机只有三个状态：已经连玩零天、一天、两天。第二步是把这台自动机与序列做乘积——子问题取后缀“从第 i 天起”，再记住“到第 i 天为止已经连玩了几天”。于是“全局约束”变成“局部状态”，你不需要回头看更早的日子，因为自动机的状态已经把需要的历史压缩掉了。
>
> 第三步是枚举。站在第 i 天，只有三种互斥的走法：今天学习，幸福值不变，转到后缀 i+1；今天玩、明天学，吃进两天的温度，转到后缀 i+2；今天玩、明天也玩、后天学，吃进三天的温度，转到后缀 i+3。三条分支覆盖了所有合法方案，且互不重叠，所以取三者最大值就是最优。窗口宽度是二，分支数固定为三，于是每个子问题的工作量是常数。
>
> 算一个具体实例。设六天的温度为三、负二、五、四、负一、二（单位是“度”，正负都允许）。最优方案是第 1、3、4、6 天出去玩，其余两天学习，总幸福值为三加五加四加二等于十四。注意第 2 天的负二与第 5 天的负一都被跳过了——这说明“贪心地尽量多玩”是错的，负温度的日子应该拿来学习，而“连玩不超过两天”恰好给了这个灵活性。
>
> 参数化一下就知道窗口宽度有多重要。若把约束放宽为“最多连续 k 天”，自动机就变成 k+1 个状态，递推要枚举 k+1 项取最大，复杂度升到 O(kn)。k 固定为常数时是线性的；若 k 随 n 增长（比如允许连玩一半的日子），复杂度就退化到平方级。也就是说，这条约束的“记忆长度”直接等于递推的分支数，也直接等于复杂度里的那个乘数。
>
> 跨课程连接：CLRS 里的 rod cutting（切杆）。两者都是后缀型子问题、都靠“枚举最后一段（或最前一段）怎么处理”，但切杆的分支数是 O(n)——第一段可以取任意长度；本题分支数固定为三——因为记忆长度是常数。这个对照给出一个判断法则：分支数由“可选决策数”决定，而可选决策数常常就是“约束允许的历史长度”。再看 House Robber（打家劫舍），它是窗口为一的退化情形，相邻两天最多选一天；本题是同一族“滑动窗口约束”的窗口为二版本。
>
> 跨课程连接二：6.042J 里有限状态机的直觉。任何“只能记住最近若干步”的约束都能写成有限自动机，而有限自动机与序列的乘积就是一个新的动态规划——状态数等于自动机状态数，转移数等于自动机的边数。这条通道让你把“看起来要回溯很久”的约束，统一翻译成“状态里多一个字段”。区别在于自动机理论关心“接受与否”，这里关心“最大值”，但结构完全一样。
>
> 收束：遇到全局约束先问一句“它需要记住多长的历史”。记忆长度是常数，就把它写进状态，DP 依然是线性的；记忆长度随输入增长，复杂度里就一定会多出那个因子。

### <span style="color:#2471a3;">**[problem]**</span> <span style="color:#c0392b">Problem 8-2. Diffing Data（数据比对）</span>

操作系统 Menix 有一个 diff utility（差异比对工具）可以比较文件。一个 file（文件）是一个有序的 strings（字符串）序列，其中第 $i$ 个字符串称为文件的第 $i$ 行。对文件的一次单个 change（变更）是以下操作之一：

- 向文件插入单个新行；
- 从文件删除单个行；或
- 交换文件中两个相邻的行。

在 Menix 中，交换两行很便宜，因为它们已经在文件里了；但插入或删除一行很贵。从文件 $A$ 到文件 $B$ 的 diff 是任意 change 序列，按顺序应用于 $A$ 就能把它变换成 $B$，条件是在何一行最多被交换一次，且任何一对被交换的行在 $A$ 中相邻、在 $B$ 中也相邻。给定两个文件 $A$ 和 $B$，每个恰好包含 $n$ 行，描述一个 $O(kn + n^2)$ 时间的 algorithm（算法），返回从 $A$ 到 $B$ 的、最小化非交换变更数的 diff，假设任一文件中的任意一行长度最多为 $k$ 个 ASCII 字符。

> **[solution] Solution（解答）:**
>
> **1. Subproblems（子问题）**
>
> - 首先，用 hash table（哈希表）在 $O(kn)$ 时间内为每个唯一行分配一个编号
> - 现在每行可以在 $O(1)$ 时间内与其他行比较
> - $x(i, j)$：将 $A[:i]$ 变换为 $B[:j]$ 所需的最小非交换变更数
>
> **2. Relate（关联）**
>
> - 如果 $A[i] = B[j]$，则在剩余部分上递归
> - 否则，考虑最后应用的一个变更：
>   - 删除 $A[i]$
>   - 插入一行与 $B[j]$ 匹配
>   - 交换 $A[:i]$ 中最后两行，以匹配 $B[:j]$ 中最后两行
> - 如果 $A[i] = B[j]$：$x(i, j) = x(i-1, j-1)$
> - 否则：
>
>   ```math
>   x(i, j) = \min \begin{cases}
>   1 + x(i-1, j) & \text{删除} \\
>   1 + x(i, j-1) & \text{插入} \\
>   x(i-2, j-2) & \text{交换，若 } A[i] = B[j-1] \text{ 且 } A[i-1] = B[j]
>   \end{cases}
>   ```
>
> **3. Topo. Order（拓扑序）**
>
> - 子问题 $x(i, j)$ 只依赖 $i + j$ 严格更小的子问题，因此 acyclic
>
> **4. Base（基例）**
>
> - $x(0, 0) = 0$：所有行都已变换完成
> - $x(i, 0) = i$：必须删除剩余部分
> - $x(0, j) = j$：必须插入剩余部分
>
> **5. Original（原问题）**
>
> - 按定义即为 $x(n, n)$
> - 存储 parent pointers 以重构实际做了哪些变更（在 $A[i] \neq B[j]$ 的分支里，记住发生的是删除、插入还是交换）
>
> **6. Time（时间分析）**
>
> - 预处理：$O(kn)$
> - 子问题数：$(n+1)^2 = O(n^2)$，$x(i, j)$，$i, j \in \{0, 1, \dots, n\}$
> - 每个子问题的工作量：$O(1)$
> - 运行时间 $O(n^2)$

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这条注要说清“操作集合”与“递推分支”之间那条一一对应的线，以及为什么加一个交换操作就要多看两行。
>
> 先把机制摆出来。二维子问题 x(i,j) 表示把 A 的前 i 行变成 B 的前 j 行所需的最少非交换变更数。关键在于：每一个被允许的操作都对应一个“吃掉多少输入”的分支。删除吃掉 A 的一行，走后继 (i−1, j) 并加一；插入吃掉 B 的一行，走后继 (i, j−1) 并加一；交换同时吃掉 A 的两行和 B 的两行，走后继 (i−2, j−2) 且不加一，因为交换本身不计入代价。三行代码就是这三个分支取最小值。
>
> 为什么交换分支只能看尾部两行？因为题目给了两条约束：每行最多被交换一次，且被交换的这一对在 A 中相邻、在 B 中也相邻。这两条把交换的“作用范围”钉死在一对相邻行上，于是任何最优方案都可以安排成“最后一步要么删、要么插、要么把最后两行对调”。如果没有这两条约束，交换可能牵动更靠前的位置，递推就必须记住更多历史，状态会爆炸。这就是“约束不是为了出题方便，而是为了让递推保持局部”的典型例子。
>
> 算几个小例子把手感校准。A 是 abcd、B 是 abdc：最后两行对调即可，非交换变更为零。A 是 abcd、B 是 badc：前两行对调、后两行对调，仍是零。A 是 abcd、B 是 dcba：需要两次删除加两次插入，代价四——注意不能让同一个字符反复参与交换来省步骤，那正是“每行最多交换一次”这条约束要排除的情形。这三个例子说明目标函数数的是“非交换变更”，交换是免费的，但免费的额度被约束卡得很紧。
>
> 有两个细节容易写错。第一，相等判断必须写成 A 的一个字符与 B 的对应字符比较；若误写成 A 内部两个字符比较，条件恒真，递推会退化成零代价，输出永远是零。第二，交换分支的触发条件必须是交叉相等——A 的最后一行等于 B 的倒数第二行，且 A 的倒数第二行等于 B 的最后一行；只写一边相等会把不相容的配对当成可交换。这两处都是“看起来像笔误、实际会改变语义”的地方。
>
> 跨课程连接：CLRS 第 15 章的 LCS（最长公共子序列）。两者骨架一致——二维子问题、按“最后一个操作”分情况、若干分支取最优；差别在于 LCS 只有两条分支（匹配或不匹配），且代价只有零与一，所以它更接近本课的“二分支最小代价递推”。本题加了一个 swap，等于把操作集合从两个元素扩到三个元素，分支数与“吃掉的行数”同时变化，这就是为什么它要多看一行。
>
> 再看工业界的对应物。git diff 默认用的是 Myers 在 1986 年提出的 O(ND) 算法，其中 D 是两个文件的差异规模，通常远小于 n 的平方，所以它在真实文件上远快于填满一张 n 乘 n 的表，且空间可以做到线性。它不做交换，只做增删；git 后来加的 --patience 与 --histogram 是对“大量重复行”的启发式改进，先用唯一行锚定、再在锚点之间做 LCS。这个对照能让你看清“动态规划的正确性”与“工程实现的可用性”是两件事：前者给你最优值与最优结构，后者为了常数与内存牺牲一部分最优性。
>
> 收束：以后见到“编辑距离”类问题，只做一件事——把允许的操作列出来，对每个操作写下它吃掉多少输入、代价是多少，递推式就自动长出来了；分支数永远等于操作数。

### <span style="color:#2471a3;">**[problem]**</span> <span style="color:#c0392b">Problem 8-3. Building Blocks（搭积木）</span>

Saggie Mimpson（萨吉·米普森）是一个喜欢搭积木塔的幼儿。她的每块积木都是一个 3D rectangular prism（三维长方体），其中每块积木 $b_i$ 有正整数 width（宽）$w_i$、height（高）$h_i$ 和 length（长）$\ell_i$，而且每种积木她至少有三块。每块积木可以定向，使得其任意一对相对的长方形面充当顶面和底面，积木在该定向下的 height 是这两个面之间的距离。Saggie 想通过把积木尽可能堆高来建造一座塔，但只有当一块定向积木 $b_i$ 的底面尺寸**严格小于**另一块定向积木 $b_j$ 的顶面尺寸¹ 时，她才能把 $b_i$ 堆在 $b_j$ 上面。给定她 $n$ 块积木的尺寸，描述一个 $O(n^2)$ 时间的 algorithm，确定 Saggie 能用她的积木建造的最高塔的高度。

> <span style="color:#7f8c8d;">¹ 如果积木 $b_i$ 的底面尺寸为 $p \times q$，积木 $b_j$ 的顶面尺寸为 $s \times t$，则在这种定向下 $b_i$ 可以堆在 $b_j$ 上，当且仅当：$p < s$ 且 $q < t$；或 $p < t$ 且 $q < s$。</span>

> **[solution] Solution（解答）:**
>
> **1. Subproblems（子问题）**
>
> - 每块积木可以按三种垂直定向之一使用
> - （不失一般性，积木底面总可以按较短边指向同一方向来堆放）
> - 因为堆叠要求底面尺寸严格递减，任何最优塔对每种积木类型最多使用三次（每种定向一次）
> - 对每块积木的尺寸排序并去重（例如用 hash table 在 $O(n)$ 时间内完成）
> - 对排序后尺寸为 $a \le b \le c$ 的每种积木类型，构造三种定向 $(a, b, c)$、$(a, c, b)$、$(b, c, a)$（最后一个维度对应 height），并在 $O(n)$ 时间内加入 oriented block list（定向积木列表）
> - （每种类型重复三次是允许的，因为每种至少有三块）
> - 在 $O(n \log n)$ 时间内按字典序排序（第一维度最显著）
> - 重新编号排序后的列表，其中积木 $i$ 的定向尺寸为 $(w_i, \ell_i, h_i)$ 且 $w_i \le \ell_i$
> - 任何可堆叠的定向积木塔都必须是该排序列表的 subsequence（子序列），因为 $w_i$ 已排序；但并非该列表的每个子序列都构成合法塔，因为 $\ell_i$ 不一定有序
> - $x(i)$：使用积木 $i$ 以及剩余积木 $1$ 到 $i-1$ 的任意子集搭成的塔的最大高度
>
> **2. Relate（关联）**
>
> - Guess（猜测）塔中下一块更低的积木，只从 $\ell_i$ 严格更小的积木中选择
>
>   ```math
>   x(i) = h_i + \max\big(\{0\} \cup \{x(j) \mid j \in \{1, \dots, i-1\} \text{ 且 } \ell_i < \ell_j\}\big)
>   ```
>
> **3. Topo. Order（拓扑序）**
>
> - 子问题 $x(i)$ 只依赖下标严格更小的子问题，因此 acyclic
>
> **4. Base（基例）**
>
> - $x(1) = h_1$：递推中的最大值平凡地为 0
>
> **5. Original（原问题）**
>
> - 某块积木必须是塔顶，因此比较所有可能的塔顶
> - $\max\{x(i) \mid i \in \{1, \dots, n\}\}$
>
> **6. Time（时间分析）**
>
> - 预处理：$O(n \log n)$
> - 子问题数：$n$，$x(i)$，$i \in \{1, \dots, n\}$
> - 每个子问题的工作量：$O(n)$
> - 计算最终解：$O(n)$
> - 运行时间 $O(n^2)$
> - 注意：这个问题可以用与 Recitation 15 中 **Longest Increasing Subsequence（最长递增子序列，LIS）** 类似的优化，在 $O(n \log n)$ 时间内解决。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这条注要说清“排序降维”这个动作到底降掉了什么，以及为什么每种积木可以用三次这件事需要单独论证。
>
> 先把问题的形状看清楚。堆叠要求上面积木的底面两个维度都严格小于下面积木的顶面，这是一个二维的严格偏序；若直接拿来当子问题，状态就得同时记住两个维度，转移时还要在二维里比较，代价高且容易漏。排序降维的办法是：先按第一维升序排，于是“第一维更小”这个条件被排序顺序自动满足，任何合法塔都只能是这个序列的子序列；剩下只需检查第二维是否也严格递减。二维偏序被压成了一维递增子序列问题。
>
> 预处理还有一步关键观察：每种积木最多用三次。理由不是“她只有三块”，而是“严格要求递减”这个条件本身——同一块积木的三种定向给出三个不同的底面尺寸，而严格递减意味着任何一个尺寸链里，每种定向至多出现一次，否则会出现两个相等或逆序的尺寸。三种定向各用一次，正好是三次。这条观察把“无限供应”的问题变成了“有限 3n 个物品”的问题，是构造子问题之前必须先做的规约。
>
> 算一个两块的例子。积木甲是 (1,2,3)，积木乙是 (2,3,4)。把六种定向按字典序排好，能找出这样一条链：底面 (3,4) 高 2，其上底面 (2,3) 高 4，再其上底面 (1,2) 高 3，总高 2+4+3 = 9。这条链用了甲一次、乙两次（两次是不同定向），完全合法。若误以为“每种只能用一次”，最好只能拿到 4 或 3，差了一倍多。
>
> 为什么排序之后不能直接数最长递增子序列就完事？因为排序是按第一维做的，第二维并不跟随单调。排序只能保证“候选者按第一维有序”，若要保证塔合法，还得在子序列里挑出第二维严格递减的那些。于是递推写成：以第 i 个定向为塔底时，塔高等于它自己的高加上“在所有更小下标且第二维严格更小的定向里取最优”。这个式子与最长递增子序列逐项对应，只是把“长度加一”换成“高度加自己的高”。
>
> 跨课程连接：6.042J 的偏序集。严格偏序的关键概念是链——集合里任意两个元素都可比；本问的最优塔就是定向集合里的一条最长链（按“能放在上面”这个关系）。区别在于偏序集理论关心链的存在性与最长链的长度，而这里每个元素还带一个权重（高度），要求的是最大权链，是把组合结构与数值优化叠在一起。跨课程连接二：本课 recitation 提过的 patience sorting（耐心排序）——它把“扫描所有更小下标”的线性代价降成对数，靠的是维护一个按第二维索引的结构。这个优化对本题同样适用。
>
> 再补一个容易忽略的边界：三种定向里有一种是“把最短边竖起来”，它的底面积最大、高度最小；另一种相反。把它们混在一起排序时，要确保每种定向的三元组按“底面两边升序、高放最后”统一书写，否则排序的字典序会失去意义，链的判定也会出错。这类格式统一的工作看着琐碎，但它决定了后面递推是否能直接使用。
>
> 收束：遇到多维度约束的堆叠、嵌套问题，先问“能不能排序消掉一维”，再问“严格性把每种物品的使用次数限到了几次”。这两问过后，剩下的通常就是一个带权的最长链。

### <span style="color:#2471a3;">**[problem]**</span> <span style="color:#c0392b">Problem 8-4. Princess Plum（梅子公主）</span>

Princess Plum（梅子公主）是一个电子游戏角色，正在一片数字 haunted forest（鬼林）中收集蘑菇。森林是一个 $n \times n$ 的方形 grid（网格），每个网格方格要么是 tree（树）、mushroom（蘑菇），要么是空的。如果两个方格共享一条边，Princess Plum 就可以从一个方格移动到另一个方格，但她不能进入含有树的方格。Princess Plum 从左上角方格出发，想到达右下角方格的家²。鬼林很吓人，所以她希望走一条 quick path（快捷路径）回家：一条从起点到家的 route（路线），经过最多 $2n-1$ 个方格（包括起点和家）。如果 Princess Plum 进入一个含有蘑菇的方格，她会捡起它。设 $k$ 为她在任意 quick path 上能捡到的最大蘑菇数，若一条 quick path 上她能捡到 $k$ 个蘑菇，则称该 quick path 为 optimal（最优）的。

> <span style="color:#7f8c8d;">² 假设起点和家的方格都是空的。</span>

<span style="color:#2471a3;">**[part]**</span> <span style="color:#00838f">**(a) [15 points]**</span> 给定森林网格的地图，描述一个 $O(n^2)$ 时间的 algorithm，返回穿过森林的 distinct（不同的）optimal quick paths 的数量，假设存在某条 quick path。

> **[solution] Solution（解答）:**
>
> **1. Subproblems（子问题）**
>
> - 设左上角方格为 $(1, 1)$，右下角方格为 $(n, n)$
> - 设 $F[i][j]$ 表示方格 $(i, j)$ 的内容
> - 定义两类子问题：一类用于最优蘑菇数，一类用于计算路径数
> - $k(i, j)$：在触碰 $i + j - 1$ 个方格的路径上，从 $(1, 1)$ 到达 $(i, j)$ 的最大蘑菇数
> - $x(i, j)$：触碰 $i + j - 1$ 个方格、收集 $k(i, j)$ 个蘑菇的、从 $(1, 1)$ 到 $(i, j)$ 的路径数
>
> **2. Relate（关联）**
>
> - 一条触碰 $i + j - 1$ 个方格、终止于 $(i, j)$ 的路径，必须延伸一条触碰 $i + j - 2$ 个方格、终止于其左邻或上邻的路径
> - 如果 $F[i][j]$ 含有树：
>   - 没有到 $(i, j)$ 的路径
>   - $k(i, j) = -\infty$ 且 $x(i, j) = 0$
> - 否则：
>   - 设 $m(i, j)$ 在 $F[i][j]$ 是蘑菇时为 $1$，否则为 $0$
>   - $k(i, j) = m(i, j) + \max(k(i-1, j),\ k(i, j-1))$
>   - $x(i, j)$ 等于所有满足「经由该前驱达到最优」条件的前驱 $x$ 值之和：
>
>   ```math
>   x(i, j) = \sum_{\substack{p \in \{(i-1,j),\ (i,j-1)\} \\ k(p) + m(i, j) = k(i, j)}} x(p)
>   ```
>
>   （即：若左邻达到最优则累加 $x(i-1, j)$，若上邻达到最优则累加 $x(i, j-1)$，两者都达到最优则累加两者之和，都不满足则为 $0$）
>
> **3. Topo. Order（拓扑序）**
>
> - 子问题 $k(i, j)$ 只依赖 $i + j$ 严格更小的 $k$ 子问题，因此 acyclic
> - 子问题 $x(i, j)$ 只依赖 $i + j$ 严格更小的 $x$ 子问题（以及不依赖任何 $x$ 子问题的 $k$ 子问题），因此 acyclic
>
> **4. Base（基例）**
>
> - $k(1, 1) = 0$：起点没有蘑菇
> - $x(1, 1) = 1$：起点处有一条路径
> - 负下标方格不可能
> - $k(0, i) = k(i, 0) = -\infty$，$i \in \{0, \dots, n\}$
> - $x(0, i) = x(i, 0) = 0$，$i \in \{0, \dots, n\}$
>
> **5. Original（原问题）**
>
> - 按定义即为 $x(n, n)$
>
> **6. Time（时间分析）**
>
> - 子问题数：$2(n+1)^2 = O(n^2)$，$k(i, j)$ 和 $x(i, j)$，$i, j \in \{0, 1, \dots, n\}$
> - 每个子问题的工作量：$O(1)$
> - 运行时间 $O(n^2)$

<span style="color:#2471a3;">**[part]**</span> <span style="color:#00838f">**(b) [25 points]**</span> 编写一个 Python 函数 `count_paths(F)`，实现你在 (a) 中的 algorithm。

> **[solution] Solution（解答）:**

```python
def count_paths(F):
    n = len(F)
    K = [[-float('inf')]*(n + 1) for _ in range(n + 1)]  # init K memo
    X = [[0]*(n + 1) for _ in range(n + 1)]  # init X memo
    for i in range(1, n + 1):  # bottom-up dynamic program
        for j in range(1, n + 1):
            if F[i - 1][j - 1] == 't':  # base case
                continue
            if i == 1 and j == 1:  # base case
                K[1][1], X[1][1] = 0, 1
                continue
            if F[i - 1][j - 1] == 'm':
                m = 1
            else:
                m = 0
            K[i][j] = m + max(K[i - 1][j], K[i][j - 1])
            if K[i - 1][j] + m == K[i][j]: X[i][j] += X[i - 1][j]
            if K[i][j - 1] + m == K[i][j]: X[i][j] += X[i][j - 1]
    return X[n][n]
```

> <span style="color:#7f8c8d;">代码要点：$K$ 表初值 $-\infty$ 充当「不可达」标记（含树方格保持 $-\infty$ 不更新），$X$ 表初值 $0$；$m$ 在蘑菇格为 $1$。两个 `if` 条件与递推中「$k$ 值相等才累加」一一对应——若两个前驱都达到最优，两个 `if` 同时成立，$X[i][j]$ 自动得两者之和，与求和式一致。边界 $k(0,i) = k(i,0) = -\infty$、$x(0,i) = x(i,0) = 0$ 由数组的零行/零列初值天然实现。</span>

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这条注要回答的是：为什么“数出达到最优值的方案数”必须维护两张表，以及那张计数表的转移为什么要加一道门。
>
> 先看问题本身逼出了什么。只维护一张最优值表，你能算出“最多能捡几个蘑菇”，但算不出“有几条路能达到这个数”，因为最值表只记了值，把“有几条路”这个信息丢掉了。于是要并行维护两张表：一张存最优值，一张存达到该最优值的方案数。两张表用同一套拓扑序一起填，互不干扰但又彼此依赖——这正是这类问题的标准形态。
>
> 机制的关键在计数表的转移上。前驱有两个：左邻与上邻。若某个前驱能达成全局最优，就把它的方案数累加进来；否则不累加。用式子说就是“只有当经由这个前驱算出的值等于当前最优值时，才把它的计数加进来”。这道门是整条注最要紧的一句：如果不加门而把两个前驱的方案数无条件相加，你数的是“所有路径”，而不是“最优路径”，答案会偏大。
>
> 算一个小网格核对。取一个三行三列的网格，其中一格是树（不能进），两格是蘑菇。只允许向右、向下走时，从左上到右下的所有路径共有六条——这对应组合数 C(4,2)，因为总共要走四步、其中两步向下。真正的最优蘑菇数是三，而达到这个数的路径只有两条。也就是说：六条路里只有两条最优，其余四条虽然能走通，但蘑菇数不够。没有那道门，计数表会给出六。
>
> 再解释题目里那个看起来多余的条件：“路径最多经过 2n−1 个方格”。在 n 乘 n 的网格上，从左上到右下最短需要经过 2n−1 个格子（含起点与终点），任何含向上或向左回退的路径都更长。所以这个条件等价于“只许向右或向下”，而“只许向右或向下”又等价于“路径落在一张有向无环图上”。这一步等价替换是整个解法的枢纽——它把“任意游走”降维成“网格上的路径计数”，从而拓扑序、无环性、递推三件事一次性到手。
>
> 为什么树那一格要清成负无穷与零？因为最优值表里负无穷表示“不可达”，计数表里零表示“没有方案”。两者必须同时置位，否则会出现“值可达但计数为零”或“计数非零但值不可达”的矛盾状态。这也说明两张表的初始化必须一致——这是写代码时最容易漏的地方，也是把递推式翻译成循环时第一个要检查的地方。
>
> 跨课程连接：6.042J 的组合计数。无阻碍的网格上，每个格子的路径数等于左邻加上邻，逐格填出来就是 Pascal 三角；本题的计数表在“没有树、且所有路径都最优”的极端情形下，退化成同一个三角形。区别在于这里的累加被“最优值相等”这道门控制，所以它数的不是“所有路径”，而是“最短路条数”——这在概率与随机游走里是同一个量：数“最可能的那条路径有多少条”。
>
> 收束：计数类动态规划只有一句话——把“值”与“数”分开存，并用“是否达成最优”把两者缝在一起；门没缝紧，数出来的东西就没有意义。
