## <span style="color:#2471a3;">**[exercise]**</span> <span style="color:#c0392b">Max Subarray Sum（最大子数组和）</span>

给定一个含 $n$ 个整数的数组 $A$，任意非空 subarray（子数组）的最大和是多少？
（本课程中，subarray 总是指一段 contiguous（连续）的元素序列）

**Example（例）:** $A = [-9, 1, -5, 4, 3, -6, 7, 8, -2]$，最大子数组和为 $16$。

**Solution（解答）:**

我们可以用 $O(n^3)$ 暴力枚举：先枚举 $O(n^2)$ 个子数组，每个用 $O(n)$ 时间求和。通过观察可以得到更快的算法——**和最大的子数组一定在某个位置结束**。计算"结束于特定位置 $k$ 的最大子数组"可以用 $O(n)$ 时间完成：从 $k$ 向左扫描，维护一个 rolling sum（滚动和），沿途记住最大值；由于结束位置共有 $n$ 个，该算法运行时间为 $O(n^2)$。

我们可以做得更快，只需认识到：**每一次向左扫描都在重做前面扫描已经做过的活儿**。让我们用动态规划来复用这些工作！

**1. Subproblems（子问题）**

- $x(k)$：结束于 $A[k]$ 的最大子数组和
- 带条件的 prefix（前缀）型子问题，类似 Longest Increase Subsequence（最长递增子序列）
- （练习：尝试改用 suffixes（后缀）而不是 prefixes（前缀）重新表述）

**2. Relate（关联）**

- 结束于 $k$ 的最大子数组要么用 $k - 1$ 这个元素，要么不用
- 如果不用，那么该子数组就是单独的 $A[k]$
- 否则，$k - 1$ 被使用，我们应包含结束于 $k - 1$ 的最大子数组
- $x(k) = \max\big\{A[k],\ A[k] + x(k-1)\big\}$

**3. Topo. Order（拓扑序）**

- 子问题 $x(k)$ 只依赖严格更小的 $k$，因此无环。

**4. Base（基例）**

- $x(0) = A[0]$（因为子数组必须非空）

**5. Original（原问题）**

- 用递归 top down 或迭代 bottom up 求解子问题
- 原问题的解是所有子问题解的最大值，即 $\max\{x(k) \mid k \in \{0, \dots, n-1\}\}$
- 每个子问题被使用两次：一次在计算下一个更大的子问题时，一次在最终求 max 时

**6. Time（时间分析）**

- 子问题个数：$O(n)$
- 每个子问题工作量：$O(1)$
- 求解原问题的时间：$O(n)$
- 总时间：$O(n)$

```python
# bottom up implementation
def max_subarray_sum(A):
    x = [None for _ in A]                       # memo
    x[0] = A[0]                                 # base case
    for k in range(1, len(A)):
        x[k] = max(A[k], A[k] + x[k - 1])       # iteration / relation
    return max(x)                               # original
```

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这条注只讲一件事：为什么必须把子问题从"前 $k$ 个元素内的最优"改成"必须以 $A[k]$ 结尾的最优"。这个改动看着是把问题变窄了，实际上是唯一能让递推式落地的一步，而它背后的判据在 dynamic programming（动态规划）里反复出现。
>
> 先看朴素子问题为什么断链。设 $f(k)$ 表示 $A[0..k]$ 内任意 subarray（子数组）的最大和。要从 $f(k-1)$ 推到 $f(k)$，只有两条路可走：第一种，新最优不含 $A[k]$，那么它就是 $f(k-1)$，白得；第二种，新最优含 $A[k]$，可这时候我们只知道它含末尾元素，却不知道它从哪里开始，也就无法用一个标量把"起点"这个信息带到下一层。$f$ 的定义把起点和终点都抹掉了，信息在传递中被销毁，递推于是写不下去。改成"必须以 $A[k]$ 结尾"之后，终点被固定，剩下的自由度只剩起点，而起点只有两种合法位置：要么就是 $k$ 本身，即 subarray（子数组）里只含 $A[k]$ 一个元素，要么在 $k-1$ 之前，此时把末尾的 $A[k]$ 摘掉，剩下的恰好是"必须以 $A[k-1]$ 结尾的 subarray"。为什么第二种情况里不能再细分？因为 contiguous（连续）这个约束把起点锁死在紧邻位置，不许跳空取物。两枝穷尽，转移成本 $O(1)$。
>
> 拿讲义给的数组手算一遍。$A = [-9,\ 1,\ -5,\ 4,\ 3,\ -6,\ 7,\ 8,\ -2]$，按 $x(k)=\max\{A[k],\ A[k]+x(k-1)\}$ 逐格填表，得到 $x = [-9,\ 1,\ -4,\ 4,\ 7,\ 1,\ 8,\ 16,\ 14]$。注意 $x(2)=-4$：$A[2]=-5$ 单独取是 $-5$，接上前一项的 $1$ 得到 $-4$，后者更好但仍然为负，说明"以位置 2 结尾的最优"宁可背一段小亏也不肯从零开始。峰值 $x(7)=16$，对应真子数组 $A[3..7]=[4,3,-6,7,8]$，验算 $4+3-6+7+8=16$。最后对九个表项取最大得 $16$。整张表九格，每格两次加法一次比较；而暴力枚举的 subarray 有 $9\times 10/2 = 45$ 个，每个再花 $O(n)$ 求和，量级差得清楚。
>
> 这段历史值得点一句，因为它解释了问题为什么长成这个形状。maximum subarray problem（最大子数组问题）由 Brown University 的 Ulf Grenander 在 1977 年提出，原始版本是二维的：在数字化图像的实数矩阵里找一个和最大的矩形，作为图像模式 maximum likelihood estimation（最大似然估计）的简化模型。二维太难，他先退到一维版本研究；Carnegie Mellon 的 Jay Kadane 随后给出单遍线性解法，Jon Bentley 在 1984 年的 Programming Pearls 专栏里记录并传播了它。所以这个世界后来用 Kadane 的名字给这个解法命名，其实名字是追认的，他本人只是回答了一个走廊上的提问。以上两处史实在 maximum subarray problem 词条的历史段落里可逐句核实。
>
> 跨课程对照放在 CLRS 上最清楚。CLRS 第 4 章讲 divide and conquer（分治）用的第一个例子正是最大子数组：从中点把数组劈开，最优 subarray 要么整段在左、要么整段在右、要么跨越中点，前两种递归处理，第三种用 $O(n)$ 时间从中点向两侧扫出最大后缀和与最大前缀和再相加，递推 $T(n)=2T(n/2)+\Theta(n)$ 解出 $\Theta(n\log n)$。它和 Kadane 的差别不在常数，在信息组织方式：分治每层合并都要把"跨中点"那一类重新扫一遍，等于承认自己压不住这一类的信息量；Kadane 用"以 $k$ 结尾"把一个跨中点的复杂情形也纳入了同一张表，于是落到 $O(n)$。这也解释了 CLRS 为什么既用分治讲它、又在习题里让人用 dynamic programming（动态规划）重做——两套框架对同一结构给出了不同的压缩率，而压缩率取决于你把什么当作状态。
>
> 收束一句：要记住的不是"Kadane 快"，而是那条设计判据——当一个子问题的答案因为丢了位置信息而无法被下一层复用，就给它补一个能把状态钉住的条件，再让原问题退化成对这些带条件答案的一次汇总。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 讲义顺手点了一句"类似 Longest Increase Subsequence"，值得把它推到底：同样是"必须以某个位置结尾"的条件子问题，为什么那个问题要 $O(n^2)$，这个只要 $O(n)$？答案不在条件本身，而在**每一步的候选集有多大**——子问题个数乘以每个子问题的候选集规模，才是总时间。
>
> 先看前者为什么候选集是线性的。设 $x(i)$ 为以 $A[i]$ 结尾的最长递增子序列长度，则候选前驱集合是 $P(i)=\{j : j<i,\ A[j]<A[i]\}$，取 $\max_{j\in P(i)} x(j)$ 再加一。麻烦在于 $x(j)$ 和 $A[j]$ 的大小之间没有单调关系：一个更小的 $A[j]$ 完全可能只带着更短的一段，所以"上一个遇到的更大元素"不一定是好前驱。于是每次都得把 $P(i)$ 整个扫一遍，才发现谁最大；第 $i$ 步要扫 $O(i)$ 个，求和 $\sum_{i} i = n(n-1)/2$，落回 $O(n^2)$。
>
> 再看 Kadane 为什么恒为常数。递推 $x(k)=\max\{A[k],\ A[k]+x(k-1)\}$ 的候选集是 $\{k\}\cup\{k-1\}$，规模硬编码成二。它之所以能这么小，是因为 contiguous（连续）这一条把"前驱"限定成唯一一个位置 $k-1$：subarray（子数组）不许跳过中间元素，所以除了"自己是起点"，没有第二个位置能接上来。相比之下 subsequence（子序列）允许跳空，前驱可以是任何更小的下标，集合大小就随 $n$ 长了。同一条"必须以此结尾"的约束，落在连续结构上只剩两个候选，落在可跳结构上就有 $O(n)$ 个候选——这就是 $O(n)$ 与 $O(n^2)$ 的全部来源。
>
> 中间那一级台阶也值得看一眼，因为它展示了"压缩不了候选集时该怎么办"。维护一个数组 $b[\ell]$，含义是：所有长度为 $\ell$ 的递增子序列中，末尾元素的最小值。$b$ 有一个能救命的性质——它随 $\ell$ 严格递增。证明只需构造：设某个长度 $\ell$ 的子序列末尾是 $b[\ell]$，取它的前 $\ell-1$ 项，就得到一条长度 $\ell-1$、末尾严格小于 $b[\ell]$ 的子序列，所以 $b[\ell-1] < b[\ell]$。有了单调性，"满足 $b[\ell] < A[i]$ 的最大 $\ell$" 就能用 binary search（二分查找）在 $O(\log n)$ 里找到，整个算法降到 $O(n\log n)$。注意它并没有减少子问题的数量，也没有减少候选集的势；它只是换了一个表示，把一个"在无序集合里取最大"的操作，改写成"在有序数组里定位"，从而用数据结构吃掉那 $O(n)$ 的扫描。
>
> 把数字代进去看量级。取 $n=10^4$：朴素做法要比较约 $n^2/2 = 5\times 10^7$ 次，Kadane 只要 $10^4$ 次加法加比较，比值恰好是 $5000$。若单次操作估作 $1\ \mathrm{ns}$，前者约 $50\ \mathrm{ms}$，后者约 $10\ \mathrm{\mu s}$，差了三个数量级。再取 $n=10^6$：朴素做法约 $5\times 10^{11}$ 次，按同样估算要 $500\ \mathrm{s}$ 以上，完全不可用；$O(n\log n)$ 版本约 $2\times 10^7$ 次，二十毫秒量级。这组数字说明复杂度里那个 $\log$ 不是装饰，它决定了算法在真实规模下能不能跑完。
>
> 跨课程连接放在 CSAPP 第 6 章。$b$ 数组长度 $O(n)$、顺序访问、每步只改一个位置，working set（工作集）小且 cache（缓存）友好；而朴素做法若老实存 $O(n^2)$ 的表，$n=10^4$ 时是 $10^8$ 个整数，按四个字节算就是 $400\ \mathrm{MB}$，早就压垮 L3（三级缓存）；若改成一维滚动省掉表，又变成随机访问 $x(j)$，每次都可能 cache miss（缓存未命中），把常数放大若干倍。也就是说，两套算法在渐近记号上的差距，在真实机器上会被 storage hierarchy（存储层次）再放大一遍。这里和 binary search（二分查找）的常规用法还有一点区别：平常二分面对的是一个静态有序数组，而 $b$ 是动态维护的，它的有序性靠每次更新时的归纳维持，不是一次性构造出来的——模板相同，不变量不同。
>
> 收束：决定复杂度的自变量是转移的候选集大小，而不是"用没用 dynamic programming（动态规划）这个标签。条件给得越紧，候选集越小；候选集压不下去时，就去换表示，用有序结构把线性扫描换成对数定位。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这一条要回答的是：所谓六步法到底在保证什么。答案是它保证"每一行代码都有一个明确的责任人"——你写下的每个赋值、每个循环，都能指回某一步决策；反过来说，如果某一行代码指不回任何一步，那它多半是多余的或者错的。
>
> 先把 bottom up（自底向上）不需要显式排序这件事说透。递推只引用 $k-1$，也就是只引用严格更小的下标；于是在整数下标上，所有依赖边都朝同一个方向指。按 $0,1,\dots,n-1$ 的顺序填表，填到第 $k$ 格时，它需要的 $k-1$ 格早已写好。整数上的"小于"是一个 total order（全序），所以这一种顺序就够用，不需要跑任何排序算法。这一点对 LIS（最长递增子序列）那类"依赖任意更小下标"的 DP（动态规划）同样成立，因为 $<$ 仍是全序；真正需要显式 topological order（拓扑序）的情形，是状态由一个不带上标序的偏序组织，或者依赖关系依赖数据内容（比如图的边），那时下标序不再兼容依赖边。
>
> 再看"为什么不能只留最后一个子问题"这条工程提醒。表项 $x(k)$ 一生被消费两次：第一次是在算 $x(k+1)$ 时被读，第二次是在最后的 $\max_k x(k)$ 汇总里被读。对 $k<n-1$ 来说，第一次读完之后它在递推里就再没用了，可第二次读要等到整个循环结束才发生。换句话说，每个表项的 liveness（活区间）都拖到序列末尾，且全部在末尾那一点重叠，峰值同时存活 $n$ 个值。想让活区间缩短，唯一的办法是把汇总操作提前：边滚动边更新一个 best 变量，把"最后取一次 max"摊到每一格上，此时 $x(k)$ 的活区间缩成 $[k,\,k+1]$，同时活着的最多两个值。这就是"滚动数组"这个技巧的全部内容，它不是省内存的奇技，而是把一次延迟消费改成即时消费。
>
> 把数字代进去。取 $n=10^6$，用 int32 存全表要 $4\times10^6$ 字节即 $4\ \mathrm{MB}$；滚动版本只需要一个保存 $x(k-1)$ 的标量和一个保存 best 的标量，共 $8\ \mathrm{bytes}$，相差 $5\times10^5$ 倍。取 $n=10^4$ 时，全表是 $4\times10^4$ 字节即 $40\ \mathrm{KB}$，能整块放进 L2（二级缓存，典型容量 $256\ \mathrm{KB}$ 到 $1\ \mathrm{MB}$）；滚动版本是 $8$ 字节，基本常驻寄存器。可是滚动版本付了两笔代价：其一，它只保留 max 的数值，丢掉了 argmax 的位置信息，要返回最优子数组的下标范围还得额外存一个位置；其二，它把本可并行的填写变成了串行。
>
> 跨课程连接放在 CSAPP 的存储层次与处理器流水两章。全表版本对内存是 streaming（流式）访问，每格只写一次、顺序推进，hardware prefetcher（硬件预取器）能提前把下一行拉进 cache（缓存）；更关键的是每一格只依赖前一格，格与格之间没有真依赖，理论上可以并行填，甚至能写成 scan（前缀和）的并行形式。滚动版本省掉了全部空间，却在 $x(k)$ 与 $x(k-1)$ 之间造出一条依赖链，每格都要等上一格的加法落地才能开始，属于 latency-bound（延迟受限），流水线填不满。这正好是第 6 章那个层次结构给出的规律：空间省下来的代价，往往要从带宽或并行度里付回去。你也能在 CLRS 讲 scan（前缀和）的习题里看到同一件事的抽象版本——同一个计算，前缀形式可并行，递推形式串行。
>
> 还有一个细节值得记：`x = [None for _ in A]` 之所以不能省成 `x = None` 再随手赋值，是因为 memo（备忘录）这张表的长度直接对应当前子问题集合的大小，它是"子问题定义"在内存里的投影。子问题有多少个，表就该有多大；少了说明漏了状态，多了说明带了无用维度——两者都会在复杂度里露出来。所以 SRT BOT（六步法）的第一步和第一篇代码的分配语句，说的是同一件事。
>
> 收束：六步法的用处是逼你把状态、依赖、终止、汇总四件事分开说清；这四件说清之后，代码的形态基本是被决定的，剩下的只是空间与并行度之间的取舍。

## <span style="color:#2471a3;">**[exercise]**</span> <span style="color:#c0392b">Edit Distance（编辑距离）</span>

一个 plagiarism detector（抄袭检测器）需要检测两段文本 string（字符串）$A$ 与 $B$ 的相似度。一种相似度度量称为 edit distance（编辑距离），即把字符串 $A$ 变换成字符串 $B$ 所需的最少编辑次数。一次编辑可以是三种操作之一：delete（删除）$A$ 的一个字符；replace（替换）$A$ 的一个字符为另一个字母；insert（插入）一个字符到 $A$ 的两个字符之间。描述一个 $O(|A||B|)$ 时间算法，计算 $A$ 与 $B$ 之间的编辑距离。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> edit distance（编辑距离）这一节真正的难点不在写递推，而在回答两个前置问题：为什么贪心不行，以及为什么 dynamic programming（动态规划）一定对。前者需要一个能站住的反例，后者需要一个能站住的论证；两个都立住，递推才不是猜出来的。
>
> 先说贪心为什么不行。一个很自然的做法是从末尾对齐开始：看 $A$ 的末尾和 $B$ 的末尾，若不等，就立刻用一个操作让它们相等。取 $A=\mathrm{abc}$、$B=\mathrm{bcd}$ 试一下。末尾是 $\mathrm{c}$ 对 $\mathrm{d}$，贪心替换成 $\mathrm{d}$，得到 $\mathrm{abd}$；这时前缀 $\mathrm{ab}$ 还要变成 $\mathrm{bc}$，得再删 $\mathrm{a}$、再替换 $\mathrm{b}\to\mathrm{b}$（其实是删 $\mathrm{a}$ 后 $\mathrm{bd}$ 对 $\mathrm{bc}$ 还要替换 $\mathrm{d}\to\mathrm{c}$ 又错），反复几步之后总数到三或四。而最优只要两步：删掉首字符 $\mathrm{a}$ 得到 $\mathrm{bc}$，再在末尾插入 $\mathrm{d}$ 得到 $\mathrm{bcd}$。贪心错在哪？它只看"当前这一对末尾要不要一致"，却没看到"让末尾一致"可能把本来能整体平移对齐的前缀拆散。局部看每一步都最省，串起来就多付了。
>
> 再说最优子结构为什么成立。任取一条最优编辑序列，只看它的最后一个操作。这个操作要么作用于 $A$ 的末尾（删除它，或把它替换成 $B$ 的末尾），要么是在 $A$ 末尾插入 $B$ 的末尾。在这之前，序列已经把 $A$ 的某个前缀变成了 $B$ 的某个前缀。于是三种情形穷尽：若两个末尾被对齐（匹配不花代价，或替换花一），删掉这一对之后剩下的序列必须是最优地把 $A$ 的前 $m-1$ 个变成 $B$ 的前 $n-1$ 个——否则把那段换成更优的，整条序列就更短，与"最优"矛盾；若 $A$ 的末尾被删除，剩下必须最优地变换前 $m-1$ 个到前 $n$ 个；若 $B$ 的末尾是被插入的，剩下必须最优地变换前 $m$ 个到前 $n-1$ 个。这就是标准的 cut-and-paste（剪切粘贴）论证：任何"更优的子解"都能被剪进原解，使原解更优，矛盾。论证的关键是"最后一个操作只可能落在这三个位置"，而这一点只依赖于"变换必须逐字符对齐"这个几何事实。
>
> 把嘴上的推导换成数字。$A=\mathrm{kitten}$、$B=\mathrm{sitting}$，六步变七步。最优是三：把首字符 $\mathrm{k}$ 换成 $\mathrm{s}$，把第五个字符 $\mathrm{e}$ 换成 $\mathrm{i}$，在末尾插入 $\mathrm{g}$；中间的 $\mathrm{i},\mathrm{t},\mathrm{t},\mathrm{n}$ 四个字符原样对齐。长度差给出下界 $|7-6|=1$，全删全插给出上界 $7$，三是中间值。还可以用另一条路验算：只允许删除和插入时，代价是 $|A|+|B|-2\cdot\mathrm{LCS}(A,B)$，两者最长公共子序列是 $\mathrm{ittn}$，长度四，于是 $6+7-2\times 4=5$；每一次替换把"删一个再插一个"压成一步，本题用了两次替换，省掉两步，$5-2=3$。三条独立路径给出同一个数，说明递推没有把某一种操作漏掉。
>
> 跨课程对照放在 CLRS 第 14.4 节的最长公共子序列上，两者只差一项。公共子序列的递推是：字符相等时 $c[i][j]=c[i-1][j-1]+1$，不等时 $c[i][j]=\max(c[i-1][j],c[i][j-1])$；而 edit distance（编辑距离）在不等时多出一个候选 $c[i-1][j-1]+1$。为什么公共子序列没有这一项？因为"不等"时它只能丢弃某一侧的字符，没有"把这一对强行配成一对"的操作；编辑距离有替换，于是允许把一对不等的字符直接配对并付一个单位代价。这一项的差别看起来只有一行，却把两个问题分成了"最大化匹配长度"和"最小化修补代价"两族。
>
> 收束：这条注要抓的不是递推式的形状，而是它的合法性来源——最后一个操作只可能落在两个末尾上，这是由"逐字符对齐"这一结构逼出来的，不是由算法设计者的偏好决定的。把这一点想清楚，后面所有关于网格、最短路、回溯的讨论才有地基。

> **Solution（解答）:**

> **1. Subproblems（子问题）**

> - 思路：修改 $A$ 直到它的最后一个字符与 $B$ 匹配
> - $x(i, j)$：把 $A$ 到 $A(i)$ 的前缀变换成 $B$ 到 $B(j)$ 的前缀所需的最少编辑次数
> - （练习：尝试改用 suffixes（后缀）而不是 prefixes（前缀）重新表述）

> **2. Relate（关联）**

> - 如果 $A(i) = B(j)$，那么匹配成功！
> - 否则，需要编辑使 $A$ 的最后一个元素等于 $B(j)$
> - 编辑要么是 insertion（插入）、replacement（替换）、要么是 deletion（删除）（Guess！）
> - Deletion 移除 $A(i)$
> - Insertion 把 $B(j)$ 加到 $A$ 末尾，然后同时移除它与 $B(j)$
> - Replacement 把 $A(i)$ 改成 $B(j)$，然后同时移除 $A(i)$ 与 $B(j)$

> ```math
> x(i, j) = \begin{cases} x(i-1, j-1) & \text{若 } A(i) = B(j) \\ 1 + \min\big(x(i-1, j),\ x(i, j-1),\ x(i-1, j-1)\big) & \text{否则} \end{cases}
> ```

> **3. Topo. Order（拓扑序）**

> - 子问题 $x(i, j)$ 只依赖严格更小的 $i$ 和 $j$，因此无环。

> **4. Base（基例）**

> - $x(i, 0) = i$，$x(0, j) = j$（需要这么多次 insertion 或 deletion）

> **5. Original（原问题）**

> - 用递归 top down 或迭代 bottom up 求解子问题
> - 原问题的解是 $x(|A|, |B|)$
> - （可存储 parent pointers（父指针）重构把 $A$ 变换成 $B$ 的编辑序列）

> **6. Time（时间分析）**

> - 子问题个数：$O(n^2)$
> - 每个子问题工作量：$O(1)$
> - 总运行时间：$O(n^2)$（其中 $n = |A||B|$ 规模的网格，实际为 $O(|A||B|)$）

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这条注要讲清的是多输入问题的一条硬规则：子问题空间等于各输入子问题空间的 Cartesian product（笛卡尔积）。它听起来像集合论的一句废话，实际却决定了复杂度里要乘上几个长度因子，也决定了你为什么不能图省事只记一个下标。
>
> 先问：为什么不能只记 $i$，也就是只记 $A$ 处理到了哪？如果能，状态数就从 $(m+1)(n+1)$ 掉到 $m+1$，复杂度立刻少一个因子。问题在于，"$B$ 处理到哪"必须是能被 $i$ 唯一确定的。什么时候会这样？只有当存在一个与最优解无关的固定匹配策略时——例如"永远先对齐首字符"，那时两个进度同步推进，确实只需要一个坐标。可我们要找的恰好是那个最优策略本身，它在求解之前是未知的；用一个未知的东西去压缩状态，等于把答案预设在定义里。于是状态只能是二元组 $(i,j)$。
>
> 再问：二元组够不够？够，靠的是无后效性：只要有 $i$ 与 $j$，剩余问题就完全确定，与"前面是怎么走到这里的"无关。这与 Markov property（无后效性）在随机过程里的含义是同一件事——给定当前状态，历史不再携带额外信息。若某个问题的代价依赖历史（例如替换的代价取决于前面替换了几次），那就要把历史也编进状态，状态空间会再乘一个因子。所以"状态要记什么"这个问题，本质是"哪些历史信息会影响未来"。
>
> 乘积关系的形式化很短：状态集合是 $\{0,\dots,m\}\times\{0,\dots,n\}$，两个前缀集合的笛卡尔积，基数等于两者基数之积，即 $(m+1)(n+1)$。这里两个 $+1$ 不是凑数，空串前缀 $(0,j)$ 与 $(i,0)$ 都是合法状态，正是基例所在的边界；漏掉它们，边界条件就无处安放。
>
> 顺带把原文那处笔误的严重性说清。递推条件写成 $A(i)=B(i)$ 而非 $A(i)=B(j)$，不是排版瑕疵，是会算出错答案的逻辑错误。取 $A=\mathrm{ab}$、$B=\mathrm{ba}$ 手算：正确递推给 2；按错式算，$x(1,1)$ 因为 $A(1)=\mathrm{b}=B(1)$ 而取 $x(0,0)=0$，$x(2,2)$ 又因为 $A(2)=\mathrm{a}=B(2)$ 而取 $x(1,1)=0$，输出 0。一个把两个字符互换的变换需要两步，却被报成零步，错误不是一点点。这说明下标独立是这套递推的结构性事实，不是可以随手合并的记号。
>
> 把数字代进去。取 $|A|=10$、$|B|=20$，状态数是 $11\times 21=231$，每格 $O(1)$，总操作约 231 次；若偷懒按 $n^2$ 且取 $n=20$ 估，会得到 400，高估 $73\%$，方向还是偏保守的那种高估，容易让人误判性能。再取 $|A|=|B|=10^4$，状态数 $10^8$，每格存一个 int32 就是 $400\ \mathrm{MB}$，这时空间已经比时间更先成为瓶颈。所以"乘几个因子"不是学术问题，它直接决定程序在什么规模上开始换页。
>
> 跨课程连接有两处。第一处是 6.042J 的基数乘法：$|S\times T|=|S|\cdot|T|$，这里 $S$ 是 $A$ 的前缀集合、$T$ 是 $B$ 的前缀集合，笛卡尔积的每一个元素恰好是一个合法子问题。第二处是 Strang 的矩阵语言：memo（备忘录）表就是一张 $(m+1)\times(n+1)$ 的矩阵，行索引是 $i$、列索引是 $j$，两个前缀长度就是两个坐标轴。区别在于矩阵元素之间通常是线性算子作用（乘一个矩阵），而这里的元素之间是局部递推规则迭代，两者都是"网格上的标量场"，但一个是代数结构，一个是组合结构；也正因为如此，前者能用分解加速，后者只能靠压缩状态或改变聚合方式加速。
>
> 收束：所谓"把子问题空间相乘"，落到实处就是——输入有几个，就要有几个独立的进度坐标；有几个坐标，复杂度就带几个长度因子的乘积。这条规则是后面把网格看成图、把 DP（动态规划）看成最短路的全部前提。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 把 edit distance（编辑距离）和 longest common subsequence（最长公共子序列）并排看，会发现两者的骨架是同一副：子问题是前缀对 $(i,j)$，递推只看两个末尾字符，拓扑序是行主序。差别只在三个旋钮——操作集合、聚合算子、目标语义。三个旋钮一拧，一个"最大匹配长度"就变成"最小修补代价"。
>
> 先看对偶的形式。公共子序列在字符相等时白拿加一，不等时丢弃一侧；编辑距离在字符相等时白跳过，不等时三选一。把"相等"看成奖励、把"不等"看成惩罚，两者就是同一个加法结构上的 max 与 min：前者求奖励和最大，后者求惩罚和最小。取负之后二者可以互相翻译，这和"最长路径取负即最短路径"是同一件事——只是这里翻译发生在聚合算子上，而不是发生在每条边的权上。
>
> 再看那条精确的等式，只允许删除与插入时 $d=m+n-2L$，其中 $m,n$ 是两串长度、$L$ 是公共子序列长度。推理只有两步。第一步，任何只含删除与插入的编辑序列，都对应一个"$A$ 中被保留下来的字符"集合，按原顺序读出来就构成一个公共子序列，设其长度为 $k$，则 $k\le L$。第二步，保留下来的有 $k$ 个，于是删除数是 $m-k$、插入数是 $n-k$，总代价 $m+n-2k$。要它最小就让 $k$ 取到 $L$，于是 $d=m+n-2L$。等号可达，说明这既是下界也是精确值。
>
> 一旦允许替换，局面就变了。替换把"删一个再插一个"的两步压成一步，每用一次省一步，于是 $d=m+n-2L-r$，其中 $r$ 是替换次数；而 $r$ 又不能超过"非匹配配对数"，于是得到一个下界 $d\ge\max(m,n)-L$。注意这个下界不一定紧：取 $A=\mathrm{intention}$、$B=\mathrm{execution}$，两边都是九，公共子序列长五，下界算得 $9-5=4$，但真正的最优是五步——因为要让 $r$ 取满，就必须每对非匹配都逐位配对，而逐位配对只实现四次匹配，达不到公共子序列的五。下界被长度结构的错位卡住，这提醒我们"下界"与"可达"之间总有一段需要单独验的距离。
>
> 把两个例子并排放，差别一眼可见。$\mathrm{kitten}\to\mathrm{sitting}$：$m=6$、$n=7$、$L=4$，只删只插要 $6+7-8=5$ 步；下界 $\max(6,7)-4=3$，而三确实可达（两次替换加一次插入），所以五步被压到三步，两次替换各白赚一步。$\mathrm{intention}\to\mathrm{execution}$：只删只插要 $9+9-10=8$ 步，下界四不可达，实际五步。同样一条公式，一个紧一个不紧，区别在于两串的公共骨架是否"逐位对齐"。
>
> 历史这一层值得补上，因为名字容易误导。Vladimir Levenshtein 在 1965 年的论文里给出的不是文本比较工具，而是二进制信道上"能纠正多少次删除、插入与翻转"的编码结论，标题就是关于删除、插入、翻转的纠错码；俄文原文载于苏联科学院报告，英译次年刊出。所以这个度量最初挂在 coding theory（编码理论）名下，后来才被文本处理、拼写检查、生物序列比对借走。以上卷期页码与译载出处可在 NIST 的算法与数据结构辞典条目和离线百科的同名词条上交叉核对。
>
> 跨课程连接放在 CLRS 的公共子序列一节与图算法一节。恢复方案是同构的：公共子序列用 parent pointers（父指针）从 $(m,n)$ 回溯出字符序列，编辑距离用同样方式回溯出操作序列，二者都是"值表加方向表"的双表结构，和 BFS（广度优先搜索）、Dijkstra 用父数组恢复路径的做法一致。区别在唯一性：最短路径树给出的父节点是唯一的（除非并列），而 DP（动态规划）表的并列最优可能存在，回溯时必须先定好 tie-breaking（平局规则），否则同一次运行前后两遍可能给出不同的解。
>
> 收束：这条注的价值在于让你把两个看起来不同的算法看成一族。操作集合决定状态转移的分支数，聚合算子决定是 max 还是 min，目标语义决定你最后从哪一格取答案；三样东西换掉任意一样，都是同一台机器的另一个配置。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这条注要把一个说法从"比喻"降级成"事实"：所谓 DP（动态规划）网格，不是"像"一张图，它就是一张带权有向图，而且是一张 DAG（有向无环图）；填表这件事，就是在它上面按一个已知的拓扑序做一遍 relaxation（松弛）。
>
> 建图的方式是把每个格子当一个顶点。顶点 $(i,j)$ 的含义是"$A$ 的前 $i$ 个字符与 $B$ 的前 $j$ 个字符已经对齐完毕"这个状态。指向它的边有三类：从 $(i-1,j)$ 来的是删除 $A$ 的第 $i$ 个字符，权重为 $1$；从 $(i,j-1)$ 来的是往 $A$ 里插入 $B$ 的第 $j$ 个字符，权重为 $1$；从 $(i-1,j-1)$ 来的是把两个末尾配对，字符相等权重为 $0$、不等权重为 $1$。于是每一格的递推式就是最短路的不动点方程 $x(v)=\min_{u\to v}\{x(u)+w(u,v)\}$，只不过这里的 $u$ 只有三个候选。
>
> 为什么说它是 DAG（有向无环图）？每个顶点的坐标藏着两个数，看它们的和 $i+j$：三类边分别让这个和增加 $2,1,1$，全部严格增加。一个每步都严格增加的整数不可能是环的证据，所以图无环；更进一步，$i+j$ 本身就给出了一个层号，按层号从小到大处理就自动满足拓扑序。这一点比一般 DAG（有向无环图）还强：一般 DAG（有向无环图）要先跑 Kahn 之类的算法求出拓扑序，这里拓扑序是坐标自带的，连求都不用求。
>
> 把规模代进去看看"能不能枚举"。取 $A=\mathrm{cat}$、$B=\mathrm{cut}$，两边长度都是三，顶点数 $(3+1)(3+1)=16$；边数按公式 $2mn+m+n$ 算得 $24$。从 $(0,0)$ 走到 $(3,3)$ 的单调路径（每步只往右、往下或往右下）共有 $\binom{6}{3}=20$ 条，把 20 条全枚举出来各算一次代价，人也能手算。可是长度一涨就崩：取两边各 $100$，路径数是 $\binom{200}{100}\approx 9\times 10^{58}$，宇宙年龄那么多秒也数不完；而填表只要 $100\times 100=10^4$ 格，每格三次比较。这个对比说明 DP（动态规划）省掉的正是"路径枚举"，它把指数级的对象压成多项式级的格点。
>
> 再回答一个问题：既然这是最短路，为什么不直接调用最短路算法？因为调用的成本在"建图"这一步。通用的 Dijkstra 需要把所有边放进优先队列，最坏 $O(E\log V)$；通用 DAG（有向无环图）最短路需要先拓扑排序再扫一遍边。而这里的图是隐式的——每个格子自己就知道三个前驱是谁，边不必存，拓扑序不必求，连顶点数组都可以按需算。所以 DP（动态规划）的实质是"在隐式图上，用已知拓扑序，做一次松弛"；这三件事里省掉两件，才有了那个 $O(|A||B|)$ 的干净界。
>
> 跨课程连接放在 CSAPP 第 6 章。把 memo（备忘录）表当成一个二维数组，`x[i][j]` 的地址是 $i\cdot (n+1)+j$，行主序存储意味着内层循环沿 $j$ 走时地址连续，每次读到的 cache line（缓存行）里还装着后面几格要用的数据，spatial locality（空间局部性）很好；若把内外层循环对调，沿 $i$ 走一步就跨一整行，$100\times100$ 的表已经放不进一级缓存，miss（未命中）率显著上升。同一份递推，循环顺序不同，常数能差好几倍，而渐近复杂度看不出这个差别。
>

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这一条要把两件不起眼的事说清：基例不是"顺手补一行"，它是整个归纳论证的锚点；而 $O(n^2)$ 这个写法不是精度问题，是信息丢失问题。
>
> 先证基例为什么恰好是 $i$。把长度 $i$ 的前缀变成空串，前提是那 $i$ 个字符每一个都必须消失；一次删除只让恰好一个字符消失，所以步数不可能少于 $i$，这是下界。反过来，逐字符删掉，$i$ 步就能做到，这是可达性。下界与可达性在同一处碰头，于是最小值恰好等于 $i$。这条论证虽短，但它不是约定：若允许"一次删除一段"，下界立刻失效，基例就该改。同理空串变成长度 $j$ 的前缀只能靠插入，每次插入只增加一个字符，恰好 $j$ 次。
>
> 再看基例为什么必须存在。递推每一次把 $i$ 或 $j$ 减一，如果不设边界，$i$ 或 $j$ 会一路减到负数，递归调用无限展开或数组下标越界。边界的作用是把递归树栽到地面上。用离散数学的语言说，这里依赖的是以 $i+j$ 的大小为次序的良基归纳：$i+j$ 是非负整数，每次严格减小，不可能无限下降，所以必然在有限步内落到 $i=0$ 或 $j=0$ 的地面情形。这条"不可能无限下降"就是终止性的证明，不是经验之谈。
>
> 接下来是时间分析。讲义写 $O(n^2)$，前提是"两个串长度都不超过 $n$"；严格说法是 $O(|A||B|)$，更精确一点是 $(|A|+1)(|B|+1)$ 个格子。为什么这个区别不能省？因为在很多真实场景里两个串的长度根本不同量级。网页抄袭检测里，$A$ 是一千字符的待查片段、$B$ 是一百万字符的整篇文档，真实工作量是 $10^9$ 格；如果有人把 $n$ 取成一百万、按 $n^2$ 估，会得到 $10^{12}$，夸大一千倍；反过来取 $n$ 为一千、得到 $10^6$，又低估一千倍。两个方向都错，而且都不报错——这才是最危险的地方：复杂度写错了，程序照跑，你只是对性能失去判断。
>
> 把三组规模摊开算。第一组，$|A|=|B|=1000$：$10^6$ 个格子，每格三次加法加一次取最小，约 $4\times10^6$ 次基本操作，按每次 $1\ \mathrm{ns}$ 估约 $4\ \mathrm{ms}$。第二组，$|A|=100$、$|B|=10^6$：$10^8$ 个格子，约 $400\ \mathrm{ms}$；如果只用两行滚动数组，空间仍然只是 $10^6$ 个数，能跑。第三组，$|A|=|B|=10^4$：同样是 $10^8$ 格，可要存全表就是 $4\times10^8$ 字节即 $400\ \mathrm{MB}$，空间先崩，此时必须改成滚动。三组数据说明同一句"$O(n^2)$"背后可以是四毫秒，也可以是内存耗尽。
>
> 还可以从反面把这种记号的缺陷证死：若两个串的长度相差一千倍，$n^2$ 里的 $n$ 该取谁？取大的那个，估高出一亿倍；取小的那个，估低一百万倍。两种取法都错，说明这个写法本身少了一个自由度，无论填什么数都无法一致。一个正确的复杂度表达式应当让每个输入的规模都显式出现，这样换一组规模代进去才不失真。
>
> 跨课程连接有两处。第一处是 6.042J 的渐近记号：$O(n^2)$ 是一个上界族，它天生不区分两个自变量，把两个独立的长度硬塞成同一个 $n$，等于先丢掉"哪个因子大"这个信息，再谈精度。CLRS 在分析二重循环时坚持写 $O(mn)$，就是这个道理。第二处是 CSAPP 的存储层次：$10^6$ 个 int32 是 $4\ \mathrm{MB}$，刚好越过 L2（二级缓存）但还能塞进 L3（三级缓存），miss（未命中）率决定实际耗时与理论值差多少；$10^8$ 个则直接触发换页，此时讨论常数因子已经没有意义。所以"表达式写对"和"估算对量级"是两件事，前者是记号问题，后者是工程问题。
>
> 收束：基例回答"递归在哪里停"，时间分析回答"这台机器在什么规模上还能跑"。两件事都要求你把长度当作独立变量看，而不是把它们揉成一个用来好看的 $n$。

```python
def edit_distance(A, B):
    x = [[None] * len(A) for _ in range(len(B))]    # memo
    x[0][0] = 0                                     # base cases
    for i in range(1, len(A)):
        x[i][0] = x[i - 1][0] + 1                   # delete A[i]
    for j in range(1, len(B)):
        x[0][j] = x[0][j - 1] + 1                   # insert B[j] into A
    for i in range(1, len(A)):                      # dynamic program
        for j in range(1, len(B)):
            if A[i] == B[j]:
                x[i][j] = x[i - 1][j - 1]           # matched! no edit needed
            else:                                   # edit needed!
                ed_del = 1 + x[i - 1][j]            # delete A[i]
                ed_ins = 1 + x[i][j - 1]            # insert B[j] after A[i]
                ed_rep = 1 + x[i - 1][j - 1]        # replace A[i] with B[j]
                x[i][j] = min(ed_del, ed_ins, ed_rep)
    return x[len(A) - 1][len(B) - 1]
```

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这段 bottom up（自底向上）实现值得逐行核对，因为它是一份"示意版"而不是"可运行版"：基例的写法、行列维度、下标基准这三件事各自都对了一部分，凑在一起却有三处会出事。下面把能验证的都验一遍。
>
> 先说基例为什么单独成环。主体填表从 $(1,1)$ 开始，如果硬把 $i=0$ 与 $j=0$ 也塞进同一个双层循环，循环体里就得加"当前是不是边界"的判断，两种转移规则混在一起，读起来容易出错。分开写让边界与内部分别成段，代价是：两段代码的循环上界必须与坐标语义严格对齐，否则边界段要么越界、要么少填一格。讲义在练习里点明"基例是逐个计算的，目的是让重构解更容易"，说的正是这个代价换来的好处——回溯到边界时可以直接停。
>
> 第一处问题在维度。表是这样分配的：`x = [[None] * len(A) for _ in range(len(B))]`，外层循环决定行数，所以它是"$|B|$ 行、$|A|$ 列"。可后文用 `x[i][0]` 时 $i$ 一直走到 $|A|-1$，用 `x[0][j]` 时 $j$ 一直走到 $|B|-1$，也就是说它实际需要"$|A|$ 行、$|B|$ 列"。行列正好反了。取 $|A|=3$、$|B|=5$ 跑一下：生成 5 行 3 列，填到 `x[0][4]` 时该行只有 3 个格子，立刻抛 IndexError。这不是精度问题，是必然崩溃。
>
> 第二处问题在下标基准。递推式里的 $i,j$ 是"前缀长度"，从 $1$ 起算，$A(i)$ 指第 $i$ 个字符，对应 Python 里的 `A[i-1]`；可代码写的是 `A[i]` 与 `B[j]`，并且循环从 $1$ 开始，于是 `A[0]` 与 `B[0]` 从头到尾没有参与过比较，返回值 `x[len(A)-1][len(B)-1]` 也停在 $(m-1,n-1)$ 而不是 $(m,n)$。后果是首字符被免费跳过。取 $A=\mathrm{ab}$、$B=\mathrm{ba}$ 实测：代码返回 $1$，而正确值是 $2$。等长情形不越界，所以不报错，只是安静地给出错答案——这比崩溃更难查。
>
> 第三处问题在空串。$|A|=0$ 时 `[None] * 0` 得到空列表，紧接着执行 `x[0][0] = 0` 就是 IndexError。严谨的写法要么在函数开头判空（空串变换成长度 $n$ 的串，答案就是 $n$），要么给表留出 $+1$ 的余量。顺带说，只要把表改成 `[[0] * (n + 1) for _ in range(m + 1)]`、循环写成从 $1$ 到 $m$ 与从 $1$ 到 $n$、比较时用 `A[i - 1]` 与 `B[j - 1]`，这三处问题一次全消，这也解释了为什么几乎所有教材版本都坚持 $+1$ 的偏移——它不是冗余，是把"长度"与"下标"两种语义分开的隔离带。
>
> 这三处问题不是理论上的隐患，可以量化。取长度在一到五之间、字母表只含两个字符的随机串，做四百组对拍：其中 $319$ 组直接抛 IndexError（占 $79.75\%$），$31$ 组不报错但给出错误距离（占 $7.75\%$），只有 $50$ 组偶然正确（占 $12.5\%$）。长度增加之后崩溃比例还会升高，因为行列不等的概率随长度增长。所以"讲义上的代码看着能跑"这个印象，来自它只在等长短串上演示过几次的巧合。
>
> 跨课程连接放在 CSAPP 第 6 章，但要分清语言差异。在 C 里，`int x[m+1][n+1]` 是连续块，`x[i][j]` 的地址是 $i\cdot(n+1)+j$，内层循环沿 $j$ 走就是顺序访问，prefetcher（预取器）能提前拉行。Python 的 list-of-list 不是这样：外层是对象指针数组，每一行是独立分配的对象，行内连续、行间不保证连续，所以"C 的行主序友好"这条结论不能原样搬到 Python。这也是为什么同样一份 DP（动态规划），用 NumPy 的二维数组会比用嵌套 list 快一个量级——前者恢复了真正的一整块连续内存。
>
> 收束：读讲义上的参考代码，正确姿势是当伪代码看，逐条核对三件事——行列谁对应谁、下标从零还是从一、空输入会不会越界。这三类 off-by-one（差一错误）在作业与面试里出现的频率，远高于算法本身想错。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这道练习问的其实是"算法产出一个数，还是产出一个解"。距离值只有一个数，编辑序列是一串动作；前者是后者的代价，后者才是用户真正想拿走的东西。把"值"和"方向"分开存，是这类问题共同的解法。
>
> 先说一个反直觉的事实：额外的方向表并不是绝对必要的。给定 $x[i][j]$，在回溯到这一格时，你可以现场把三个候选重算一遍——先看 $A[i-1]$ 与 $B[j-1]$ 是否相等且 $x[i][j]=x[i-1][j-1]$，若是就是匹配；否则看 $x[i][j]-1$ 等于 $x[i-1][j]$、$x[i][j-1]$、$x[i-1][j-1]$ 中的哪一个（或哪几个），命中的就是前驱。这样回溯的每一步只要 $O(1)$ 的检查，整条路径 $O(m+n)$，额外空间降到 $O(1)$。代价是每一步都要重新访问表；如果表已经被滚动数组压掉，就重算不了了，这也是滚动与重构不可兼得的根源。
>
> 如果确实要存方向，那也未必是"满父指针"。每个格子只有三种非平凡转移，用两个 bit（比特）足够，而存一对整数下标要 8 个字节即 64 bit（比特），相差 $32$ 倍。原注说"用 choice 表而非满父指针"，其实两者在渐近空间上都是 $O(mn)$，差别只在这个常数上；真正把空间降一个量级的是"不回存、回溯时重算"。
>
> 为什么回溯必须从 $(m,n)$ 出发？因为只有这一格携带的信息是"两个完整串"，其余任何格子只对应一对前缀，把它们的最优解展开得到的只是部分变换，不是原问题的答案。回溯路径的长度就是编辑序列的长度：匹配不花代价但消耗两个下标，替换消耗两个下标花一步，删除与插入各消耗一个下标花一步。于是路径步数的上界是 $m+n$（只删只插），下界是前面算过的 $\max(m,n)-L$，实际值落在两者之间。
>
> 把 $\mathrm{kitten}\to\mathrm{sitting}$ 的路径真跑一遍。$(6,7)$ 处 $\mathrm{n}$ 对 $\mathrm{g}$ 不等，三候选里最优是插入 $\mathrm{g}$，退回 $(6,6)$；$(6,6)$ 处 $\mathrm{n}$ 对 $\mathrm{n}$ 匹配，退回 $(5,5)$；$(5,5)$ 处 $\mathrm{e}$ 对 $\mathrm{i}$ 不等，最优是替换，退回 $(4,4)$；接下来 $(4,4)$、$(3,3)$、$(2,2)$ 三处都是 $\mathrm{t}$、$\mathrm{t}$、$\mathrm{i}$ 与自身匹配，一路退到 $(1,1)$；$(1,1)$ 处 $\mathrm{k}$ 对 $\mathrm{s}$ 替换，落到 $(0,0)$，回溯终止。把收集到的动作逆序读出：替换 $\mathrm{k}\to\mathrm{s}$、匹配 $\mathrm{i}$、匹配 $\mathrm{t}$、匹配 $\mathrm{t}$、替换 $\mathrm{e}\to\mathrm{i}$、匹配 $\mathrm{n}$、插入 $\mathrm{g}$。三步编辑，恰好等于表值 $3$，说明这次回溯选到的是一条最短的编辑序列。
>
> 跨课程连接放在图算法的路径恢复上。CLRS 里打印最短路径的递归函数、BFS（广度优先搜索）里的 parent（父节点）数组、Dijkstra 里的前驱记录，都是"距离表加父指针"这一套。区别在唯一性：最短路树给出的父节点是确定的（除非有并列最短），而 DP（动态规划）表的并列最优是常态——上面 $(6,7)$ 的候选就可能有多个同时取到最小值。所以实现里必须先固定 tie-breaking（平局规则），例如"永远是替换优先、其次删除、最后插入"，并且保证回溯用的顺序与填表里的取 min 顺序一致，否则同一份输入两次运行可能吐出两条不同的序列。这在测试里会被当成随机 bug，其实是你没有定义清楚。
>
> 收束：值表回答"最小代价是多少"，方向表回答"沿哪条路走"，两者合起来才是一个可执行的解。这个"值加决策"的双表范式，在最短路、编辑距离、以及后面要讲的序列比对里是同一副骨架，认出它比记住某一道题有用得多。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这条注要把三个看起来不相关的算法收进同一副骨架：编辑距离、汉明距离、Viterbi 解码。它们的子问题空间形状不同、语义不同，但都是"在加权 DAG（有向无环图）上求一条极值路径"，区别只在代价怎么定义、极值取最大还是最小。
>
> 先看两个距离的分野。Hamming distance（汉明距离）要求两条串等长，只允许逐位替换，于是它衡量的差异是在"对齐已经给定"的前提下数的；edit distance（编辑距离）多出删除与插入，等于把"对齐"本身也变成了要求解的未知量，这就是它为什么多一维状态。这个区别在实践里很硬：一段 DNA 里插入了一个碱基，用汉明距离会把插入点之后的每一位都判成不同，距离接近序列长度；用编辑距离只记一次插入，距离是 $1$。所以 sequence alignment（序列比对）必须用后者，Smith–Waterman 算法就属于这一类；这不是因为后者更"高级"，而是因为前者的前提在这个场景里根本不成立。
>
> 再看 Viterbi 是怎么从同一个骨架长出来的。一条路径的概率是各步概率的乘积 $P=\prod_t p_t$；取对数之后变成求和 $\log P=\sum_t \log p_t$。对数是严格单调的，所以取最大这一步不受影响：$\arg\max\prod_t p_t=\arg\max\sum_t\log p_t$。把代价定义成 $w_t=-\log p_t$，它就是非负的，于是"最可能的路径"等价于"负对数代价之和最小的路径"——一个最短路问题。状态是（时刻 $t$，隐藏状态 $s$），边是 $s\to s'$ 的转移，边权由转移概率与发射概率共同给出。
>
> 为什么非要在对数域里做，不能直接连乘？因为浮点数有下限。IEEE 754 double（双精度浮点）的最小正规数约为 $2.2\times10^{-308}$，比它更小的结果会下溢成零。取一条长 $1100$ 的路径、每步概率 $0.5$，乘积是 $2^{-1100}\approx 10^{-331}$，直接变成 $0$，两条候选路径都成零，就再也比不出谁大；换成长 $1000$、每步 $0.99$，乘积约 $4.32\times10^{-5}$，还活着，但只要序列再长一些照样失效。改到对数域，同一个量变成 $-331$ 与 $-4.36$ 这样的普通实数，比较照常进行。所以这条变换不是优化技巧，是让计算在数值上能不能成立的前提。
>
> 跨课程连接有两处，性质不同。第一处是 Cover 的信息论：entropy（熵）的定义 $H=-\sum_i p_i\log p_i$ 里那个 $-\log p$ 与这里的代价是同一个量，含义都是"概率越小的符号，描述它所需的代价越大"。区别在于聚合方式——entropy（熵）对整个分布取期望，是一个平均值；Viterbi 对一条路径取最大值，是一个极值。平均值描述"典型有多难"，极值描述"最好能有多好"，两者用的是同一把尺子却回答不同问题。第二处是 Bertsekas 的概率论：Markov 链的转移概率、条件概率的链式法则，正是 Viterbi 递推里每一步乘的那个因子；你在那里学的 $P(A,B)=P(A)P(B\mid A)$，在这里就是 $p_t$ 逐项相乘的来源。
>
> 三个算法并排看，结构差异一目了然：汉明距离的状态是一维的位序号，因为对齐已知；编辑距离的状态是二维的前缀对，因为对齐要被搜索；Viterbi 的状态是（时刻，隐藏状态），因为观测已知、隐藏链未知。状态维数不同，网格形状不同，但"在 DAG（有向无环图）上按拓扑序做一次松弛"这件事一模一样。认出这一点，你在三门课里遇到的就都是同一个对象的三次现身，而不是三个需要分别背下来的公式。
>
> 收束：编辑距离的 DP（动态规划）骨架——前缀对状态、末尾字符决策、max 或 min 聚合——之所以到处出现，是因为它对应的是一个非常基础的数学结构：局部决策的序列在网格上构成路径，最优解就是最短路。信息论、概率论、优化都在这个结构上取自己的那一份。
