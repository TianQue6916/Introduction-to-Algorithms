# 编辑距离：为什么「局部规则」替代不了 DP 的三分支

> <span style="color:#7f8c8d;">回应你在 Recitation 16 第三个问题（Edit Distance）上的挑战——「用局部邻居比对把 3 分支压成 1 分支、把复杂度降到 O(n)，为什么不这么做？」这里给出标准反驳：一个程序验证过的反例 + 推广构造 + 理论下界。</span>

---

## 1. 先纠正一个误解：DP 不是指数级，3 分支不是问题所在

你以为「每个子问题 3 个分支」会导致指数爆炸，所以要压成 1 分支。这是误会：

- 编辑距离 DP 的状态是 $(i,j)$，共 $O(nm)$ 个；
- 每个状态 3 个分支（删除 / 插入 / 替换）是**常数**；
- 记忆化后每个状态只算一次，总复杂度 $O(nm)$，$n=m$ 时 $O(n^2)$——**不是指数级**。

所以「把 3 分支压成 1」**不是**降低复杂度的关键。复杂度来自**状态数** $O(nm)$（两个序列所有前缀对的乘积），不来自分支数。你想把 $O(n^2)$ 降到 $O(n)$，这才是真正的诉求——但它做不到，见第 4、5 节。

---

## 2. 你的规则是什么（先复述，避免稻草人）

扫描 $A$、$B$，对当前对准的字符 $A[i]$ 与 $B[j]$，看它**前后邻居**与 $B$ 对应位置的匹配情况：

- 前后与 $B$ 相同、仅当前不同 → **替换**；
- 当前字符和后面字符与 $B$ 的相邻位置相同 → **插入**；
- 该字符前后与 $B$ 的相邻位置相同 → **删除**。

本质：用**长度固定的局部窗口**猜测最优操作，从而把 DP 的「枚举三分支」换成「每步一个确定动作」。

---

## 3. 反例：`A = "aaaa"` → `B = "bbba"`（程序验证，手工可算）

**最优解 = 3 步**：替换 $A[0], A[1], A[2]$ 三个 `a` 为 `b`，保留 $A[3]$ 的 `a`，得到 `bbba`。

**你的局部规则会走 5 步**，关键错在第 3 步：

| 步 | 动作 | 对错 |
|---|---|---|
| 1 | 替换 $A[0]$ `a→b` | ✅ |
| 2 | 替换 $A[1]$ `a→b` | ✅ |
| 3 | 看到 $A[2]$=`a` 与 $B[3]$=`a` 相同 → **插入** `b`，想让 $A[2]$ 去对齐 $B[3]$ | ❌ 错在这里 |
| 4 | 匹配 $A[2]$=`a` == $B[3]$=`a` | ✅ |
| 5 | $A[3]$=`a` 被孤立，只能**删除** | ❌ 多余 |

**错在哪一步？** 第 3 步。你的规则看到「$A[2]$ 和 $B[3]$ 局部相同」，就急着让它们对齐，牺牲了 $A[3]$。而全局最优是：**让 $A[3]$ 对齐 $B[3]$，$A[2]$ 直接替换成 $b$**。「到底让 $A[2]$ 还是 $A[3]$ 去对齐 $B[3]$」这个抉择，需要看到 $A[3]$ 的存在——而你的局部窗口（只看前后 1 个字符）在第 3 步时已经把 $A[3]$ 挡在视野外了。

> <span style="color:#1e8449;">**[note] Note（译者注）:**</span> 这正是贪心（greedy）失败的经典机制：**局部看到两个相同字符就急着对齐，可能锁死一个次优的全局对齐。** 你学过的「局部暴力枚举」（locally brute-force，Lecture 16 术语）之所以要枚举三分支，正是因为它不预设「当前字符该和谁对齐」，而是把三种对齐可能全部保留、交给后续取 $\min$。你的规则等于「每步替未来的自己做了对齐决定」，而这个决定在反例里是错的。

---

## 4. 这不是巧合：对任意固定窗口都失败

推广构造：$A = a^n$（$n$ 个 `a`），$B = b^{n-1}a$（$n-1$ 个 `b` 接 1 个 `a`）。

- 最优 = $n-1$（替换前 $n-1$ 个 `a` 为 `b`，最后一个 `a` 保留）。
- 任何「只看固定长度 $k$ 的窗口」的规则，总在**倒数第二个 `a`** 那里被「$A[n-2]$ 后面跟着的 `a` 与 $B$ 末尾的 `a` 相同」诱惑，做出插入/删除而非替换。只要 $n > k+1$，窗口就看不到 $A[n-1]$ 会被孤立，必然失败。

程序穷举实测（窗口 $k=1,2,3$ 均失败）：

```
n=4: A=aaaa  B=bbba    DP=3   贪心=5
n=5: A=aaaaa B=bbbba   DP=4   贪心=6
n=6: A=aaaaaa B=bbbbba DP=5   贪心=7
n=8: ...              DP=7   贪心=9
```

窗口再大也没用——**只要你固定窗口长度，就存在一个足够长的反例让你的窗口「不够看」**。

---

## 5. 标准理论下界：$O(n)$ 精确算法几乎不可能存在

这不是我随口说的，是领域内公认的硬结果：

> **Backurs & Indyk（STOC 2015）**：在 SETH（强指数时间假设，Strong Exponential Time Hypothesis）下，编辑距离**不存在 $O(n^{2-\varepsilon})$ 时间的精确算法**。

推论：如果你真的找到了 $O(n)$（甚至 $O(n^{1.99})$）的精确算法，就**推翻了 SETH**——这是计算复杂性领域的一个核心未解猜想。所以你的线性规则「几乎肯定」有反例，而第 3 节那个就是具体的一个。

---

## 6. 本质：为什么局部信息注定不够

编辑距离的本质，是在两个字符串之间找一条**全局对齐**（monotone alignment）。插入/删除会让**后续所有字符的索引整体偏移**，这个偏移的影响范围可以任意长——开头插一个字符，后面所有对齐关系全变。

一个局部规则只能在「当前位置 + 固定邻域」里看，它**看不到远处字符将来会被孤立还是被匹配**。而 DP 的三分支（删/插/换）恰好枚举了「当前位置所有可能的对齐方式」——它不是「暴力地猜」，而是「把未来的可能性摊开，用记忆化只算一遍」。

你想要的「1 个分支」，等价于「每一步都敢肯定：这个操作一定通向全局最优」。反例证明：**没有任何局部信息能给你这个把握**。这就是分支是 3 而不是 1 的根本原因。

---

## 7. 一句话

> **三分支不是浪费，是「对齐的三种可能」。** 局部规则想把它压成 1，等于假设「看了前后邻居就知道全局最优对齐」——反例 `A="aaaa" → B="bbba"` 证明这个假设是假的：你会在倒数第二个 `a` 那里，因为看到「后面有个 `a` 相同」而做插入，最终把一个 `a` 孤立成删除，多花 2 步。
