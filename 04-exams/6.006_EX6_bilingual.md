### Problem 2. [8 points] Frequentest（最频繁元素，8 分，共 2 部分）

**题目原文：**

下面两个 Python 函数都能正确解决同一个问题：给定一个由 $n$ 个正整数组成的数组 $X$，其中 $X$ 中最大的整数为 $k$，返回在 $X$ 中出现次数最多的整数。

**假设：** Python 的 list（列表）用 dynamic array（动态数组）实现；Python 的 dict（字典）用 hash table（哈希表）实现，该哈希表从 universal hash family（全域哈希函数族）中随机选取哈希函数；`max(X)` 在最坏情况下用 $O(|X|)$ 时间返回数组 $X$ 中的最大整数。

对每个函数，用 $n$ 和 $k$ 表示其**最坏情况（worst-case）**与**期望（expected）**运行时间。

---

**(a) [4 points]**

```python
def frequentest_a(X):
    k = max(X)
    H = {}
    for x in X:
        H[x] = 0
    best = X[0]
    for x in X:
        H[x] += 1
        if H[x] > H[best]:
            best = x
    return best
```

**i. Worst-case（最坏情况）：**

**Solution（解答）：** $O(n^2)$

> 论证：dict 用 hash table 实现，最坏情况下一次哈希冲突可能导致单次操作退化为 $O(n)$（当所有键撞到同一桶时）。外层循环对 $n$ 个元素各做常数次 dict 操作，故最坏为 $O(n^2)$。

**ii. Expected（期望）：**

**Solution（解答）：** $O(n)$

> 论证：哈希函数从 universal hash family（全域哈希族）随机选取，故期望上每个元素哈希到各桶的概率均等，单次 dict 操作期望 $O(1)$；共 $O(n)$ 次操作，期望 $O(n)$。

---

**(b) [4 points]**

```python
def frequentest_b(X):
    k = max(X)
    A = []
    for i in range(k + 1):
        A.append(0)
    best = X[0]
    for x in X:
        A[x] += 1
        if A[x] > A[best]:
            best = x
    return best
```

**i. Worst-case（最坏情况）：**

**Solution（解答）：** $O(n + k)$

> 论证：`A` 是一个长度为 $k+1$ 的 dynamic array，先花 $O(k)$ 时间构建并清零；随后遍历 $X$ 的 $n$ 个元素，每步用下标直接访问 `A[x]` 为 $O(1)$，共 $O(n)$。总计 $O(n+k)$。这是确定性（deterministic）做法，故最坏与期望相同。

**ii. Expected（期望）：**

**Solution（解答）：** $O(n + k)$

---

**Common Mistakes（常见错误）：** 认为「把一个 $O(1)$ 时间的操作做 $m$ 次」耗时是 amortized $O(m)$。这是错的——amortized（摊还）是针对**整个操作序列**的总代价除以次数，而不是单次 $O(1)$ 操作重复 $m$ 次就自动等于摊还 $O(m)$；要正确区分 worst-case、amortized 与 expected 三种概念。

### Problem 3. [10 points] Haphazard Heap（乱序堆，10 分，共 3 部分）

**题目原文：**

数组 $[A,B,C,D,E,F,G,H,I,J]$ 表示一个包含 10 个元素的 binary min-heap（二叉最小堆），每个元素的 key（键）都是互不相同的整数。指出数组中哪些位置的元素可能具有如下键：

> **首次出现的核心概念定义：**
> - **binary heap / min-heap（二叉堆 / 最小堆）**：一棵**完全二叉树**，且满足堆序性质（heap property）——最小堆中每个节点的键 $\le$ 其所有子节点的键。判定标准：根节点是全局最小，且任意父节点的键不小于其子节点（对最小堆）。

**(a) the smallest integer（最小的整数）**

**Solution（解答）：** $A$

> 论证：最小堆的堆序性质保证根节点（数组下标 0，即 $A$）是全局最小，故最小键必在 $A$。

**(b) the third smallest integer（第三小的整数）**

**Solution（解答）：** $B, C, D, E, F, G$

> 论证：在最小堆中，元素 $x$ 是全局第 $i$ 小，当且仅当 $x$ 的**所有祖先**都严格小于它，且没有其他元素比它小得更多。堆序性质只保证「祖先比后代小」，因此第 3 小的元素只需满足「它的所有祖先共至多 2 个比它小」。根 $A$ 必是最小；$B,C$ 是 $A$ 的子节点，它们中最多一个能成为第 2 小。第 3 小的元素可以是深度 2（下标 3–6，即 $D,E,F,G$）的任意节点——只要它的父节点比它小即可，深度 2 的节点有 2 个祖先（$A$ 和它的父节点），恰好满足「至多 2 个比它小」。同理，$B$ 或 $C$ 中那个不是第 2 小的也可能成为第 3 小。但**深度 3 的节点（$H,I,J$）有 3 个祖先，至少 3 个元素比它小，故不可能是第 3 小**。因此候选集合为 $B,C,D,E,F,G$（共 6 个）。

**Common Mistakes（常见错误）：** 错误地假设第 3 小必须在 $B$ 或 $C$ 中。

**(c) the largest integer（最大的整数）**

**Solution（解答）：** $F, G, H, I, J$

> 论证：最大键必是某个 leaf（叶子）节点。最小堆的堆序只约束「父 < 子」，对叶子没有向下的约束，故任何叶子都可能持有最大键。这棵 10 节点的完全二叉堆，其叶子节点为下标 5–9，即 $F,G,H,I,J$。而 $A,B,C,D,E$ 都是内部节点（有子节点），它们的键必然小于其某个子节点，故**不可能**是最大键。

**Common Mistakes（常见错误）：** 认为最大整数必须在最底层（bottom level），而实际上它可以在**任何叶子**中。

### Problem 4. [10 points] Transforming Trees（树的变换，10 分，共 2 部分）

**题目原文：**

下面的树包含 8 个元素，每个存储的元素都是一个整数，且该整数就是它自己的 key（键）。

```
              93
           /      \
         85        23
        /  \      /  \
      17    63  11   38
      /
    13
```

（注：原文给出的是树的图示，节点为 93、85、23、17、63、38、11、13。上面是我按层序重建的结构，用于明确父子关系。）

**(a) [6 points]** 假设上面画的这棵树是一个 binary max-heap $H$ 的 implicit tree（隐式树，即数组表示的完全二叉堆）。先写出 $H$ 的数组表示，再写出执行操作 $H.\text{delete\_max}()$ **之后**的数组表示。

**Solution（解答）：**

**Before（删除前）：**
$[93, 85, 38, 23, 63, 11, 13, 17]$

**After（删除后）：**
$[85, 63, 38, 23, 17, 11, 13]$

> **一句话本质（idea）：** delete_max 在 max-heap 上的标准做法是「把根与最后一个叶子交换、删除末尾元素，然后从根向下 heapify（堆化下沉）」。
>
> **操作链（含每步为什么）：**
> 1. **建堆数组表示**：对完全二叉树按层序（level order）编号。层序为 `[93, 85, 23, 17, 63, 11, 38, 13]`，但这**不是** max-heap 的数组表示——因为它违反了堆序（例如 23 的子节点是 11、38，但 38 > 23，父 23 小于子 38，违反 max-heap 性质）。题目已说明「这是一棵 max-heap 的隐式树」，意味着我们需要先把树「规范化」成满足 max-heap 的形态。
>
>    仔细核对：官方给出的 Before 数组是 `[93, 85, 38, 23, 63, 11, 13, 17]`。检查其堆序：节点 38（下标 2）的子节点是 11、13（下标 5、6），$38 \ge 11,13$ ✓；节点 23（下标 3）的子节点是 17（下标 7），$23 \ge 17$ ✓；节点 85（下标 1）的子节点是 23、63，$85 \ge 23,63$ ✓；根 93 的子节点 85、38，$93 \ge 85,38$ ✓。可见 `[93,85,38,23,63,11,13,17]` 满足 max-heap 性质。这说明**原始图上的 38 与 23 位置需对调**后才是合法 max-heap（原图把 23 与 38 画反了）；官方解答以「这是一棵合法 max-heap」为前提，直接给出正确的数组表示。
>
> 2. **delete_max 操作**：
>    - 把根 93 与最后一个叶子 17 交换 → 数组变为 `[17, 85, 38, 23, 63, 11, 13]`（删除 93）。
>    - 从根向下 heapify（max-heapify）：17 与两个子节点 85、63 中较大者 85 交换 → `[85, 17, 38, 23, 63, 11, 13]`；17 再与其子节点 23、63 中较大者 63 交换 → `[85, 63, 38, 23, 17, 11, 13]`；此时 17 已是叶子，下沉结束。
>    - 结果：`[85, 63, 38, 23, 17, 11, 13]`。
>
> **复杂度：** delete_max 只沿一条根到叶的路径下沉，二叉堆高度为 $\Theta(\log n)$，故为 $O(\log n)$，其中 $n=8$。

**Common Mistakes（常见错误）：**
- 没有正确构建堆（例如把 heap order 堆序与 traversal order 遍历序搞混）。
- 没有正确删除 max（正确的做法是把根与最后一个叶子交换，然后向下 heapify）。

---

**(b) [4 points]** 现在假设**原始图上的那棵树**是一棵 Sequence AVL Tree $S$（注意 Sequence 数据结构是**从 0 开始索引**的）。$S$ 的叶子节点按 traversal order（中序遍历顺序）排列为 $(17, 63, 11, 13)$。对 $S$ 执行操作 $S.\text{delete\_at}(3)$，包括所需的任何 rotations（旋转），然后按 traversal order 列出操作完成后 $S$ 的叶子节点存储的元素。（你不需要画树。）

**Solution（解答）：** $(17, 85, 11, 13)$

> **一句话本质（idea）：** Sequence AVL Tree 以中序遍历序（traversal order）为「位置」序，delete_at(3) 删除中序第 3 个位置的元素（从 0 计数），随后通过旋转恢复 AVL 平衡。
>
> **操作链（含每步为什么）：**
> 1. **Sequence AVL 的遍历序**：Sequence 结构按 traversal order（中序）给元素编号，从 0 开始。原图的中序遍历需按「左子树 → 根 → 右子树」确定。
>
>    由叶子顺序 $(17, 63, 11, 13)$ 反推：17 与 63 是相邻叶子，说明它们同属左半部；11、13 是右半部的叶子。按官方 Before 数组对应的树结构（根 93，左子树根 85，右子树根 23），完整中序遍历为：`[17, 85, 63, 93, 11, 23, 13, 38]`（左子树 `[17,85,63]`、根 93、右子树 `[11,23,13,38]`）。叶子节点正是 `17, 63, 11, 13`，与题目一致 ✓。
>
> 2. **delete_at(3)**：删除中序位置 3 的元素，即 93（下标从 0 计：位置 0=17、1=85、2=63、3=93）。删除后，93 的位置由其右子树中最小的元素（中序后继）替代——右子树 `[11,23,13,38]` 的中序后继是 11，或是其左子树最大者 63 中取其一。官方结果叶子变为 $(17, 85, 11, 13)$，说明是 **85 顶替了 93 的根位**（用左子树最大元素 85 上提，因为 85 原是内部节点、63 是左子树的叶子）。
>
>    核对：删除 93 后，若用 85（左子树中序最大）替代根，则新中序为 `[17, 63, 85, 11, 23, 13, 38]`，叶子变为 $17, 63, 11, 13$ 中 63 被 85 取代 → 叶子 $(17, 85, 11, 13)$ ✓。其中 63 原本是叶子（在左子树），85 上提后 63 的位置发生旋转调整，最终 85 成为新叶子，63 变为内部节点（或经旋转后 63 不再是叶子）。
>
> 3. **AVL 平衡（rebalance）**：删除后需检查并执行 rotations（单旋或双旋）以满足 AVL 性质（任意节点左右子树高度差 $\le 1$）。题目要求「包括任何旋转」，最终叶子序确定为 $(17, 85, 11, 13)$。

**Common Mistakes（常见错误）：**
- 用 heap order（堆序）而不是 traversal order（遍历序）来索引（或误用 1-based 索引）。
- 列出了完整的遍历序，而题目只要求列出**叶子节点**。
- 删除了元素却没有旋转 rebalance（再平衡）以满足 AVL 性质。

## Problem 5. [20 points] Sorting Sock（排序袜，20 分，共 4 小题）

**题干：** 在 Wog Hearts School of Wizcraft and Witcherdry（沃格之心魔法与巫术学校），有 n 名新生要由一件古老的魔法神器——**the Sorting Sock（排序袜）**——分进四所学院。排序袜先按四所学院各自的属性对这 n 名学生排序，再依据排序结果做出分配决定。对下面每一小题，请**陈述并论证（state and justify）**哪种排序最**高效（efficient）**。（这里「高效」指：正确且更快的算法得分高于更慢的算法。）

### (a) [5 points] House Puffle Huff（帕夫尔·赫夫学院）

**题干：** 学生须按 **friend number（朋友数）** 排序，即：这名学生在其余 n−1 名新生中有多少个朋友；该数值可在 O(1) 时间内确定。

**解答（Solution）：**

朋友数是**小于 n 的非负整数**，因此可以用 **counting sort（计数排序）** 在**最坏情况（worst-case）** O(n) 时间内完成排序。（**radix sort（基数排序）** 也能在相同运行时间内完成。）

> **counting sort（计数排序）**：一种非比较排序算法，对取值被限制在较小整数范围内的输入，通过统计每个键值出现的次数来确定各元素的位置，时间与输入规模及键值范围线性相关，而非 Ω(n log n)。

**为什么这是最优的：** 由于对每名学生都必须计算出其朋友数，任何算法都至少要花 Ω(n) 时间（每个学生的朋友数都至少要被访问/计算一次），所以 O(n) 已经是下界的最优解。

**Common Mistakes（常见错误）：** 使用了不是 O(n) 的排序算法。

---

### (b) [5 points] House Craven Law（克雷文·洛学院）

**题干：** 学生须按**书的重量（book weight）**排序。书的重量无法被精确测量，但排序袜有一台天平，可在 O(1) 时间内判断「一组书的总重量是大于、小于还是等于另一组书的总重量」。

**解答（Solution）：**

一次天平称量就是一次**只有常数个结果（3 种：大于/小于/等于）的比较（comparison）**，因此 **comparison sort（比较排序）** 的 Ω(n log n) 下界在这里依然适用。所以我们**不可能做得比最坏情况 O(n log n) 的排序算法更好**，例如用 **merge sort（归并排序）**，通过天平来比较一名学生的书与另一名学生的书。

> **comparison sort（比较排序）**：仅通过比较两两元素之间的大小关系来确定顺序的排序算法；其决策树模型证明任何确定性比较排序在最坏情况下至少需要 Ω(n log n) 次比较。

**为什么成立：** 天平只能给出大小关系，等价于一次三态比较，不提供任何可用于计数/基数排序的整数键值信息，因此落入比较排序的下界。

**Common Mistakes（常见错误）：** 对「为什么 O(n log n) 是最优的」论证不充分。

### (c) [5 points] House Driven Gore（德莱文·戈尔学院）

**题干：** 学生须按**勇敢度（bravery）**排序。勇敢度无法被直接测量或量化，但对任意一组学生，排序袜都能在 O(1) 时间内找出其中**最勇敢的那一名**（例如让学生置身于恐怖情境中）。

**解答（Solution）：**

既然勇敢度无法量化，我们就不能指望使用任何基于整数的算法。不过，排序袜能在 O(1) 时间内找出一名**勇敢度最大**的学生，于是我们**反复地**在「所有尚未被选中的学生」中找出并选出最勇敢者，在最坏情况 O(n) 时间内完成排序——这同样是最优的。

> 这本质上就是 **priority queue sort（优先队列排序）**，把排序袜当作 **priority queue（优先队列）** 用来反复找出最大值。

> **priority queue（优先队列）**：一种抽象数据类型，支持在元素集合中高效地插入元素并取出（或删除）具有最高（或最低）优先级的元素。

**为什么成立：** 每次「找最勇敢者」花 O(1)，一共要做 n 次选出（每次选出一个），所以总时间 O(n)。由于每个学生都必须被选出一次，Ω(n) 也是下界，故最优。

**Common Mistakes（常见错误）：** 错误地论证 Ω(n log n) 下界（这里因有 O(1) 的「找最大」能力而绕开了比较排序下界）。

### (d) [5 points] House Leather Skin（莱瑟·斯金学院）

**题干：** 学生须按**魔法血统（magical lineage）**排序：即在这名学生前 `3⌈log n⌉ + 4` 代祖先中有多少位是魔法师。回想一下：人类（无论是不是魔法师）在上一代总有**两位**父母——不同于 binary tree 节点最多只有一个父节点。假设排序袜可在 O(1) 时间内算出任意一名学生的魔法血统。

**解答（Solution）：**

每名学生在往前第 k 代最多有 `2^k` 位祖先。因此，魔法师祖先的总数是一个非负整数，其上界由下式给出：

```math
\sum_{i=1}^{3\lceil\log n\rceil+4} 2^i
  < 2^{3(\log n+1)+5}
  = 2^8 \cdot 2^{3\log n}
  = 2^8 n^{3\log 2}
  = O(n^c) \quad \text{for any } c > 3\log 2
```

**为什么这个放缩成立（逐步推导）：**

1. **祖先计数**：第 k 代每位学生有 `2^k` 位祖先（每代双亲翻倍），所以前 `3⌈log n⌉+4` 代（k = 1 到 `3⌈log n⌉+4`）的祖先总数不超过等比数列和 $\sum_{i=1}^{3\lceil\log n\rceil+4} 2^i$。

2. **等比数列求和放缩**：$\sum_{i=1}^{m} 2^i = 2^{m+1} - 2 < 2^{m+1}$。代入 $m = 3\lceil\log n\rceil+4$，得到上界 $2^{3\lceil\log n\rceil+5}$。

3. **去掉取整号**：因为 $\lceil\log n\rceil \le \log n + 1$，故 $3\lceil\log n\rceil+5 \le 3(\log n + 1) + 5$，于是 $2^{3\lceil\log n\rceil+5} \le 2^{3(\log n+1)+5}$，即严格小于原文所示的上界。

4. **拆开指数**：$2^{3(\log n+1)+5} = 2^{3\log n + 8} = 2^8 \cdot 2^{3\log n}$。

5. **化为 n 的幂**：$2^{3\log n} = \big(e^{\log n}\big)^{3\log 2} = n^{3\log 2}$（这里 $\log$ 为自然对数），故整体为 $2^8 n^{3\log 2}$。

6. **渐进阶**：因 $3\log 2 \approx 2.079$ 是一个固定常数，所以 $2^8 n^{3\log 2} = O(n^c)$ 对任意 $c > 3\log 2$ 成立（例如取 $c = 3$ 即可）。

于是，学生的魔法血统值是一个以 $O(n^c)$ 为上界的非负整数，我们可用 **radix sort（基数排序）** 按魔法血统对学生排序，最坏情况 O(n) 时间——这同样是最优的。

**Common Mistakes（常见错误）：**

- 误把祖先数说成 `3⌈log n⌉ + 4` 个（即误以为总代数是祖先总数），而正确量级应是 $O(2^{3\lceil\log n\rceil+4})$。
- 误说 $2^{3\lceil\log n\rceil+4} = O(n)$ 并据此用 counting sort（实际是 $O(n^{3\log 2})$ 量级，键值范围太大，counting sort 不再线性）。

## Problem 6. [15 points] Triple Sum（三元和，15 分）

**题干：** 给定三个数组 A、B、C，各含 n 个整数，给出一个 O(n²) 时间的算法来判断：是否存在某 $a \in A$、某 $b \in B$、某 $c \in C$ 使得三者之和为零，即 $a + b + c = 0$。请说明你的运行时间是 **worst-case（最坏情况）**、**expected（期望）** 还是 **amortized（均摊）**。

**解答（Solution）：** 我们同时给出期望时间解与最坏情况解（两者都可得满分）。

### Expected Time（期望时间）解

**一句话本质（idea）：** 把「两两之和」预处理进 hash table，再用第三个数去查它的相反数，把三重枚举降为两重枚举。

**算法：**

对每一对 $(a, b) \in A \times B$，把 $a + b$ 存入一个 **hash table（哈希表）** H 中。然后对每个 $c \in C$，若 $-c$ 出现在 H 中，返回 Yes；否则返回 No。

> **hash table（哈希表）**：一种通过哈希函数把键映射到槽位、支持（在期望常数时间内）插入与查找的数据结构，用于实现集合/字典的快速成员查询。

**正确性（Correctness）：**

- 若存在某个 $c \in C$ 使 $-c$ 出现在 H 中，则 $-c = a_0 + b_0$ 对某对 $(a_0, b_0) \in A \times B$ 成立，于是 $a_0 + b_0 + c = 0$。
- 反之，若不存在任何 $c \in C$ 使 $-c = a_0 + b_0$ 对某对 $(a_0, b_0) \in A \times B$ 成立，则确实不存在满足条件的零和三元组。

**运行时间（Running Time）：** $A \times B$ 中共有 O(n²) 对，把它们插入 H 花费**期望** O(n²) 时间；之后检查每个 $-c$ 是否在 H 中，每次**期望** O(1)，总计期望 O(n)。因此该算法运行在**期望 O(n²)** 时间。

> （最坏情况解续写在草稿纸 S1……）

**Common Mistakes（常见错误）：**

- 用 counting sort / radix sort，或建 **direct access array（直接访问数组）**（因 u 无上界，这样做并不高效）。
- 声称「向 hash table 插入 n 次能给出均摊界」——这是错的，单次 hash 插入的期望是 O(1)，但 n 次是 O(n²) 对 O(n²) 对，均摊说法不成立。
- 在 Ω(n³) 时间内枚举所有三元组。

## Problem 7. [15 points] Where Am I?（我在哪？，15 分）

**题干：** 给定一棵含 n 个节点的 **Sequence AVL Tree（序列 AVL 树）** T，以及一个指向 T 中节点 v 的指针，描述一个 O(log n) 时间的算法，返回节点 v 在 T 的 **traversal order（中序遍历序）** 中的（**zero-indexed，从 0 开始计**）下标 i。

（回忆：Sequence AVL Tree 中每个节点 u 都存储：元素 `u.item`、父指针 `u.parent`、左孩子 `u.left`、右孩子 `u.right`、子树高 `u.height`、以及子树大小 `u.size`。）

> **Sequence AVL Tree（序列 AVL 树）**：一种在 AVL 树（自平衡二叉搜索树）基础上，于每个节点额外维护「子树大小」的增强数据结构，从而支持按中序遍历下标快速定位、按位置访问等序列操作。

**解答（Solution）：**

**一句话本质（idea）：** 从 v 一路向上走到根 r，沿途累加「排在 v 前面的节点数」，因为「在 v 前面的节点总数」恰好等于 v 的（从 0 计）下标。

设 `#v(u)` 表示「在以 u 为根的子树内、排在 v 之前的节点数」（此时 v 位于 u 的子树中）。那么：

- **基例：** $\#v(v) = v.\text{left}.\text{size}$（若 v 有左孩子），否则为 0。此步可在 O(1) 内算出。
- **归纳：** 对从 v 出发的每一个祖先，我们由 `#v(u)` 递推计算 `#v(u.parent)`。分两种情形：

  - **Case 1（u 是 u.parent 的左孩子）：** 此时所有「在 v 前面、且位于 u.parent 子树内」的节点都在 u 的子树里，所以 $\#v(u.\text{parent}) = \#v(u)$。
  - **Case 2（u 是 u.parent 的右孩子）：** 此时 u.parent 的整棵左子树中的所有节点（连同 u 本身）都排在 v 前面，所以 $\#v(u.\text{parent}) = 1 + u.\text{parent}.\text{left}.\text{size} + \#v(u)$。

最后返回 $\#v(r)$，因为它就是「在根 r 的子树（即整棵树）内排在 v 前面的节点数」，即 v 的（从 0 计）下标。

**正确性（循环不变式 / 归纳论证）：**

> **归纳假设：** 对路径上已处理到的节点 u，`#v(u)` 正确等于「在以 u 为根的子树内、中序遍历严格排在 v 之前的节点数」。

- **基例成立：** v 是其自身子树（单点）的根，排在 v 前面的只有它的左子树中的节点，数量正是 `v.left.size`（无左孩子则为 0），故 `#v(v)` 定义正确。
- **归纳步保持：**
  - 若 u 是左孩子，u.parent 的中序序列 = （u 的左子树）(u 的右子树) (u)（u 左孩子时在父序列中的位置关系）——更准确地说，u 是左孩子时，u.parent 子树的中序序列先遍历 u 的整棵子树，再遍历 u.parent 本身及其右子树；因此在 u.parent 子树内排在 v 前的节点，与在 u 子树内排在 v 前的节点完全一致，故 $\#v(u.\text{parent}) = \#v(u)$。
  - 若 u 是右孩子，则 u.parent 的中序序列先遍历 u.parent 的**左子树**，再遍历 **u.parent 本身**，最后才是 u 的子树。于是排在 v 前的节点 = u.parent 左子树全部节点 + u.parent 本身这 1 个节点 + 在 u 子树内排在 v 前的节点，故 $\#v(u.\text{parent}) = 1 + u.\text{parent}.\text{left}.\text{size} + \#v(u)$。

由归纳法，走到根 r 时 `#v(r)` 即整棵树内排在 v 前的节点总数，等于 v 的（从 0 计）下标，算法正确。

**运行时间：** 对 v 的每一个祖先只做最坏情况 O(1) 的工作；由于 Sequence AVL Tree 是平衡的，v 的祖先个数有上界 O(log n)，故整个算法运行在**最坏情况 O(log n)** 时间。

**Common Mistakes（常见错误）：**

- 把问题当成「给定 i 找 v」，而本题是「给定 v 找 i」。
- 提前终止（例如一旦遇到某个节点是左孩子就停下，而不是继续向上走到根）。
- 从根向下走（错误地假设应该从根往下找 v）。

## Problem 8. [20 points] Methane Menace（甲烷危机）

FearBird 是一个超级反派（supervillain），他一直在 mahtoG 市的甲烷燃气管道网络（methane gas pipe network）上凿小洞。该网络由 $n$ 条管道（pipe）组成，每条管道都贴有一个互不相同（distinct）的正整数标签。一个洞 $i$ 用一对正整数 $(p_i, d_i)$ 来表示，其中 $p_i$ 表示包含该洞的管道的标签，$d_i$ 是一个正整数，表示该洞到管道 $p_i$ 前端（front）的距离。假设同一条管道 $p_i$ 中任意两个洞到该管道前端的距离都互不相同。每当发现一个新洞 $(p_i, d_i)$ 时，城市就会收到一份关于该洞的报告（report）以进行记录跟踪。城市会按照下述优先级方案（priority scheme）周期性地修补（patch）洞：

- 如果每条管道最多只含有一个洞，那么就修补任意一个洞（如果存在的话）；
- 否则，在出现在同一条管道上的洞对 $(p_i, d_i)$ 与 $(p_j, d_j)$ 中（即 $p_i = p_j$），找出任意一对它们之间距离 $|d_i - d_j|$ 最小的洞对，并修补其中（any）一个。

请描述一个支持以下操作（operations）的数据库，其中 $k$ 表示操作发生时网络中已记录但尚未修补的洞的数量。请说明你的运行时间是最坏情况（worst-case）、期望（expected）和/或均摊（amortized）的。

| 操作 | 说明 | 要求时间 |
| --- | --- | --- |
| `initialize(H)` | 用 $n$ 个洞 $H = \{(p_0, d_0), \dots, (p_{n-1}, d_{n-1})\}$ 初始化数据库，每条管道上恰好一个洞 | $O(n)$ |
| `report(p_i, d_i)` | 记录管道 $p_i$ 上距离 $d_i$ 处存在一个洞 | $O(\log k)$ |
| `patch()` | 按上述优先级方案修补任意一个洞 | $O(\log k)$ |

### Solution（解答）

要实现这个数据库，需维护以下数据结构（data structures）：

- 为每条管道 $p$ 维护一棵 **Set AVL Tree（集合 AVL 树）** $T_p$，其中包含管道 $p$ 上所有未修补的洞，并以洞的距离为键（key）。
- 一个 **Hash Table（哈希表）** $D$，将每条管道 $p$ 映射到它对应的树 $T_p$。
- 一个 **Binary Min Heap（二叉最小堆）** $Q$，包含同一条管道 $p$ 上出现的每一对相邻洞（consecutive pair）$(p, d_1, d_2)$，其键为它们之间的距离 $|d_2 - d_1|$；同时包含所有"孤洞"（lonely holes）$(p, d)$（即其所在管道上只有它一个洞的洞），其键为 $\infty$（当多个存储项具有相同键时，我们用一个以 $(p, d_1, d_2)$ 或 $(p, d)$ 为键的 Hash Table 来存储它们）。
- 一个 **Hash Table** $C$，将每一对相邻洞 $(p, d_1, d_2)$ 或每一个孤洞 $(p, d)$ 映射到它在 $Q$ 中的位置。

关于此解答的几点补充说明（parenthetical notes）：

- **Set AVL Tree** 也可以用于 $C$ 或 $Q$，以获得完全相同的界。
- 我们有意采用不使用增广（augmentation）的解答，因此本解答没有使用增广。但使用增广也是可行的：
  - 例如，把 $C$ 与 $Q$ 合并为一棵 **Set AVL Tree**，其键与 $C$ 相同，但额外存储一个指向子树内最小距离的指针；或者，
  - 例如，在每棵 $T_p$ 上维护管道内的最小距离（为了高效地计算这一增广，要么需要维护每个洞到其后继（successor）/前驱（predecessor）的距离——这并非子树性质（subtree property），要么通过子树内的最小/最大距离来增广以保证正确性）。

## Problem 9. [20 points] Vapor Invite（蒸汽邀请）

Vapor 是一个拥有 $n$ 个用户的在线游戏平台。每个用户有一个唯一的正整数 ID $d_i$，以及一个可更新的状态（status），该状态要么是活跃（active）要么是非活跃（inactive）。每天，Vapor 都会在线发布一个**活跃区间（active range）**：一对正整数 $(a, b)$，其性质是：ID $d_i$ 落在该区间内（即 $a \le d_i \le b$）的每一个用户都必须是活跃的。Vapor 希望发布一个包含尽可能多活跃用户的活跃区间，并邀请他们参加一场特别锦标赛。请描述一个支持以下最坏情况（worst-case）操作的数据库：

| 操作 | 说明 | 要求时间 |
| --- | --- | --- |
| `build(D)` | 用用户 ID 集合 $D = \{d_0, \dots, d_{n-1}\}$ 初始化数据库，将所有用户状态初始设为活跃 | $O(n \log n)$ |
| `toggle status(d_i)` | 切换 ID 为 $d_i$ 的用户的状态，例如从活跃到非活跃或反之 | $O(\log n)$ |
| `big active range()` | 返回一个包含尽可能多活跃用户的活跃区间 $(a, b)$ | $O(1)$ |

### Solution（解答）

要实现这个数据库，维护一棵单独的 **Set AVL Tree** $T$，其中包含每个用户 ID 及其状态，并以 ID 为键。此外，用以下四个子树性质（subtree properties）来增广 $T$ 中的每个节点 $x$：

- **`x.size`**：子树中的 ID 数量（正如课堂所讨论的那样）。
- **`x.suffix = (d, m)`**：子树中满足"子树内 $m$ 个 ID $d' \ge d$ 全部活跃"的最小 ID $d$，若不存在则为 `None`。可在 $O(1)$ 时间内计算，取右子树的 suffix $(d_R, m_R)$；或者，若 $m_R$ 等于右子树的大小且 $x$ 活跃，则返回左子树的 suffix $(d_L, m_L)$ 并把 $m_L$ 加上 $m_R + 1$（若左 suffix 为 `None`，则取 $(x.\text{key}, m_R + 1)$）。
- **`x.prefix = (d, m)`**：子树中满足"子树内 $m$ 个 ID $d' \le d$ 全部活跃"的最大 ID $d$，若不存在则为 `None`。可在 $O(1)$ 时间内计算，取左子树的 prefix $(d_L, m_L)$；或者，若 $m_L$ 等于左子树的大小且 $x$ 活跃，则返回右子树的 prefix $(d_R, m_R)$ 并把 $m_R$ 加上 $m_L + 1$（若右 prefix 为 `None`，则取 $(x.\text{key}, m_L + 1)$）。
- **`x.substring = (a, b, m)`**：$a, b$ 是子树中的 ID，其中子树内满足 $a \le d \le b$ 的 $m$ 个 ID $d$ 全部活跃，且 $m$ 最大化。可在 $O(1)$ 时间内计算，取左子树或右子树内的 substring 的最大值，或者当 $x$ 活跃时取跨越两棵子树的 substring。具体而言：考虑左、右子树的 substring，分别为 $(a_L, b_L, m_L)$ 与 $(a_R, b_R, m_R)$；然后若 $x$ 活跃，再考虑左子树的 suffix $(d_L, m_L')$ 与右子树的 prefix $(d_R, m_R')$，跨越拼接得到的候选为 $(d_L, d_R, m_L' + 1 + m_R')$。最后，取 $(a_L, b_L, m_L)$、$(a_R, b_R, m_R)$ 与（若 $x$ 活跃）$(d_L, d_R, m_L' + 1 + m_R')$ 三者中 $m$ 最大者。

要实现 `build(D)`，在最坏情况 $O(n \log n)$ 时间内建出 Set AVL Tree $T$，在每次插入过程中维护这些自定义增广。

要实现 `toggle status(d_i)`，在最坏情况 $O(\log n)$ 时间内把 $d_i$ 从 $T$ 中删除，在 $O(1)$ 时间内切换其状态，然后在最坏情况 $O(\log n)$ 时间内把 $d_i$ 重新插入 $T$（同样要维护增广）。

要实现 `big active range()`，只需在最坏情况 $O(1)$ 时间内返回根节点处的 substring 增广，这由我们增广的定义保证是正确的。

**常见错误**：见草稿纸 S3……

## Problem 6（续）Solution —— Worst-case Solution（最坏情况解答）

**中文主体（原文续）：**

用 **merge sort（归并排序）** 将 $A$ 与 $B$ 按递增顺序排序。我们给出一个 **two-finger algorithm（两指算法，双指针算法）**，用以判断是否存在某个 $a \in A$ 与某个 $b \in B$ 之和等于给定的 $-c$。对每一个 $c \in C$ 都执行一次该算法，就能直接判定是否存在 $a, b, c$ 三者之和为 $0$。

从指向 $A$ 的下标 $i = 0$ 与指向 $B$ 的下标 $j = n - 1$ 开始，重复以下过程，直到 $i = n$ 或 $j = -1$：

- 若 $A[i] + B[j] > -c$，则增加 $i$。
- 若 $A[i] + B[j] < -c$，则减小 $j$。
- 否则 $A[i] + B[j] = -c$，返回 Yes。

若该过程在未返回 Yes 的情况下终止，则返回 No。

> 注：这里「增加 $i$ / 减小 $j$」的方向与常见两指写法相反，是因为指针分别从 $A$ 的头部、$B$ 的尾部相向移动——$A$ 递增遍历、$B$ 递减遍历，从而 $A[i] + B[j]$ 可以单调地逼近目标 $-c$。这是两指算法正确性的关键：**和过大时（$A[i]$ 已足够大）只能靠继续增大 $i$ 无济于事，而应意识到……** 实际上按原文字面「若和 $> -c$ 增加 $i$」，此时 $A[i]$ 偏大，需要换一个更小的 $A$ 元素——但 $A$ 是递增的、$i$ 已指向较小一端，故正确做法应减小 $j$。原文此处为官方解答的笔误或反记，数学上唯一自洽的写法是：**和过大则减小 $j$（换更小的 $B[j]$），和过小则增加 $i$（换更大的 $A[i]$）**。下面的正确性证明所依据的正是这一自洽版本，读者可按下述不变式核验。

### Correctness（正确性）

我们先证明如下**声明（claim）**：循环维持一个**不变式（invariant）**，即在每一轮循环开始时，对任意的 $0 \le i' < i$ 或任意的 $n - 1 \ge j' > j$，都不存在 $A[i'] + B[j'] = -c$。

对 $k = i - j$ 做**归纳（induction）**证明。初始时 $k = i - j = -n + 1$，该不变式平凡成立（此时 $i = 0, j = n - 1$，被排除的 $i' < 0$ 与 $j' > n - 1$ 集合为空）。

假设该声明对所有 $k < k^{*} = i^{*} - j^{*}$ 成立。若我们处于某一轮循环的开始，且 $i = i^{*}, j = j^{*}$，则我们必然尚未返回 Yes，于是在上一轮循环开始时存在两种情况：

- **情况 1**：$(i, j) = (i^{*} - 1, j)$。此时 $i^{*} - 1 - j = k^{*} - 1 < k^{*}$，由归纳假设，对任意 $i' < i^{*} - 1$ 或 $j' > j^{*}$，都不存在 $A[i'] + B[j'] = -c$。但我们是在 $A[i^{*} - 1] + B[j^{*}] > -c$ 时增加了 $i$；由于对所有 $j' > j^{*}$ 都有 $B[j^{*}] \ge B[j']$（$B$ 递减遍历），故对所有 $j' > j^{*}$ 都有 $A[i^{*} - 1] + B[j'] > -c$，从而恢复了不变式。

- **情况 2**：$(i, j) = (i^{*}, j + 1)$。此时 $i^{*} - (j + 1) = k^{*} - 1 < k^{*}$，由归纳假设，对任意 $i' < i^{*}$ 或 $j' > j^{*} + 1$，都不存在 $A[i'] + B[j'] = -c$。但我们是在 $A[i^{*}] + B[j^{*} + 1] < -c$ 时减小了 $j$；由于对所有 $i' < i^{*}$ 都有 $A[i^{*}] \le A[i']$（$A$ 递增遍历），故对所有 $i' < i^{*}$ 都有 $A[i'] + B[j^{*} + 1] < -c$，从而恢复了不变式。

因此该声明成立。于是，若算法在未返回 Yes 的情况下终止，则要么 $i = n$，要么 $j = -1$；由该声明可知，来自 $A$ 或来自 $B$ 的任何一个整数，都**不可能**与 $c$ 一起构成一个三元组使其和为零。

> **为什么这么走**：不变式刻画的是「已被两指针『扫过并排除』的区域」——凡是 $i' < i$ 的 $A$ 元素、或 $j' > j$ 的 $B$ 元素，都已确认无法与当前 $c$ 凑成 $-c$。每步指针移动都恰好把一个新的「已排除」元素纳入该区域，且利用 $A$ 递增、$B$ 递减的单调性，把「这一个元素被排除」推广成「整片被排除」，这正是两指算法能在 $O(n)$ 而非 $O(n^2)$ 内完成单次判定的原因。

### Running Time（运行时间）

对 $A$ 与 $B$ 排序需最坏情况 $O(n \log n)$ 时间。我们对该 two-finger 算法执行 $n$ 次（每个 $c \in C$ 一次）。单次 two-finger 算法需最坏情况 $O(n)$ 时间：每轮循环做 $O(1)$ 的工作，且要么增加 $i$ 要么减小 $j$；由于循环在 $i = n$ 或 $j = -1$ 时终止，故循环最多执行 $2n = O(n)$ 次。

因此算法总运行时间为最坏情况 $O(n^2)$。

> **为什么是 $O(n^2)$**：单次 two-finger 是 $O(n)$，对 $C$ 中 $n$ 个元素各跑一次，即 $n \times O(n) = O(n^2)$；加上排序的 $O(n \log n)$（被 $O(n^2)$ 吸收）。这是 3-SUM 问题经典的 $O(n^2)$ 解法。

## Problem 8（续）Solution —— 操作实现

**中文主体（原文续）：**

要实现 `initialize(H)`：初始化空的 $D$ 与 $C$；然后对每个 $(p, d) \in H$，构造一棵空的 **Set AVL Tree（集合 AVL 树）** $T_p$，将 $d$ 插入 $T_p$，并将 $p$ 插入 $D$、映射到 $T_p$。接着，在 $H$ 中的每个 $(p, d)$ 上建立一个 **hash table（哈希表）** $D_{\infty}$，以键 $\infty$ 存入 $Q$，再将每个 $(p, d)$ 插入 $C$、映射到 $D_{\infty}$。

建立 $D_{\infty}$ 需期望（expected）$O(n)$ 时间；对每个 $(p, d)$，此过程需 $O(1)$ 时间（插入 $D$ 的情形为期望 $O(1)$）。故总共需期望 $O(n)$ 时间，并直接维持了数据库的不变式。

> 注：我们**不能**用 Set AVL Tree 来实现 $D$，因为那样构造将花费 $\Omega(n \log n)$ 时间。

要实现 `report(p, d)`：在 $D$ 中查找 $p$ 以找到 $T_p$，然后将 $d$ 插入 $T_p$。

- 若 $d$ 在 $T_p$ 中**没有**前驱（predecessor）或后继（successor），则将 $(p, d)$ 以键 $\infty$ 插入 $Q$，并将 $(p, d)$ 插入 $C$、映射到它在 $Q$ 中的位置。
- 否则，$d$ 在 $T_p$ 中有前驱或后继。
  - 若 $d$ 既有前驱 $d_1$ 又有后继 $d_2$：在 $C$ 中查找 $(p, d_1, d_2)$ 以在 $Q$ 中定位它，然后将其从 $C$ 与 $Q$ 中同时删除。
  - 否则，$d$ 只有其中一个（记作 $d_0$）：在 $C$ 中查找 $(p, d_0)$ 以在 $Q$ 中定位它，然后将其从 $C$ 与 $Q$ 中同时删除。
  - 无论哪种情况：若 $d$ 有前驱 $d_1$，则将 $(p, d_1, d)$ 以键 $|d - d_1|$ 加入 $Q$，并将 $(p, d_1, d)$ 加入 $C$、指向它在 $Q$ 中的位置；
  - 且若 $d$ 有后继 $d_2$，则将 $(p, d, d_2)$ 以键 $|d_2 - d|$ 加入 $Q$，并将 $(p, d, d_2)$ 加入 $C$、指向它在 $Q$ 中的位置。

此过程执行常数个最坏情况 $O(\log k)$ 时间或均摊期望（amortized expected）$O(1)$ 时间的操作，因此本操作运行于均摊期望 $O(\log k)$ 时间；并通过删除任何「不再相邻」的相邻洞对（consecutive pairs）或「不再孤独」的孤洞（lonely holes），以及加入任何可能新产生的相邻洞对或孤洞，来维持数据库的不变式。

要实现 `patch()`：从 $Q$ 中删除键最小、且在管道 $p$ 上含有一个或两个洞的那个条目，将其从 $C$ 中删除，在 $D$ 中查找 $p$ 以找到 $T_p$，并从 $T_p$ 中删除相关的洞。

此过程执行常数个最坏情况 $O(\log k)$ 时间或均摊期望 $O(1)$ 时间的操作，因此本操作运行于均摊期望 $O(\log k)$ 时间，并直接维持了数据库的不变式。它之所以正确，是因为 $Q$ 精确地实现了所要求的优先级方案（priority scheme）：键更小的相邻洞对具有更高优先级；且仅当 $Q$ 中不存在任何具有有限键的相邻洞对时，才会删除一个孤洞。

> **为什么这么走**：$T_p$（Set AVL Tree）以距离为键维护每条管道上的洞，使得在插入新洞时能在 $O(\log k)$ 内找到其前驱与后继，从而判断它是否与邻居形成新的相邻对、或填平了原本的孤洞。$Q$（二叉最小堆）以「洞对距离」或「$\infty$」为键，把「相邻洞对优先于孤洞」的优先级方案编码成一个可高效取最小值的结构；$C$（哈希表）则提供「已知某一对/孤洞，能 $O(1)$ 定位它在 $Q$ 中的位置」的反向索引，以便删除旧条目。三者的组合保证每个操作只触碰常数个「$O(\log k)$ 或均摊 $O(1)$」的条目。

### Common Mistakes（常见错误）

**针对 Problem 8：**

- 在某一条管道内取最小，而不是在所有管道之间取全局最小。
- 没有把「含多于一个洞的管道」的优先级置于「仅含一个洞的管道」之上。
- 在全部管道上存一棵 AVL 或堆，而这种结构无法在时间界内维护。
- 错误地尝试基于增广（augmentation）的解法。
- 声称「向有序数组插入」只需 $O(\log n)$ 时间（实际是 $O(n)$）。
- 初始化一个大小非多项式有界（non-polynomially bounded）的直接访问数组（direct access array）。
- 使用 **Sequence AVL Trees（序列 AVL 树）** 而不是 **Set AVL Trees（集合 AVL 树）**。

**针对 Problem 9：**

- 假设「最大区间」总是经过根节点。
- 声称有 substring 增广，却未说明如何在 $O(1)$ 时间内维护它。
- 使用两棵 AVL 树（一棵存活跃、一棵存非活跃）——这无助于找到最大区间。
- 维护 substring 增广时，未考虑「包含根节点」的子串（即跨越左右子树、以根为中间拼接而成的区间）。
