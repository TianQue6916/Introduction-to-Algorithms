## 复习范围（Scope）与 SRTBOT 框架

- Quiz 1 & Quiz 2 的内容可考但不作重点（fair game but explicitly not emphasized）。
- 动态规划（dynamic programming）4 讲（L15–L18），Problem Sets PS7–PS8。
- 递归框架 SRTBOT：子问题重叠、构成一个 DAG（subproblem dependencies overlap, forming a DAG）。

### 递归框架（Recursive Framework, SRTBOT）

1. **Subproblem definition（子问题定义）**
   - 用参数 $x \in X$ 描述子问题的含义。
   - 常是输入的某类子集：前缀（prefixes）、后缀（suffixes）、序列的连续子串（contiguous substrings）。
   - 常跨多个输入取子集。
   - 常通过维护辅助状态（auxiliary state，即 expansion/扩展）来「记住」信息。
   - 常按问题空间中整数的状态扩展（pseudopolynomial?）。

2. **Relate recursively（递归关联）**
   - 用递推关联子问题的解：$x(i) = f(x(j), \dots)$，其中 $j < i$。
   - 找出关于子问题解的一个「问题」，回答它即可归约到更小子问题，然后对该问题的所有可能答案做局部暴力（locally brute-force）。

3. **Topological order（拓扑序）**
   - 论证关联是无环的（acyclic，定义出「更小」的子问题），子问题构成 DAG。

4. **Base cases（基例）**
   - 给出所有（可达的）独立子问题的解（关联在这些点失效）。

5. **Original problem（原问题）**
   - 说明如何由子问题的解算出原问题的解。
   - 可能用 parent pointers（父指针）恢复实际解，而不仅是目标函数值。

6. **Time analysis（时间分析）**
   - 总时间 $= \sum_{x \in X} \text{work}(x)$；若对所有 $x \in X$ 有 $\text{work}(x) = O(W)$，则总时间 $= |X| \cdot O(W)$。
   - `work(x)` 度量关联中的**非递归**工作量；把递归调用视为 $O(1)$ 时间。

## Problem 1. Future Investing（未来投资，改编自 S18 PS9）

### 题意

Tiffany Bannen 捡到一张未来穿越者掉落的彩票图（lottery chart），列出未来 $n$ 天每天的中奖号码和正整数现金派彩（cash payouts）。她想利用这信息赚钱，但担心每天买中奖号码会被彩票组织怀疑。因此她决定**低频**买彩票：任意 7 天内至多买 2 次（at most twice in any seven day period）。描述一个 $O(n)$ 时间算法，求她在未来 $n$ 天低频买彩票能获得的最大奖金总额。

### 解答

**核心思想**：需要「记住」最近两次买彩票的时间（等价于对未来购买的约束）。由于「任意 7 天至多 2 次」的约束只与最近 6 天相关，可用一个带常数大小状态维的 DP。

**1. Subproblems（子问题）**

- 令 $L(i)$ 为第 $i$ 天（$i \in \{1,\dots,n\}$）买彩票的现金派彩。
- 需要跟踪最近两次购买（等价于对未来的限制）。
- 定义 $x(i,j)$：在从第 $i$ 天到 $n$ 天的后缀（suffix）上买彩票的最大奖金，假设在第 $i$ 天买、且下一次允许购买是在第 $i+j$ 天。
- 其中 $i \in \{1,\dots,n\}$，$j \in \{1,\dots,6\}$。

**2. Relate（递归关联）**

- Tiffany 会在未来某天再次购买。**Guess（猜测）** 下一次购买的时间。
- **关键观察**：连续 11 天不买绝不是最优的，因为在第 6 天买是合法的且会严格增加奖金。
- 下一次购买可在第 $i+k$ 天，$k \in \{j,\dots,11\}$。
- 若下一次在第 $i+k$ 天（$k \in \{1,\dots,6\}$），则再下一次允许购买是第 $i+7$ 天。
- 若下一次在第 $i+k$ 天（$k \in \{7,\dots,11\}$），则再下一次允许购买是第 $i+k+1$ 天。

```math
x(i,j) = L(i) + \max\big\{ x(i+k,\ \max\{1,\,7-k\})\ \big|\ k \in \{j,\dots,11\},\ i+k \le n \big\}
```

**3. Topo（拓扑序）**：$x(i,j)$ 只依赖严格更大的 $i$，故无环（acyclic）。

**4. Base（基例）**：$x(n,j) = L(n)$，对所有 $j \in \{1,\dots,6\}$（原文 `L(i)` 应为 `L(n)` 之笔误）。

**5. Original（原问题）**：

- 用自顶向下（recursive top-down）或自底向上（iterative bottom-up）求解。
- 猜测第一次购买（在前 7 天之内）。
- 原问题解为 $\max\{x(i,1) \mid i \in \{1,\dots,7\}\}$。
- （可用 parent pointers 重构实际购买的天数。）

**6. Time（时间）**：

- 子问题数：$6n$。
- 每个子问题工作量：$O(1)$（$k$ 只枚举至多 11 个值，常数）。
- 原问题工作量：$O(1)$。
- 总时间 $O(n)$。✅

**伪代码：**

```text
Future-Investing(L[1..n]):
    memo[1..n][1..6] = undefined

    solve(i, j):
        if i == n:
            return L[n]
        if memo[i][j] defined:
            return memo[i][j]
        best = 0
        for k = j to 11:
            if i + k <= n:
                best = max(best, solve(i + k, max(1, 7 - k)))
        memo[i][j] = L[i] + best
        return memo[i][j]

    answer = 0
    for i = 1 to min(7, n):
        answer = max(answer, solve(i, 1))
    return answer
```

**复杂度分析**：子问题数 $= n \times 6 = 6n$；每个子问题做常数（$\le 11$）次递归转移，`work = O(1)$。故总时间 $O(6n) = O(n)$，空间 $O(n)$（记忆化）。✅

## Problem 2. Oh Charlie, Where Art Thou?（改编自 S18 PS9）

### 题意

富豪家庭 Alice、Bob 和他们的幼子 Charlie 环球航行时遭遇暴风雨，Charlie 落水被认定溺亡。二十年后，一个男人找到 Alice 和 Bob 自称是 Charlie。他们既兴奋又怀疑，于是向基因检测公司 46AndThee 订购 DNA 匹配测试。给定 Alice、Bob、Charlie 三人的长度均为 $n$ 的 DNA 序列，检测中心的亲子判定规则如下：

> 若 Charlie 的 DNA 能**划分（partition）成两个等长**的子序列（不要求连续，not necessarily contiguous），其中一个（子序列）是 Alice DNA 的子序列，另一个是 Bob DNA 的子序列，则 Charlie 是他们的儿子。

例：Alice DNA = `AATT`，Bob DNA = `CCGG`。若 Charlie DNA = `CATG`，则匹配为儿子，因为 `CATG` 可划分为不相交子序列 `CG`（Bob 的子序列）和 `AT`（Alice 的子序列）。若 Charlie DNA = `AGTC`，则判定为冒名顶替者（imposter）。

描述一个 $O(n^4)$ 时间算法，判断 Charlie 是否是冒牌货。

### 解答

**核心思想**：要把 $A$、$B$ 的某些字符匹配到 $C$ 的全部字符，且 $A$、$B$ 各贡献恰好 $n/2$ 个字符。这是双序列匹配的二维「扫描」+ 两个计数维的 DP。

**1. Subproblems（子问题）**

- 令 $A,B,C$ 分别为 Alice、Bob、Charlie 的长度 $n$ 的 DNA 序列。
- 目标：把 $A$ 和 $B$ 的某些字符匹配到 $C$ 的全部字符。
- 定义 $x(i,j,k_i,k_j)$：**真**，当且仅当能用「$A$ 后缀 $A[i:]$ 中长度为 $k_i$ 的子序列」与「$B$ 前缀 $B[j:]$ 中长度为 $k_j$ 的字符」匹配到「$C$ 后缀 $C[(n-k_i-k_j):]$（含最后 $k_i+k_j$ 个字符）」的全部字符；否则为**假**。
- 其中 $i,j \in \{0,\dots,n\}$，$k_i,k_j \in \{0,\dots,n/2\}$（假设 $n$ 为偶数）。

**2. Relate（递归关联）**

- 必须匹配字符 $C[n-k_i-k_j]$；若 $A[i] = C[n-k_i-k_j]$ 或 $B[j] = C[n-k_i-k_j]$，则对剩余部分递归。
- 或者，不使用 $A[i]$ 或 $B[j]$（跳过该字符）。

```math
x(i,j,k_i,k_j) = \text{OR}\begin{cases}
x(i+1,\ j,\ k_i+1,\ k_j), & \text{若 } A[i]=C[n-k_i-k_j] \text{ 且 } k_i < n/2 \\
x(i,\ j+1,\ k_i,\ k_j+1), & \text{若 } B[j]=C[n-k_i-k_j] \text{ 且 } k_j < n/2 \\
x(i+1,\ j,\ k_i,\ k_j), & \text{若 } i < n \text{（跳过 } A[i]\text{）} \\
x(i,\ j+1,\ k_i,\ k_j), & \text{若 } j < n \text{（跳过 } B[j]\text{）}
\end{cases}
```

> 原文递推中 `ki > 0` / `kj > 0` 的写法应为「尚未用完配额」的边界判断；为保持匹配数不超过 $n/2$，此处写为 $k_i < n/2$、$k_j < n/2$。`〔原书此处模糊，疑似边界条件笔误，待核〕`

**3. Topo（拓扑序）**：$x(i,j,k_i,k_j)$ 只依赖严格更小的 $i+j$（每次转移 $i$ 或 $j$ 至少加一），故无环（acyclic）。

**4. Base（基例）**：

- $x(n,n,0,0) = \text{true}$（全部匹配完毕）。
- $x(n,j,k_i,k_j) = \text{false}$，若 $k_i > 0$（$A$ 中已无字符可再取，但仍欠 $A$ 侧配额）。
- $x(i,n,k_i,k_j) = \text{false}$，若 $k_j > 0$（$B$ 中已无字符可再取，但仍欠 $B$ 侧配额）。

**5. Original（原问题）**：答案是 $x(0,0,0,0)$。

> 原文写作 `x(n, n, n/2, n/2)`，但按子问题定义（$k_i,k_j$ 表示「已从 $A$/$B$ 用掉的字符数」），初始状态应为 $x(0,0,0,0)$（尚未用任何字符、需匹配 $C$ 全部），终止状态为 $x(n,n,n/2,n/2)$ 为 true。`〔原书此处模糊，疑似初值/终值笔误，待核〕` 下面给出与「$k_i,k_j$ 表示剩余配额」这一等价约定的自洽版本。

**伪代码（采用 $k_i,k_j$ 表示「已用字符数」的约定，$0 \le k_i,k_j \le n/2$）：**

```text
Oh-Charlie(A, B, C, n):   // n 为偶数
    memo = 4D boolean table, all undefined

    solve(i, j, ki, kj):
        if ki == n/2 and kj == n/2:
            return true                 // 已各取满 n/2，匹配完成
        if i >= n and j >= n:
            return false                // 无字符可用但配额未满
        if memo[i][j][ki][kj] defined:
            return memo[i][j][ki][kj]

        t = n - ki - kj                 // 当前要匹配的 C 中的下标
        res = false
        if i < n and ki < n/2 and A[i] == C[t]:
            res = res or solve(i+1, j, ki+1, kj)
        if j < n and kj < n/2 and B[j] == C[t]:
            res = res or solve(i, j+1, ki, kj+1)
        if i < n:
            res = res or solve(i+1, j, ki, kj)   // 跳过 A[i]
        if j < n:
            res = res or solve(i, j+1, ki, kj)   // 跳过 B[j]
        memo[i][j][ki][kj] = res
        return res

    return solve(0, 0, 0, 0)
```

**正确性（Correctness）**：`t = n - k_i - k_j` 是「已从 $C$ 末尾向前匹配掉了 $k_i+k_j$ 个字符后，当前要匹配的字符下标」，它始终指向 $C$ 中尚未匹配的最靠后的字符。因为 $C$ 必须被完全、顺序地匹配，任何合法方案要么用 $A[i]$、要么用 $B[j]$ 匹配当前字符，要么跳过 $A[i]$ 或 $B[j]$（子序列可以不连续）。四个分支穷尽了所有可能，且 $k_i,k_j$ 的配额限制保证 $A$、$B$ 各恰好贡献 $n/2$。归纳可得 `solve(0,0,0,0)` 正确判定。✅

**6. Time（时间）**：

- 子问题数：$i,j \in \{0,\dots,n\}$（$O(n^2)$），$k_i,k_j \in \{0,\dots,n/2\}$（$O(n^2)$），共 $O(n^4)$。
- 每个子问题工作量：$O(1)$。
- 总时间 $O(n^4)$。✅ 空间 $O(n^4)$。

## Problem 3. Sweet Tapas（甜味小食，改编自 S18 Final）

### 题意

Obert Ratkins 在一家高档 tapas（西班牙小食）餐厅用餐，要点很多小盘菜。菜单上有 $n$ 道菜，第 $i$ 道菜的信息是一个三元组 $(v_i, c_i, s_i)$（均为非负整数）：体积（volume）$v_i$、卡路里（calories）$c_i$、甜度（sweetness）$s_i \in \{0,1\}$（$s_i=1$ 表示甜，$s_i=0$ 表示不甜）。Obert 在节食：一餐想摄入**不超过 $k$** 卡路里，但要尽量填饱肚子（最大化体积）。他还想恰好点 $s < n$ 道甜食，且同一道菜不重复购买。描述一个 $O(nks)$ 时间算法，求他在节食约束下的最大食物体积。

### 解答

**核心思想**：这是一个三维 0/1 背包（knapsack），容量维是卡路里 $j$ 与甜食数 $s'$，物品维是菜品。因为每道菜只能选一次，按 $i$ 从后往前递推即可。

**1. Subproblems（子问题）**

- $x(i,j,s')$：从菜品的后缀 $p_i$ 到 $p_{n-1}$ 中购买，卡路里不超过 $j$、恰好点 $s'$ 道甜食时，能获得的最大体积。
- 其中 $i \in \{0,\dots,n\}$，$j \in \{0,\dots,k\}$，$s' \in \{0,\dots,s\}$。

**2. Relate（递归关联）**

- 要么点 $p_i$，要么不点。**Guess！**
- 若点 $p_i$：获得体积 $v_i$，消耗 $c_i$ 卡路里；若 $p_i$ 是甜食，还需少点一道甜食。

```math
x(i,j,s') = \max\begin{cases}
v_i + x(i+1,\ j-c_i,\ s'-s_i), & \text{若 } c_i \le j \text{ 且 } s_i \le s' \\
x(i+1,\ j,\ s'), & \text{始终可选（不点 } p_i\text{）}
\end{cases}
```

**3. Topo（拓扑序）**：$x(i,j,s')$ 只依赖严格更大的 $i$，故无环（acyclic）。

**4. Base（基例）**：

- $x(n,j,0) = 0$，对任意 $j$（没有菜可点了，体积为 0）。
- $x(n,j,s') = -\infty$，对 $s' > 0$ 且任意 $j$（没有菜可点，但仍欠甜食配额，不可行）。

**5. Original（原问题）**：答案是 $x(0,k,s)$。

**6. Time（时间）**：

- 子问题数：$O(n \cdot k \cdot s) = O(nks)$。
- 每个子问题工作量：$O(1)$。
- 总时间 $O(nks)$。✅

**伪代码：**

```text
Sweet-Tapas(v[0..n-1], c[0..n-1], s[0..n-1], k, s):
    NEG = -infinity
    dp[n][0..k][0..s] = 0            // i = n 且 s' = 0 时值为 0
    dp[n][j][s'] = NEG  for s' > 0

    for i = n-1 downto 0:
        for j = 0 to k:
            for sp = 0 to s:
                best = dp[i+1][j][sp]                 // 不点 p_i
                if c[i] <= j and s[i] <= sp:
                    cand = v[i] + dp[i+1][j - c[i]][sp - s[i]]
                    best = max(best, cand)
                dp[i][j][sp] = best

    return dp[0][k][s]
```

**正确性（Correctness）**：对 $i$ 归纳，$x(i,j,s')$ 精确等于后缀 $p_i..p_{n-1}$ 上满足卡路里 $\le j$、恰好 $s'$ 道甜食的最大体积。递推穷尽「点 / 不点 $p_i$」两分支，甜食计数通过 $s_i$ 精确维护，卡路里容量通过 $j-c_i$ 维护，故正确。✅

> 注：这是**伪多项式**时间（依赖 $k$ 与 $s$ 的数值），与题意相符。

## Problem 4. Gokemon Po（改编自 S18 Final）

### 题意

Kash Etchum 想玩一款新的增强现实（augmented reality）游戏 Gokemon Po。目标是在她所在小镇的特定位置捕捉 $n$ 只怪物（monsters）。怪物必须按**特定顺序**获得：在获得怪物 $m_i$ 之前，必须先已获得所有 $m_j$（$j < i$）。要获得 $m_i$，Kash 可以（1）花 $c_i$ 美元在游戏内购买（purchase），或（2）在该怪物的位置免费捕捉（catch）。若她不在该怪物的位置，则需要付费打拼车（ride share）前往。从 $m_i$ 位置到 $m_j$ 位置的最低拼车费用记为正整数 $s(i,j)$。给定所有怪物对的购买价与拼车价表，描述一个 $O(n^2)$ 时间算法，求 Kash 捕捉全部 $n$ 只怪物所需的最小花费，假设她从 $m_1$ 的位置出发。

### 解答

**核心思想**：状态需要记录「当前正在处理的怪物 $i$」与「当前所在位置（最近一次免费捕捉或到达的怪物 $j$）」两个维度，构成 $O(n^2)$ 的 DP。

**1. Subproblems（子问题）**

- $x(i,j)$：从位置 $m_j$ 出发（$j \le i$），捕捉怪物 $m_i$ 到 $m_n$ 的最小花费。

**2. Relate（递归关联）**

- 若已在怪物位置（$j=i$），则免费捕捉它。
- 否则，获得 $m_i$ 要么购买、要么拼车前往后免费捕捉。**Guess！**
- 若购买，花 $c_i$ 美元；否则需从 $m_j$ 拼车到 $m_i$，花 $s(j,i)$。

```math
x(i,j) = \begin{cases}
x(i+1,\ j), & \text{若 } j = i \text{（免费捕捉后，位置不变，处理下一个）} \\
\min\big\{\ c_i + x(i+1,\ j),\ \ s(j,i) + x(i,\ i)\ \big\}, & \text{否则}
\end{cases}
```

**3. Topo（拓扑序）**：$x(i,j)$ 只依赖严格更大的 $i+j$（$i$ 增或 $j$ 增至 $i$），故无环（acyclic）。

**4. Base（基例）**：$x(n+1,j) = 0$，对任意 $j$（没有怪物可捕捉，花费为 0）。

**5. Original（原问题）**：答案是 $x(1,1)$。

**6. Time（时间）**：

- 子问题数：$i \in \{1,\dots,n\}$，$j \in \{1,\dots,i\}$，共 $O(n^2)$。
- 每个子问题工作量：$O(1)$。
- 总时间 $O(n^2)$。✅

**伪代码：**

```text
Gokemon-Po(c[1..n], s[1..n][1..n]):
    memo[1..n+1][1..n] = undefined

    solve(i, j):
        if i == n + 1:
            return 0
        if memo[i][j] defined:
            return memo[i][j]
        if j == i:
            memo[i][j] = solve(i+1, j)            // 免费捕捉
        else:
            buy  = c[i] + solve(i+1, j)           // 购买
            ride = s[j][i] + solve(i, i)          // 拼车前往后免费捕捉
            memo[i][j] = min(buy, ride)
        return memo[i][j]

    return solve(1, 1)
```

**正确性（Correctness）**：捕捉顺序是固定的（必须先 $m_1$，再 $m_2$，…），因此只需在「已处理到 $i$、当前位置为 $j$」的状态上决策。对 $m_i$ 只有三种可能：已在原地（免费）、购买（花 $c_i$、位置不变）、拼车到 $m_i$（花 $s(j,i)$、位置变为 $i$）。递推穷尽了这三者，归纳可得 $x(1,1)$ 是最小总花费。✅

**复杂度分析**：子问题数 $O(n^2)$（$i$ 与 $j\le i$ 的组合），每个子问题 $O(1)$ 转移，故总时间 $O(n^2)$，空间 $O(n^2)$。✅
