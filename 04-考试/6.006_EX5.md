### Algorithm: Sorting（算法：排序）

把问题**归约**为一个你已知算法的已知问题。你应当掌握下表每一种排序算法的实现方式，并能针对给定任务选出正确的算法。

**首次出现的算法核心概念定义：**

- **Divide & Conquer（分治法）**：把原问题递归地拆成若干个规模更小的同类子问题，分别求解后再合并子问题的解以得到原问题的解。判定标准：问题能否「拆成子问题 + 合并子解」。
- **Greedy（贪心算法）**：每一步都做当前看起来最优的局部选择，期望通过局部最优累积得到全局最优。判定标准：是否存在「贪心选择性质 + 最优子结构」，且不需要回溯。

| Algorithm（算法） | Time $O(\cdot)$（时间） | In-place?（原地？） | Stable?（稳定？） | Comments（备注） |
|---|---|---|---|---|
| Insertion Sort（插入排序） | $n^2$ | Y | Y | $O(nk)$，其中 $k$ 为「k-proximate」（k-近邻，即每个元素距其最终位置不超过 $k$ 的数组） |
| Selection Sort（选择排序） | $n^2$ | Y | N | $O(n)$ 次 swaps（交换） |
| Merge Sort（归并排序） | $n \log n$ | N | Y | stable（稳定）、optimal comparison（比较次数最优） |
| AVL Sort（AVL 排序） | $n \log n$ | N | Y | 若同时需要 dynamic（动态）操作则更好 |
| Heap Sort（堆排序） | $n \log n$ | Y | N | low space（低空间开销）、optimal comparison |
| Counting Sort（计数排序） | $n + u$ | N | Y | 当 $u = O(n)$ 时 $O(n)$ |
| Radix Sort（基数排序） | $n + n \log_u n$ | N | Y | 当 $u = O(n^c)$ 时 $O(n)$ |

> 译注：表中「In-place」指算法是否原地排序（额外空间为常数或对数级），「Stable」指相等元素的相对顺序是否保持不变。Y=是，N=否。

### Data Structures（数据结构）

把问题**归约**为使用一个存储「一组元素」的数据结构，该结构高效支持特定的查找（search）与动态（dynamic）操作。你应当掌握每种数据结构如何实现它所支持的操作，并能针对给定任务选出正确的数据结构。

**首次出现的核心概念定义：**

- **Data Structure（数据结构）**：一种组织、存储数据的方式，使得对数据的查询与修改操作能以特定复杂度高效执行。判定标准：它规定了「存什么 + 支持哪些操作 + 各操作代价」。

**Sequence data structures（序列型数据结构）** 支持 **extrinsic operations（外生操作）**：维护、查询、修改一个由外部施加给元素的顺序（即「位置」顺序）。

| Sequence（序列） | Operations $O(\cdot)$（操作） | | | | | | | | |
|---|---|---|---|---|---|---|---|---|---|
| Data Structure（数据结构） | build(X) | get_at(i) | set_at(i,x) | insert_first(x) | delete_first() | insert_last(x) | delete_last() | insert_at(i,x) | delete_at(i) |
| Array（数组） | $n$ | $1$ | $1$ | $n$ | $n$ | $n$ | $n$ | $n$ | $n$ |
| Linked List（链表） | $n$ | $n$ | $n$ | $1$ | $1$ | $n$ | $n$ | $n$ | $n$ |
| Dynamic Array（动态数组） | $n$ | $1$ | $1$ | $n$ | $n$ | $1_{(a)}$ | $1_{(a)}$ | $n$ | $n$ |
| Sequence AVL（序列 AVL 树） | $n$ | $\log n$ | $\log n$ | $\log n$ | $\log n$ | $\log n$ | $\log n$ | $\log n$ | $\log n$ |

> 译注：下标 $(a)$ 表示 amortized（摊还）复杂度。下表同。

**Set data structures（集合型数据结构）** 支持 **intrinsic operations（内生操作）**：基于元素「是什么」（即每个元素唯一的 key 键）来维护、查询、修改一组元素。

| Set（集合） | Operations $O(\cdot)$（操作） | | | | | | | | |
|---|---|---|---|---|---|---|---|---|---|
| Data Structure | build(X) | find(k) | insert(x) | delete(k) | find_min() | find_max() | find_prev(k) | find_next(k) |
| Array（数组） | $n$ | $n$ | $n$ | $n$ | $n$ | $n$ | $n$ | $n$ |
| Sorted Array（有序数组） | $n \log n$ | $\log n$ | $n$ | $n$ | $1$ | $1$ | $\log n$ | $\log n$ |
| Direct Access（直接寻址数组） | $u$ | $1$ | $1$ | $1$ | $u$ | $u$ | $u$ | $u$ |
| Hash Table（哈希表） | $n_{(e)}$ | $1_{(e)}$ | $1_{(a)(e)}$ | $1_{(e)}$ | $n$ | $n$ | $n$ | $n$ |
| Set AVL（集合 AVL 树） | $n \log n$ | $\log n$ | $\log n$ | $\log n$ | $\log n$ | $\log n$ | $\log n$ | $\log n$ |

> 译注：下标 $(e)$ 表示 expected（期望）复杂度，$(a)$ 表示 amortized（摊还）。

**Priority Queues（优先队列）** 只支持一组有限的 Set 操作。

| Priority Queue（优先队列） | Operations $O(\cdot)$（操作） | | | |
|---|---|---|---|---|
| Data Structure | build(X) | insert(x) | delete_max() | find_max() |
| Dynamic Array（动态数组） | $n$ | $1_{(a)}$ | $n$ | $n$ |
| Sorted Dyn. Array（有序动态数组） | $n \log n$ | $n$ | $1_{(a)}$ | $1$ |
| Set AVL（集合 AVL 树） | $n \log n$ | $\log n$ | $\log n$ | $\log n$ |
| Binary Heap（二叉堆） | $n$ | $\log n_{(a)}$ | $\log n_{(a)}$ | $1$ |

> 译注：优先队列的核心是只关心最大/最小元素（这里为 max），故 find_max 与 delete_max 是主操作。

### Problem 1. Restaurant Lineup (S19 Q1)

**题目（Restaurant Lineup —— 餐厅排队，S19 测验第 1 题）**

Popular restaurant Criminal Seafood does not take reservations, but maintains a wait list where customers who have been on the wait list longer are seated earlier.

人气餐厅 Criminal Seafood 不接受预订（does not take reservations），但它维护一张等候名单（wait list），在这张名单上等候更久的顾客会被更早安排入座（seated earlier）。

Sometimes customers decide to eat somewhere else, so the restaurant must remove them from the wait list.

有时顾客决定去别处用餐（eat somewhere else），因此餐厅必须把他们从等候名单中移除（remove）。

Assume each customer has a different name, and no two customers are added to the wait list at the exact same time.

假设每位顾客的名字各不相同（each customer has a different name），且任意两位顾客都不会在完全相同的时刻被加入（added）等候名单。

Design a database to help Criminal Seafood maintain its wait list supporting the following operations, each in O(1) time.

请设计一个数据库（database）来帮助 Criminal Seafood 维护它的等候名单，需要支持以下操作，每个操作都在 $O(1)$ 时间内完成。

State whether each operation running time is worst-case, amortized, and/or expected.

对每个操作，说明其运行时间属于最坏情况（worst-case）、均摊（amortized）还是期望（expected）复杂度（可以同时属于多类）。

- **build()** —— initialize an empty database（初始化一个空数据库）
- **add_name(x)** —— add name $x$ to the back of the wait list（把名字 $x$ 加到等候名单的末尾）
- **remove_name(x)** —— remove name $x$ from the wait list（把名字 $x$ 从等候名单中移除）
- **seat()** —— remove and return the name of the customer from the front of the wait list（移除并返回等候名单最前面的顾客的名字）

---

**解答（Solution）**

Maintain a doubly-linked list containing customers on the wait list in order, maintaining a pointer to the front of the linked list corresponding to the front of the wait list, and a pointer to the back of the linked list corresponding to the back of the wait list.

维护一个双向链表（doubly-linked list），按顺序存放等候名单中的顾客；同时维护一个指向链表头部（front）的指针，它对应等候名单的最前端，以及一个指向链表尾部（back）的指针，它对应等候名单的最末尾。

Also maintain a hash table mapping each customer name to the linked list node containing that customer.

再维护一个哈希表（hash table），把每位顾客的名字映射到包含该顾客的那个链表节点（linked list node）。

> **核心数据结构说明**：双向链表 + 哈希表这一组合的关键作用在于——链表天然表达了「先到先服务」的先后顺序，而哈希表提供了「从名字直接跳到对应节点」的 $O(1)$ 平均查找能力，二者互补，缺一不可。若只有链表，`remove_name` 需要从头线性扫描找名字，退化为 $O(n)$；若只有哈希表，则无法维护先后次序，`seat` 无法 $O(1)$ 找到「最前面」的顾客。

To implement add_name(x), create a new linked list node containing name $x$ and add it to the back of the linked list in worst-case $O(1)$ time. Then add name $x$ to the hash table pointing to the newly created node in amortized expected $O(1)$ time.

实现 `add_name(x)`：新建一个包含名字 $x$ 的链表节点，并把它加到链表末尾，这一步是最坏情况 $O(1)$ 时间（因为尾指针让我们无需遍历）。然后把名字 $x$ 加入哈希表，指向这个新节点，这一步是均摊期望（amortized expected）$O(1)$ 时间（哈希表的插入平均 $O(1)$，最坏可能因重哈希/冲突退化）。

To implement remove_name(x), lookup name $x$ in the hash table and remove the mapped node from the linked list in expected $O(1)$ time.

实现 `remove_name(x)`：先在哈希表中查找（lookup）名字 $x$，然后把映射到的那个节点从链表中移除（双向链表使得「已知节点直接摘除」只需改动前后邻居的指针），这一步是期望（expected）$O(1)$ 时间。

Lastly, to implement seat(), remove the node from the front of the linked list containing name $x$, remove name $x$ from the hash table, and then return $x$, in amortized expected $O(1)$ time.

最后，实现 `seat()`：从链表头部移除包含名字 $x$ 的那个节点，再把名字 $x$ 从哈希表中删除，然后返回 $x$，这一步是均摊期望（amortized expected）$O(1)$ 时间。

**复杂度归类小结：**

| 操作 | 运行时间 | 类别 |
| --- | --- | --- |
| `build()` | $O(1)$ | 最坏情况 worst-case |
| `add_name(x)` | $O(1)$ | 最坏情况 worst-case（链表部分）+ 均摊期望 amortized expected（哈希表部分） |
| `remove_name(x)` | $O(1)$ | 期望 expected |
| `seat()` | $O(1)$ | 均摊期望 amortized expected |

### Problem 2. Rainy Research (S19 Q1)

**题目（Rainy Research —— 降雨研究，S19 测验第 1 题）**

Mether Wan is a scientist who studies global rainfall. Mether often receives data measurements from a large set of deployed sensors.

Mether Wan 是一位研究全球降雨（global rainfall）的科学家。Mether 经常从大量已部署的传感器（deployed sensors）接收数据测量值。

Each collected data measurement is a triple of integers $(r, \ell, t)$, where $r$ is a positive amount of rainfall measured at latitude $\ell$ at time $t$.

每一个采集到的数据测量值是一个整数三元组（triple）$(r, \ell, t)$，其中 $r$ 是在纬度（latitude）$\ell$、时间（time）$t$ 处测得的一个正降雨量。

> 注：原文中的纬度符号在 PDF 文字层被打散为孤立字母，按数学意义应为 $\ell$（latitude 的常用记号，拉丁小写 l 的花体），下同。

The peak rainfall at latitude $\ell$ since time $t$ is the maximum rainfall of any measurement at latitude $\ell$ measured at a time greater than or equal to $t$ (or zero if no such measurement exists).

纬度 $\ell$ 自时间 $t$ 以来的峰值降雨量（peak rainfall）定义为：在纬度 $\ell$ 处、于时间 $\ge t$ 测得的所有测量值中的最大降雨量（如果不存在这样的测量值则为 0）。

Describe a database that can store Mether's sensor data and support the following operations, each in worst-case $O(\log n)$ time where $n$ is the number of measurements in the database at the time of the operation.

请描述一个数据库，能够存储 Mether 的传感器数据，并支持以下操作，每个操作都在最坏情况 $O(\log n)$ 时间内完成，其中 $n$ 是操作发生时数据库中测量值的数量。

- **build()** —— initialize an empty database（初始化一个空数据库）
- **record_data(r, ℓ, t)** —— add a rainfall measurement $r$ at latitude $\ell$ at time $t$（在纬度 $\ell$、时间 $t$ 处加入一条降雨量测量值 $r$）
- **peak_rainfall(ℓ, t)** —— return the peak rainfall at latitude $\ell$ since time $t$（返回纬度 $\ell$ 自时间 $t$ 以来的峰值降雨量）

---

**解答（Solution）**

Maintain a Set AVL tree $L$ storing distinct measurement latitudes, where each latitude $\ell$ maps to a rainfall Set AVL tree $R(\ell)$ containing all measurement triples with latitude $\ell$, keyed by time.

维护一棵 Set AVL 树（一种基于 AVL 平衡二叉搜索树的集合结构）$L$，用来存放互不相同的测量纬度；其中每个纬度 $\ell$ 映射到一棵「降雨量 Set AVL 树」$R(\ell)$，这棵树包含所有纬度为 $\ell$ 的测量三元组，并以时间（time）为键（keyed by time）。

> **核心概念说明**：
> - **AVL 树（AVL tree）**：一种自平衡二叉搜索树（binary search tree，BST），每个节点左右子树高度差至多为 1，通过旋转保证高度始终为 $O(\log n)$，从而查找/插入/删除都是最坏情况 $O(\log n)$。
> - **Set AVL 树（Set AVL tree）**：以集合为语义的 AVL 树实现，维护一组互不相同的键。
> - **增强（augment）**：在每个节点额外存储一个可由子树信息快速计算的派生值（这里是子树内最大降雨量），从而支持原本不直接支持的聚合查询。

We only store nodes associated with measurements, so the height of each Set AVL tree is bounded by $O(\log n)$.

我们只为与测量值相关联的内容建立节点（不建无测量的空节点），因此每棵 Set AVL 树的高度都被限制在 $O(\log n)$ 以内。

For each rainfall tree, augment each node $p$ with the maximum rainfall $p.m$ of any measurement within $p$'s subtree.

对每一棵降雨量树，给每个节点 $p$ 做增强：额外存储 $p.m$ = 以 $p$ 为根的子树（subtree）内任意测量值的最大降雨量。

This augmentation can be maintained in constant time at a node $p$ by taking the maximum of the rainfall at $p$ and the augmented maximums of $p$'s left and right children (if they exist); thus this augmentation can be maintained without effecting the asymptotic running time of standard AVL tree operations.

这个增强值可以在节点 $p$ 处用常数时间维护：只需取「$p$ 自身的降雨量」「$p$ 左孩子（left child）的增强最大值」「$p$ 右孩子（right child）的增强最大值」（若存在）三者中的最大者。因此这个增强可以在不影响标准 AVL 树操作渐近运行时间（asymptotic running time）的前提下被维护（旋转后只需重新计算受影响几个节点的 $m$，仍是常数开销）。

To implement record_data(r, ℓ, t), search $L$ for latitude $\ell$ in worst-case $O(\log n)$ time. If $\ell$ does not exist in $L$, insert a new node corresponding to $\ell$ mapping to a new empty rainfall Set AVL tree, also in $O(\log n)$ time. In either case, insert the measurement triple to $R(\ell)$, for a total running time of worst-case $O(\log n)$.

实现 `record_data(r, ℓ, t)`：在最坏情况 $O(\log n)$ 时间内在外层树 $L$ 中搜索（search）纬度 $\ell$。如果 $\ell$ 不在 $L$ 中，就插入一个对应于 $\ell$ 的新节点，映射到一棵新的空降雨量 Set AVL 树，这同样只需 $O(\log n)$ 时间。无论哪种情况，最后都把测量三元组插入到 $R(\ell)$ 中，因此总运行时间为最坏情况 $O(\log n)$。

> **为什么这里是 $O(\log n)$**：外层 $L$ 的搜索/插入是 AVL 树的 $O(\log n)$；内层 $R(\ell)$ 的插入也是 $O(\log n)$。两次操作串行相加仍是 $O(\log n) + O(\log n) = O(\log n)$（常数因子 2 被大 O 吸收），故总复杂度不变。

To implement peak_rainfall(ℓ, t), search $L$ for latitude $\ell$ in worst-case $O(\log n)$ time. If $\ell$ does not exist, return zero. Otherwise, perform a one-sided range query on $R(\ell)$ to find the peak rainfall at latitude $\ell$ since time $t$.

实现 `peak_rainfall(ℓ, t)`：在最坏情况 $O(\log n)$ 时间内在外层树 $L$ 中搜索纬度 $\ell$。如果 $\ell$ 不存在，返回 0。否则，对 $R(\ell)$ 执行一次单侧区间查询（one-sided range query，即只查询时间 $\ge t$ 的那一侧），找出纬度 $\ell$ 自时间 $t$ 以来的峰值降雨量。

Specifically, let peak(v, t) be the maximum rainfall of any measurement in node $v$'s subtree measured at time $\ge t$ (or zero if $v$ is not a node):

具体地，令 `peak(v, t)` 表示节点 $v$ 的子树内、测量时间 $\ge t$ 的任意测量值的最大降雨量（若 $v$ 不是节点则为 0）。递归定义如下：

```math
peak(v, t) =
\begin{cases}
\max\{ v.item.r,\ v.right.m,\ peak(v.left, t) \}, & \text{if } v.t \ge t \\[4pt]
peak(v.right, t), & \text{if } v.t < t
\end{cases}
```

> **递推式解释（为什么这么分）**：因为树按时间 $t$ 排序（时间小的在左子树、时间大的在右子树），这是一个二分查找结构（binary search tree）的关键性质。
> - 当 $v.t \ge t$（当前节点本身已满足「时间 $\ge t$」）：那么 $v$ 的**右子树**里所有节点时间都 $\ge v.t \ge t$，全部合格，其最大值可直接用增强值 $v.right.m$ 拿到；但**左子树**里的节点时间都 $< v.t$，其中可能仍有时间 $\ge t$ 的合格节点，所以必须递归进入左子树 `peak(v.left, t)`。再与 $v$ 自身降雨量 $v.item.r$ 取最大，三者取 $\max$。
> - 当 $v.t < t$（当前节点自身不合格）：$v$ 自身和它的整个**左子树**（时间更小）都不合格，唯一可能合格的在**右子树**，因此只需递归 `peak(v.right, t)`。

Then peak rainfall is simply peak(v, t) with $v$ being the root of the tree, which can be computed using at most $O(\log n)$ recursive calls. So this operation runs in worst-case $O(\log n)$ time.

于是峰值降雨量就是 `peak(v, t)`，其中 $v$ 取这棵树的根（root）。它可以由至多 $O(\log n)$ 次递归调用计算得出（每次递归要么沿左孩子下降、要么沿右孩子下降，路径长度不超过树高 $O(\log n)$）。所以这个操作运行在最坏情况 $O(\log n)$ 时间。

Note, this problem can also be solved where each latitude AVL tree is keyed by rainfall, augmenting nodes with maximum time in subtree. We leave this as an exercise to the reader.

注意：本题还有一种对称解法——每棵纬度 AVL 树改为以降雨量（rainfall）为键，同时在节点上增强「子树内最大时间」（maximum time in subtree）。我们把它作为练习留给读者。

> **对称解法思路**：与本题解相对称，把「以时间为键 + 增强子树最大降雨量」换成「以降雨量为键 + 增强子树最大时间」，则 `peak_rainfall(ℓ, t)` 等价于在 $R(\ell)$ 上询问「子树内最大时间 $\ge t$ 的最大降雨量」，通过对称的单侧区间查询同样可做到 $O(\log n)$。两种方案的存储与增强都只需常数开销，渐近复杂度一致。
